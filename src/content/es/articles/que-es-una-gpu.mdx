Una **GPU**, del inglés *graphics processing unit* o unidad de procesamiento gráfico, es un procesador diseñado para ejecutar muchos cálculos en paralelo. Reparte el trabajo entre numerosas unidades de cálculo para procesar grandes conjuntos de datos. Nació para dibujar gráficos; también puede acelerar tareas científicas y de [aprendizaje automático](/articulos/que-es-el-aprendizaje-automatico/).

## Un mismo cálculo, muchos datos

Una imagen de 1920 × 1080 tiene más de dos millones de píxeles, los puntos que forman la imagen:

```js
const puntosPorFotograma = 1920 * 1080;

console.log(puntosPorFotograma); // 2073600
console.log(puntosPorFotograma * 60); // 124416000
```

A sesenta imágenes por segundo hay que producir más de 124 millones de valores de píxel por segundo. Esto cuenta píxeles de salida, **no operaciones del procesador**: obtener un color puede requerir muchos cálculos, y algunas partes de una imagen dependen de otras.

Un caso más sencillo sí permite trabajar por separado. Tenemos cuatro intensidades de gris, entre 0 y 255, y queremos aclararlas sumando 50 sin superar el máximo:

```js
const puntos = [10, 200, 90, 255];
const aclarar = (valor) => Math.min(255, valor + 50);

console.log(puntos.map(aclarar).join(" ")); // "60 250 140 255"
```

El primer resultado solo necesita el 10; el segundo, el 200. Podemos asignar cada posición a una unidad distinta sin esperar a las anteriores. Esto es **paralelismo de datos**. El código JavaScript muestra la transformación y se ejecuta normalmente en la CPU: usar `map` no encarga automáticamente el trabajo a la GPU.

## CPU y GPU: prioridades distintas

La [CPU](/articulos/como-funciona-un-procesador/) está preparada para avanzar deprisa en programas variados, incluidos los que toman decisiones y siguen dependencias entre instrucciones. La GPU dedica muchos recursos a mantener numerosos cálculos en marcha y obtener un gran **caudal**, es decir, mucho trabajo terminado por segundo.

Una CPU también puede trabajar en paralelo: tiene varios núcleos y puede aplicar una instrucción a varios datos. Además, un «núcleo» de GPU no equivale a un núcleo de CPU. Comparar sus cantidades como si fueran piezas intercambiables no permite predecir cuál terminará antes.

En una GPU, grupos de operaciones comparten instrucciones. Si unos datos necesitan una rama de un [condicional](/articulos/condicionales/) y otros otra, puede ser necesario ejecutar los caminos por turnos. Parte de las unidades espera y se aprovecha peor el hardware. También cuestan tiempo preparar el trabajo, acceder a memoria y, cuando corresponde, transferir datos entre CPU y GPU. Para cuatro grises, ese coste puede superar cualquier ahorro.

## Cómo dibuja una escena

Una forma habitual de producir gráficos tridimensionales es la **rasterización**:

1. Los objetos se describen mediante triángulos. Se calcula dónde quedan sus vértices desde la cámara.
2. Se determina qué muestras de la pantalla cubren esos triángulos.
3. Pequeños programas llamados **sombreadores**, o *shaders*, calculan valores como el color usando texturas e iluminación.
4. Se resuelven profundidad y mezcla: un objeto puede tapar otro o ser transparente.

Los resultados intermedios, llamados fragmentos, no corresponden siempre uno a uno con los píxeles finales. Varios triángulos pueden cubrir el mismo punto y parte del trabajo se descarta.

La posibilidad de programar esos cálculos permitió usar las GPU para otras tareas. Plataformas como CUDA proporcionan herramientas para expresarlas sin tener que presentarlas como un dibujo.

## Memoria y tareas que caben por partes

Una GPU **dedicada**, como componente separado de la CPU, suele disponer de memoria propia, llamada **VRAM**. Las GPU **integradas** actuales suelen incorporarse al procesador junto a la CPU y compartir la [RAM](/articulos/memoria-ram-y-almacenamiento/) del sistema. Esa integración no determina por sí sola su rendimiento ni su consumo.

La capacidad de memoria importa, pero el conjunto completo de datos no siempre tiene que caber a la vez. Para aclarar ocho imágenes independientes, podemos cargar dos, procesarlas y continuar con las siguientes. El programa debe organizar esos lotes y conservar los resultados fuera de la GPU cuando haga falta.

También existen mecanismos para mover datos bajo demanda y repartir trabajo entre varias GPU, con límites que dependen del equipo y del software. Compartir direcciones de memoria no garantiza que todos los accesos sean igual de rápidos o que no haya transferencias.

## Por qué se usa en inteligencia artificial

Muchas operaciones de una [red neuronal](/articulos/que-es-una-red-neuronal/) multiplican y suman tablas de números, llamadas matrices. Esa estructura ofrece trabajo repetitivo que puede repartirse. Sin embargo, una red también tiene otras operaciones, y el tiempo total depende del tamaño, la memoria, las transferencias y la implementación.

La GPU complementa a la CPU. Su ventaja aparece cuando el programa consigue darle suficiente trabajo paralelo útil; no existe una aceleración fija para cualquier aplicación.

## Lo esencial

- Una GPU reparte muchos cálculos, pero no todas las tareas admiten ese reparto.
- Preparar el trabajo, acceder a memoria y transferir datos también consume tiempo.
- La memoria limita el trabajo disponible a la vez; algunos problemas permiten dividirlo en lotes.
