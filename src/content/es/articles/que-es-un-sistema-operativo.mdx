Un **sistema operativo** es el conjunto de software que gestiona los recursos de un dispositivo y ofrece servicios a los programas. Windows, macOS, Android, iOS y las distribuciones basadas en Linux son ejemplos.

## Qué problema resuelve

Imagina un editor que tuviera que incluir por su cuenta cómo comunicarse con cada disco, pantalla y teclado. Además de editar texto, tendría que resolver cómo compartir esos dispositivos y la memoria con otros programas.

Un programa pequeño puede funcionar sin un sistema operativo, pero entonces él u otras bibliotecas deben asumir el control que necesite. En un ordenador con varias aplicaciones conviene ofrecer servicios comunes y reglas de acceso.

El sistema operativo se coloca en medio y resuelve las dos cosas:

- **Oculta las diferencias del hardware.** Un programa pide "guarda este archivo" y no necesita saber qué tipo de disco hay debajo.
- **Reparte los recursos.** Decide quién usa el procesador, la memoria y los dispositivos, y limita interferencias mediante permisos y protección.

## De qué se encarga

### Procesos

Un programa describe instrucciones; una instancia en ejecución, con sus datos y recursos, es un [**proceso**](/articulos/que-es-un-proceso/). El sistema prepara su memoria y estado, sin necesitar que todos sus archivos se carguen de golpe.

El [procesador](/articulos/como-funciona-un-procesador/) ejecuta las instrucciones. Cuando hay más tareas listas que recursos para ejecutarlas a la vez, el sistema reparte tiempo entre ellas. También puede dejar avanzar una mientras otra espera datos del disco. La parte que elige a quién le toca es el [**planificador**](/articulos/planificador-de-procesos/). Varios núcleos permiten además ejecutar trabajo en paralelo.

### Memoria

Cada proceso necesita memoria para sus datos. En un sistema con protección de memoria, el sistema operativo y el hardware comprueban qué regiones puede leer o modificar. Así se limitan accesos a la memoria privada de otros procesos. Puede haber regiones compartidas con autorización; el aislamiento no elimina todos los fallos ni las dependencias entre programas.

### Archivos

Un dispositivo de almacenamiento conserva datos representados mediante [bits](/articulos/que-es-un-bit/). El [**sistema de archivos**](/articulos/sistema-de-archivos/) los organiza en archivos y carpetas con nombre y registra dónde están. El sistema operativo utiliza esa organización y sus reglas de permisos para atender peticiones. Los detalles físicos del dispositivo quedan en otra capa.

### Dispositivos

Teclado, pantalla, red e impresora necesitan formas concretas de comunicación. Los **controladores**, o *drivers*, traducen operaciones del sistema al mecanismo del dispositivo. Al conectar uno, puede utilizarse un controlador ya instalado, uno genérico compatible o uno específico que haya que añadir.

## El núcleo

La parte central del sistema operativo se llama **núcleo**, o *kernel*. En el modelo habitual de protección, ejecuta operaciones privilegiadas: por ejemplo, configurar qué memoria puede usar una aplicación. Los controladores pueden formar parte del núcleo o ejecutarse por separado con accesos autorizados, según el diseño.

Las aplicaciones normales se ejecutan con permisos limitados. Para pedir un servicio protegido, como abrir un archivo, utilizan una [**llamada al sistema**](/articulos/llamadas-al-sistema/), normalmente a través de una función de biblioteca. El núcleo valida la petición y devuelve un resultado o un error. No todas las funciones de un programa necesitan hacer una llamada al sistema.

### Seguir la lectura de una nota

En un modelo con archivo local y lectura bloqueante, abrir `nota.txt` en un editor puede seguir estos pasos:

1. El editor pide abrir el archivo para leer. El sistema resuelve su nombre y comprueba los permisos; si no existe o el acceso está prohibido, devuelve un error.
2. Si la apertura tiene éxito, entrega una referencia al archivo abierto. El editor la usa para pedir una cantidad de datos.
3. Si los datos necesarios ya están en memoria, el sistema puede atender la lectura desde esa copia. Si hacen falta datos del dispositivo, solicita la operación mediante su controlador.
4. Mientras espera una lectura que lo bloquea, el hilo del editor deja de ejecutar. El planificador puede dar CPU a otra tarea lista.
5. Cuando la lectura se completa, el editor recibe los datos o un error y decide cómo mostrarlos. Estar listo para continuar no garantiza recibir CPU inmediatamente.

El editor conoce archivos y texto; el controlador conoce la comunicación con el dispositivo. La política de permisos y el reparto de CPU permiten que esa operación conviva con otras. No garantizan que el dispositivo nunca falle ni que todas las solicitudes terminen con éxito.

## Lo que ves no es todo

Ventanas, iconos y menús forman la **interfaz gráfica**, que es solo la capa visible. Un sistema operativo puede funcionar sin ella: muchos servidores se manejan únicamente escribiendo órdenes de texto en una [**terminal**](/articulos/terminal-y-shell/).

Varios sistemas pueden compartir núcleo y diferenciarse en todo lo demás. Android, por ejemplo, usa el núcleo de [Linux](/articulos/que-es-linux/).

## Lo esencial

- El sistema operativo hace de intermediario entre el hardware y los programas.
- Gestiona procesos, memoria, archivos y dispositivos.
- El núcleo controla operaciones privilegiadas; las llamadas al sistema permiten solicitar servicios con comprobaciones de acceso.
- La interfaz gráfica es una capa encima, no el sistema operativo en sí.
