Un **puntero** es un valor que permite designar una posición de memoria, por ejemplo la de otro dato. Puede guardarse en una [variable](/articulos/que-es-una-variable/). La dirección también es un dato; no es el contenido al que apunta. Es como una nota que dice "lo que buscas está en el cajón 42". Una **referencia** permite acceder a otro valor, pero sus reglas cambian entre lenguajes: no toda referencia impide por sí sola los accesos inválidos.

## En C

```c
int edad = 30;
int *puntero = &edad;   // guarda la dirección de edad
*puntero = 31;          // cambia el valor de edad a través del puntero
```

`&` obtiene la dirección de una variable; `*` accede a lo que hay en esa dirección.

## Para qué sirven

- **No copiar datos grandes**: se pasa la dirección en lugar del dato.
- **Modificar un dato desde otra función**, como explica [paso por valor y por referencia](/articulos/paso-por-valor-y-por-referencia/).
- **Construir estructuras** como las [listas enlazadas](/articulos/listas-enlazadas/) o los [árboles](/articulos/arboles-binarios-de-busqueda/), en las que cada elemento apunta a otros.
- **Reservar memoria** en el [montículo](/articulos/pila-y-monticulo-de-memoria/).

## Sus peligros

Los punteros sin control son una de las mayores fuentes de errores y vulnerabilidades:

- **Puntero nulo**: no designa un objeto. Desreferenciarlo en C tiene comportamiento indefinido; no se garantiza un cierre limpio del programa.
- **Puntero colgante**: apunta a memoria que ya se liberó.
- **Desbordamiento**: escribir más allá del espacio reservado, y pisar otros datos. Lo aprovechó, por ejemplo, el [gusano Morris](/articulos/el-gusano-morris/).

## Referencias

Lenguajes como JavaScript, Java o Python no tienen punteros a la vista: los objetos se manejan con **referencias**, que el lenguaje controla y que no permiten hacer aritmética con direcciones.

```js
const a = { valor: 1 };
const b = a;

b.valor = 2;

console.log(a.valor); // 2
```

`a` y `b` son referencias al mismo objeto.

En Rust seguro, el compilador comprueba préstamos y tiempos de vida para impedir referencias inválidas. El código `unsafe` y las interfaces con otros lenguajes requieren mantener manualmente las condiciones que esas comprobaciones presuponen.
