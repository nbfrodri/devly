La **tarjeta de red** es el hardware que permite intercambiar datos con otros equipos por una red. Convierte bits en señales y recupera bits de las señales recibidas. También se llama **NIC**, por *network interface controller*, controlador de interfaz de red.

Puede ser una tarjeta conectada a la placa base, un adaptador USB o circuitería integrada en el equipo. «Interfaz de red» es un término más amplio: el sistema operativo también puede presentar interfaces virtuales que no corresponden a una tarjeta física independiente.

## Con cable o por radio

| | Ethernet | Wifi |
| --- | --- | --- |
| Medio habitual | Cable de cobre o fibra óptica | Ondas de radio |
| Familia de estándares | IEEE 802.3 | IEEE 802.11 |
| Restricción del enlace | Necesita el cable y los conectores adecuados | Comparte el canal de radio y depende de cobertura e interferencias |

La velocidad real depende de los dispositivos, el enlace y el tráfico; «con cable» no significa automáticamente «más rápido que cualquier wifi». Un ordenador puede tener varias interfaces y usarlas para redes distintas. [Cómo funciona el wifi](/articulos/como-funciona-el-wifi/) desarrolla el caso por radio.

## Los datos viajan en tramas

La tarjeta no recibe una «página web» como objeto completo. Intercambia **tramas**: unidades que agrupan datos con información de control, como direcciones locales y un código para detectar alteraciones durante la transmisión.

La [dirección MAC](/articulos/que-es-una-direccion-mac/) identifica una interfaz en ese intercambio local. Una dirección puede venir asignada por el fabricante, pero también puede configurarse mediante software. Por ejemplo, algunos dispositivos emplean direcciones wifi privadas que cambian para dificultar el seguimiento. No es una identidad permanente e infalsificable de la persona o del ordenador.

El filtrado puede aceptar tramas para la propia interfaz y también envíos a grupos o a toda la red local. Un código de detección de errores permite descartar muchas tramas dañadas; no demuestra que cualquier alteración imaginable sea imposible ni que una aplicación haya recibido ya su contenido.

## Seguir el envío de un mensaje

Supongamos que escribes «hola» en una aplicación:

1. La aplicación entrega datos al sistema operativo. Sus [protocolos de red](/articulos/que-es-un-protocolo-de-red/) añaden la información necesaria para transportarlos.
2. El **driver**, o [controlador de dispositivo](/articulos/que-es-un-driver/), prepara espacios de memoria con datos e instrucciones para la tarjeta.
3. La tarjeta obtiene los datos pendientes, realiza las operaciones que le correspondan y transmite las tramas mediante señales.
4. En el destino, otra interfaz recibe señales, comprueba las tramas y deja datos disponibles para que el sistema los procese.

El reparto exacto de tareas entre software y tarjeta varía. Un mecanismo habitual es el **acceso directo a memoria**, o DMA: el dispositivo transfiere datos a la [RAM](/articulos/memoria-ram-y-almacenamiento/) sin que la CPU copie cada byte. La CPU sigue preparando y atendiendo la operación; DMA no elimina todo su trabajo.

## Avisar una vez y atender un lote

Una [interrupción](/articulos/interrupciones-y-entrada-salida/) es un aviso al procesador de que hay trabajo que atender. Generar y gestionar un aviso separado para cada paquete puede resultar costoso con mucho tráfico.

Linux utiliza **NAPI** para combinar avisos y procesamiento por lotes. En una configuración habitual, una interrupción inicia la atención de una cola; mientras se procesa, se mantienen desactivados los avisos correspondientes a ese trabajo. No se desactivan todas las interrupciones del ordenador.

Imagina tres paquetes en una cola y un presupuesto de dos por turno. El primer turno procesa dos y solicita otro; el segundo procesa el restante. Cuando termina el trabajo pendiente, se puede volver a habilitar el aviso. Ese presupuesto evita que una cola monopolice indefinidamente la atención. Existen también modos de sondeo sin una interrupción inicial.

## Tener enlace no equivale a tener internet

Una tarjeta puede estar conectada correctamente y aun así fallar la configuración [IP](/articulos/que-es-una-direccion-ip/), la resolución de nombres mediante [DNS](/articulos/que-es-dns/) o el [servidor](/articulos/que-es-un-servidor/) solicitado. Son pasos distintos del recorrido.

Del mismo modo, que la tarjeta haya recibido datos no significa que la aplicación los haya leído o que la persona haya visto el mensaje. La interfaz resuelve el intercambio con la red; el resto de la comunicación necesita otras piezas.

## Lo esencial

- La interfaz física intercambia tramas mediante señales; el sistema organiza el recorrido de los datos.
- Una MAC es una dirección local configurable, no una identidad personal permanente.
- DMA y el procesamiento por lotes reducen trabajo de la CPU, pero no eliminan su intervención.
