Un **sistema de archivos** es la parte del [sistema operativo](/articulos/que-es-un-sistema-operativo/) que organiza el almacenamiento en archivos y carpetas. Decide dónde se guarda cada dato en el disco, cómo se le pone nombre y cómo se vuelve a encontrar.

## Qué problema resuelve

Un disco, visto por dentro, es una secuencia enorme de bloques numerados. No sabe nada de documentos ni de fotos.

Sin un sistema de archivos, cada programa tendría que recordar en qué bloques dejó sus datos y vigilar que no los pisara otro. El sistema de archivos se ocupa de eso y ofrece a todos una idea sencilla: archivos con nombre, organizados en carpetas.

## Archivos y directorios

Un **archivo** es una secuencia de bytes con un nombre. Al sistema de archivos le da igual lo que contenga: texto, una imagen o un programa son, para él, bytes. Quien interpreta el contenido es el programa que lo abre.

La extensión, como `.txt` o `.jpg`, es parte del nombre: una pista para personas y programas. Cambiarla no transforma el contenido.

Un **directorio**, o carpeta, es una lista de nombres, cada uno asociado a un archivo o a otro directorio. Como un directorio puede contener otros, se forma un [árbol](/articulos/arboles-binarios-de-busqueda/), con un directorio **raíz** del que cuelga todo.

## Rutas

La posición de un archivo en ese árbol se indica con una **ruta**.

- Una **ruta absoluta** parte de la raíz: `/home/ana/notas.txt`.
- Una **ruta relativa** parte del directorio en el que se está trabajando: `documentos/notas.txt`.

Dos nombres especiales aparecen en todos los directorios: `.` es el propio directorio y `..` es el que lo contiene.

En Linux y macOS, las partes se separan con `/` y hay un único árbol. Windows usa `\` y tiene un árbol por unidad, como `C:\`.

## Lo que se guarda además del contenido

De cada archivo se conservan **metadatos**: datos sobre el archivo.

- Su tamaño.
- Quién es el propietario.
- Qué permisos tiene.
- Cuándo se creó y se modificó. La forma de guardar esas fechas está detrás del [problema del año 2038](/articulos/el-efecto-2000-y-el-problema-de-2038/).
- En qué bloques del disco está su contenido.

En los sistemas de tipo Unix, esa información vive en una estructura llamada **inodo**. Hay un inodo por archivo, identificado por un número.

Un detalle que sorprende: **el nombre no está en el inodo**. Está en el directorio, que es una tabla de parejas de nombre y número de inodo. El archivo es el inodo; el nombre es solo una etiqueta que apunta a él.

El número de inodo identifica esa estructura dentro de un sistema de archivos, no en todo el ordenador. Dos sistemas de archivos montados pueden utilizar el mismo número para archivos distintos. Tampoco permanece reservado para siempre: después de eliminar un archivo puede reutilizarse. Por eso no sirve como identificador universal permanente.

### Enlaces

De ahí sale una consecuencia: un mismo archivo puede tener varios nombres.

- Un **enlace duro** es otro nombre que apunta al mismo inodo. Los dos son igual de válidos, y el contenido solo se borra cuando desaparece el último.
- Un **enlace simbólico** es un archivo pequeño que contiene la ruta de otro, como un acceso directo. Si el original se borra, el enlace queda apuntando a nada.

El último nombre no es la única referencia relevante. Si un proceso mantiene abierto el archivo mediante un [descriptor](/articulos/descriptores-de-archivo/), puede seguir utilizándolo después de borrar su nombre. El espacio se libera cuando desaparecen los enlaces y las aperturas que lo conservan.

### Enlace duro frente a simbólico

Supón un archivo llamado `informe.txt`. Creas otro nombre, `copia-dura.txt`, para su inodo y un enlace simbólico `acceso.txt` que contiene la ruta `informe.txt`. No has creado dos copias independientes del contenido.

Si renombras `informe.txt` a `final.txt`, `copia-dura.txt` sigue identificando el mismo archivo. El simbólico conserva la ruta anterior y queda roto. Si después creas un archivo distinto llamado `informe.txt`, el simbólico resolverá hacia ese archivo nuevo, mientras el enlace duro seguirá identificando el anterior.

| Criterio | Enlace duro | Enlace simbólico |
| --- | --- | --- |
| Qué conserva | Otro nombre para el mismo inodo | Una ruta hacia el destino |
| Si renombras el otro nombre | Sigue funcionando | Puede quedar roto |
| Si editas a través del enlace | Modifica el mismo archivo | Modifica el destino que resuelva la ruta |
| Cruza sistemas de archivos | No | Puede hacerlo |
| Puede apuntar a algo inexistente | No al crearlo normalmente | Sí |
| Directorios | Normalmente restringido | Permitido en usos habituales |

Utiliza un enlace duro cuando necesitas varios nombres para un mismo archivo dentro del mismo sistema de archivos. Un enlace simbólico permite expresar una referencia por ruta, también a directorios o a otros sistemas montados, asumiendo que el destino puede cambiar o desaparecer.

No los uses como sustituto de una copia de seguridad. Editar el archivo por cualquiera de sus nombres duros cambia el mismo contenido; seguir un simbólico también puede llevarte al dato original. Para conservar un estado anterior necesitas otra estrategia.

### Editar el contenido o sustituir el archivo

También hay que distinguir editar de sustituir. Si un editor modifica el archivo existente, los dos nombres duros ven el contenido cambiado. Si guarda un archivo nuevo y después lo renombra sobre `informe.txt`, ese nombre pasa a identificar el nuevo inodo; el otro nombre duro puede seguir identificando el anterior. «Guardar» no describe por sí solo qué operación hizo el programa.

### Resolver una ruta relativa

Un enlace simbólico relativo guarda una ruta que se interpreta desde el directorio donde está el enlace, no desde cualquier directorio de trabajo del proceso que lo utiliza. Mover el enlace a otra carpeta puede cambiar a qué apunta aunque su texto sea idéntico. Al diagnosticarlo, inspecciona la ruta guardada y la ubicación del enlace, además de comprobar si existe un archivo con un nombre parecido.

## Cómo se reparte el disco

El disco se divide en **bloques** de tamaño fijo, a menudo de 4 kilobytes. Un archivo ocupa un número entero de bloques, aunque le sobre sitio en el último.

Los bloques de un archivo no tienen por qué estar seguidos. Cuando acaban muy dispersos se habla de **fragmentación**. En los discos mecánicos, que tienen que mover un cabezal para leer, eso ralentizaba el acceso. En las unidades de estado sólido apenas influye.

## Permisos

Esta sección es un resumen; el detalle está en [cómo funcionan los usuarios y los permisos](/articulos/permisos-y-usuarios/).

En los sistemas de tipo Unix, cada archivo tiene tres permisos para tres clases de usuarios:

| | Leer (`r`) | Escribir (`w`) | Ejecutar (`x`) |
| --- | --- | --- | --- |
| Propietario | | | |
| Grupo | | | |
| Otros | | | |

Se suelen ver escritos así: `rwxr-xr--`. Los tres primeros caracteres son para el propietario, los tres siguientes para el grupo y los tres últimos para los demás. Un guion indica que falta ese permiso.

En ese ejemplo, el propietario puede leer, escribir y ejecutar; el grupo, leer y ejecutar; los demás, solo leer.

En un directorio, los permisos significan otra cosa: leer es listar su contenido, escribir es crear o borrar archivos dentro, y ejecutar es poder entrar en él.

## Sobrevivir a un apagón

Crear un archivo implica varios cambios en el disco: reservar bloques, escribir el inodo, añadir el nombre al directorio. Si se corta la corriente a mitad, las estructuras quedan a medias y el sistema de archivos se corrompe.

Los sistemas actuales lo evitan con un **[registro por diario](/articulos/sistema-de-archivos-con-registro/)** (*journaling*): antes de aplicar un cambio, anotan en un diario lo que van a hacer. Tras un apagón, basta con leer el diario para completar o descartar lo que quedó pendiente. Es la misma idea de atomicidad que las [transacciones](/articulos/transacciones-y-acid/) de una base de datos.

## Sistemas de archivos habituales

| Sistema | Dónde se usa |
| --- | --- |
| ext4 | Linux |
| NTFS | Windows |
| APFS | macOS e iOS |
| FAT32 y exFAT | Memorias USB y tarjetas, por su compatibilidad |

Cada uno organiza el disco a su manera. Por eso un disco preparado para un sistema operativo puede no leerse en otro, y por eso las memorias USB suelen venir con FAT32 o exFAT, que casi todos entienden.

Preparar un disco para un sistema de archivos se llama **formatear**. Hacerlo accesible en un punto del árbol de directorios se llama **montarlo**.

## Borrar no es destruir

Al borrar un archivo, normalmente solo se quita su nombre del directorio y se marcan sus bloques como libres. El contenido sigue ahí hasta que otro archivo lo sobrescribe. Por eso existen programas de recuperación, y por eso borrar un archivo no basta para destruir datos sensibles.

## Para comparar

Dos sistemas de archivos muy extendidos se comparan en [FAT y NTFS](/articulos/fat-y-ntfs/).

## Lo esencial

- El sistema de archivos convierte los bloques de un disco en archivos y directorios con nombre.
- Un archivo son bytes más metadatos; un directorio asocia nombres con archivos.
- Una ruta indica la posición de un archivo en el árbol, desde la raíz o desde el directorio actual.
- Los permisos controlan quién puede leer, escribir y ejecutar.
- El registro por diario protege la estructura frente a apagones.
