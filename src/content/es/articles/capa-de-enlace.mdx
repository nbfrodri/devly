La **capa de enlace** transporta datos dentro de un enlace o una red local, en unidades llamadas **tramas**. Ethernet y wifi incluyen funciones de esta capa: permiten cubrir un tramo de una comunicación que puede atravesar muchas redes.

Es la capa 2 del modelo OSI y la inferior del [modelo TCP/IP](/articulos/modelos-osi-y-tcp-ip/).

## Qué problema resuelve

La capa de red utiliza [direcciones IP](/articulos/que-es-una-direccion-ip/) para encaminar paquetes entre redes. Ese recorrido está hecho de tramos: del ordenador al router, de ese router al siguiente y así hasta el destino, si existe una ruta utilizable.

La capa de enlace resuelve cada tramo. Su tarea es más modesta y más concreta: entregar un bloque de datos al equipo vecino por el medio que los une, sea un cable, fibra o el aire.

Se parece a un viaje con escalas: enlace resuelve el transporte de un tramo e IP permite avanzar entre redes. La analogía tiene un límite: cada router decide el siguiente salto, sin necesitar conocer de antemano el recorrido completo.

## Tramas

Una trama Ethernet envuelve el paquete de la capa de red y añade, entre otros campos:

- La dirección del destinatario en esta red.
- La dirección del remitente.
- Un código para detectar errores.

Cuando un router reenvía el paquete a otro enlace, crea el envoltorio correspondiente a ese tramo. El paquete IP tampoco es inmutable: cambian campos como TTL, y NAT puede modificar direcciones. Un switch, en cambio, puede reenviar dentro de la misma red de enlace sin hacer un salto IP.

## Direcciones MAC

Ethernet y wifi emplean [**direcciones MAC**](/articulos/que-es-una-direccion-mac/) de 48 [bits](/articulos/que-es-un-bit/) para identificar destinatarios en el ámbito del enlace. Se escriben con seis pares de cifras [hexadecimales](/articulos/sistema-hexadecimal/):

```
3c:22:fb:9a:41:07
```

```js
console.log(2 ** 48); // 281474976710656
```

Algunas MAC provienen de bloques asignados a organizaciones; otras se configuran localmente. El formato de 48 bits no implica que toda dirección permita identificar al fabricante ni que sea permanente.

### Por qué dos tipos de dirección

| | Dirección IP | Dirección MAC |
| --- | --- | --- |
| Capa | Red | Enlace |
| Uso | Dirigir paquetes entre redes | Entregar tramas en el ámbito de enlace |
| Alcance | Depende de la dirección y las rutas | El enlace o la red local |
| Puede cambiar | Sí | Sí |
| Sirve para | Encaminar entre redes | Entregar al vecino |

Al pasar de casa a una cafetería puede cambiar la IP y también la MAC, si el sistema usa direcciones privadas para wifi. Ninguna de ellas demuestra por sí sola la identidad de la persona.

En IP sobre Ethernet se usan ambas porque resuelven decisiones distintas: IP identifica el destino de red y la trama identifica a quién entregarlo en este tramo. No todas las tecnologías de enlace tienen el mismo formato ni utilizan MAC de esta manera.

## De IP a MAC: el protocolo ARP

Tu ordenador quiere enviar un paquete a la IP `192.168.1.20`, que está en su misma red. Para construir la trama necesita la dirección MAC de ese equipo, y no la conoce.

El protocolo [**ARP**](/articulos/que-es-arp/) la averigua en este caso IPv4:

1. Tu ordenador envía una pregunta a todos los equipos de la red: "¿quién tiene la IP 192.168.1.20?".
2. El equipo con esa IP contesta: "yo, y mi MAC es esta".
3. Tu ordenador guarda la respuesta durante un tiempo para no volver a preguntar.

El primer mensaje es una **difusión** (*broadcast*): una trama dirigida a una dirección especial que significa "todos los de esta red".

Si el destino está en otra red, el proceso es el mismo, pero se pregunta por la MAC del router. La trama va al router, y él se encarga del siguiente tramo.

## Conmutadores

En una red cableada, los equipos se conectan a un **conmutador** (*switch*). El conmutador aprende qué dirección MAC hay en cada uno de sus puertos, observando las tramas que le llegan, y lo anota en una tabla.

Cuando conoce una MAC de destino, reenvía por el puerto aprendido. Si la desconoce, normalmente inunda los otros puertos habilitados de la misma red lógica, excluyendo el de entrada. Aprende observando las MAC de origen, no preguntando quién está detrás de cada cable. Los casos completos están en [hub, switch y router](/articulos/hub-switch-y-router/).

Estas son funciones de enlace del conmutador. El enrutamiento usa direcciones IP para conectar redes; un mismo aparato puede realizar ambas tareas y aplicar filtros adicionales.

## Compartir el medio

En un medio compartido, transmisiones simultáneas pueden interferir y provocar una **colisión**: el receptor no puede recuperar correctamente una trama.

El [wifi](/articulos/como-funciona-el-wifi/) tiene este problema, porque todos los dispositivos usan el mismo aire. Lo afronta con una regla: antes de transmitir, cada equipo escucha, y si el canal está ocupado espera un tiempo aleatorio antes de volver a intentarlo.

En un enlace Ethernet punto a punto con dúplex completo, los extremos pueden enviar y recibir simultáneamente y no se utiliza el mecanismo de colisiones del Ethernet compartido antiguo.

## Detectar errores

Las interferencias pueden alterar bits durante la transmisión. Cada trama lleva al final un código calculado a partir de su contenido. El receptor repite el cálculo y, si el resultado no coincide, descarta la trama.

Detectar un error no reconstruye los datos. Ethernet convencional descarta la trama dañada; wifi puede usar confirmaciones y retransmisiones en el propio enlace. Aun con recuperación local, pueden perderse paquetes en otros puntos: [TCP](/articulos/tcp-y-udp/) aporta recuperación de extremo a extremo cuando se utiliza.

## Tamaño máximo

La [**MTU**](/articulos/que-es-una-mtu/) limita el tamaño del paquete transportado por un enlace; en IP sobre Ethernet suele ser 1500 [bytes](/articulos/que-es-un-byte/). No es el tamaño total de la trama, que añade información propia. Un paquete que no cabe puede necesitar un tamaño menor o fragmentación cuando esté permitida; también puede ser descartado.

El [origen del nombre Ethernet](/articulos/por-que-ethernet-se-llama-asi/) recuerda el medio compartido de sus primeras implementaciones.

## Lo esencial

- La capa de enlace entrega datos entre equipos de la misma red local.
- Los datos viajan en tramas, que se renuevan en cada tramo del camino.
- Ethernet y wifi usan direcciones MAC de 48 bits en el ámbito del enlace.
- En IPv4 sobre Ethernet, ARP obtiene la MAC del siguiente destinatario local.
- Un conmutador reenvía tramas según la MAC; un router conecta redes según la IP.
