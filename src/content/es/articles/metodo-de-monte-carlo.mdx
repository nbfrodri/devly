El **método de Monte Carlo** es una técnica para obtener una respuesta aproximada a un problema repitiendo muchas veces un experimento con números aleatorios y analizando los resultados. Sustituye un cálculo difícil por una simulación sencilla repetida miles o millones de veces.

Nació en los años cuarenta en el laboratorio de Los Álamos, de la mano de Stanislaw Ulam, John von Neumann y Nicholas Metropolis. El nombre alude al casino de Montecarlo, por el papel del azar.

## La idea

A Ulam se le ocurrió convaleciente, jugando al solitario. Quiso saber qué probabilidad hay de que una partida salga. Calcularla con matemáticas era muy complicado. Entonces pensó en otra vía: jugar cien partidas y contar cuántas salían.

Esa es toda la idea. Si no sabes calcular algo, simúlalo muchas veces y mira qué ocurre.

Para repeticiones independientes de un mismo experimento, la ley de los grandes números justifica que la frecuencia se aproxime a la probabilidad del **modelo**. Una moneda equilibrada puede dar siete caras de diez; siete mil de diez mil sería mucho más improbable. Más repeticiones reducen la incertidumbre de muestreo, no los errores de un modelo inadecuado.

## Un ejemplo con dados

¿Qué probabilidad hay de sacar un 7 al sumar dos dados?

Con dados equilibrados e independientes, seis de las 36 parejas posibles suman 7: `1 / 6 ≈ 0,1667`. Sirve para contrastar la simulación. Usamos un generador determinista sencillo con semilla fija para reproducir el ejemplo; no es un generador de seguridad ni una recomendación para simulaciones exigentes. El número de tiradas debe ser un entero positivo.

```js
let estado = 42;
function aleatorio() {
	estado = (estado * 16807) % 2147483647;
	return (estado - 1) / 2147483646;
}

function tirarDado() {
	return Math.floor(aleatorio() * 6) + 1;
}

function estimarProbabilidadDeSiete(tiradas) {
	let aciertos = 0;

	for (let i = 0; i < tiradas; i++) {
		if (tirarDado() + tirarDado() === 7) {
			aciertos = aciertos + 1;
		}
	}

	return aciertos / tiradas;
}

const estimacion = estimarProbabilidadDeSiete(1000000);
console.log(Math.abs(estimacion - 1 / 6) < 0.005); // true
```

Con este generador, semilla y orden de llamadas, el resultado se repite y cumple la tolerancia mostrada. Cambiar la semilla cambia la estimación; el método no garantiza esa tolerancia para cualquier ejecución. El programa no enumera combinaciones: genera pares de dados y cuenta aciertos.

## Los cuatro pasos

Toda simulación de Monte Carlo sigue el mismo esquema:

1. **Definir el experimento** y qué resultado se va a medir.
2. **Generar entradas al azar.**
3. **Ejecutar el experimento** con esas entradas y anotar el resultado.
4. **Repetir** muchas veces y resumir: una proporción, una [media](/articulos/media-mediana-y-desviacion/), una distribución.

## Estimar pi con puntos al azar

El ejemplo clásico muestra que el método sirve incluso para problemas sin azar aparente.

Dibuja un cuadrado de lado 1 y, dentro, un cuarto de círculo de radio 1 con centro en una esquina. El área del cuarto de círculo es pi dividido entre 4.

Si generas puntos uniformes e independientes dentro del cuadrado, la proporción que cae dentro del cuarto de círculo aproxima la razón de áreas, `π / 4`. Multiplicándola por 4, estimas pi. El siguiente bloque es independiente y reinicia su propio generador; `puntos` debe ser un entero positivo.

Un punto está dentro si su distancia a la esquina es como mucho 1, es decir, si `x² + y²` no pasa de 1.

```js
let estado = 42;
function aleatorio() {
	estado = (estado * 16807) % 2147483647;
	return (estado - 1) / 2147483646;
}

function estimarPi(puntos) {
	let dentro = 0;

	for (let i = 0; i < puntos; i++) {
		const x = aleatorio();
		const y = aleatorio();

		if (x * x + y * y <= 1) {
			dentro = dentro + 1;
		}
	}

	return (4 * dentro) / puntos;
}

console.log(Math.abs(estimarPi(1000000) - Math.PI) < 0.02); // true
```

## La precisión cuesta

Para una media de repeticiones independientes con varianza finita, el **error estándar** disminuye como `1 / √n`. Es una medida de la variabilidad entre ejecuciones, no una promesa de que el error observado baje en cada paso. Manteniendo el modelo y el método:

| Repeticiones | El error estándar se reduce |
| --- | --- |
| 100 veces más | 10 veces |
| 10 000 veces más | 100 veces |

Reducir diez veces ese error típico exige cien veces más repeticiones. Para los dados, con `p = 1/6` y un millón de tiradas independientes, es `√(p(1-p)/1000000) ≈ 0,000373`. Esto explica el orden de precisión, pero no elimina la posibilidad de una desviación mayor.

Para calcular pi hay métodos mucho más eficientes. Monte Carlo resulta útil cuando el cálculo directo es difícil o costoso; también puede combinarse con soluciones analíticas para parte del problema.

## Dónde se usa

- **Finanzas.** Simular miles de evoluciones posibles del mercado para estimar el riesgo de una inversión.
- **Física e ingeniería.** Seguir el recorrido de partículas, que fue su primer uso, o estimar la fiabilidad de un sistema con muchos componentes.
- **Gestión de proyectos.** Si cada tarea puede durar entre un mínimo y un máximo, simular el proyecto muchas veces da la probabilidad de terminar en una fecha.
- **Gráficos por ordenador.** Calcular la iluminación de una escena siguiendo rayos de luz en direcciones aleatorias.
- **Inteligencia artificial.** Los programas que juegan al go exploran las jugadas simulando partidas al azar.

Lo que tienen en común es que hay demasiadas variables, o demasiado enredadas, para un cálculo directo.

## El azar de un ordenador

Los ejemplos usan números [**pseudoaleatorios**](/articulos/numeros-aleatorios-y-pseudoaleatorios/): una secuencia calculada a partir de un estado inicial. El generador y su calidad estadística forman parte del experimento.

Un generador adecuado puede ser útil para simular y reproducir resultados. Se deben conservar semilla, algoritmo, implementación y orden de llamadas. `Math.random()` no permite fijar su semilla desde JavaScript; por eso aquí hemos usado un generador explícito.

Los generadores sencillos del ejemplo y `Math.random` no ofrecen garantías criptográficas. Para claves y tokens secretos se necesita un generador diseñado para seguridad, como los que expone Web Crypto.

## Errores comunes

- **Elegir un número de repeticiones sin fijar la precisión necesaria.** Cien pueden bastar para un efecto grande y ser insuficientes para un suceso raro; depende de la variabilidad y del objetivo.
- **Confiar en una sola cifra.** Conviene acompañar la estimación de su dispersión, o repetir la simulación para ver cuánto varía.
- **Simular un modelo equivocado.** La estimación conserva incertidumbre estadística y se refiere a las reglas elegidas. Más repeticiones no corrigen reglas que describen mal la realidad.

## Lo esencial

- Monte Carlo estima un resultado repitiendo muchas veces un experimento aleatorio.
- Se apoya en que, con muchas repeticiones, las proporciones se acercan a las probabilidades reales.
- Bajo los supuestos indicados, el error estándar baja con la raíz cuadrada de las repeticiones: ganar precisión es caro.
- Es útil cuando no hay fórmula o el problema tiene demasiadas variables.
