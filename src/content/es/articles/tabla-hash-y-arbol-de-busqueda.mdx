Una **[tabla hash](/articulos/tablas-hash/)** y un **[árbol de búsqueda equilibrado](/articulos/arboles-equilibrados/)** sirven para lo mismo: guardar pares de clave y valor y encontrar un valor por su clave. La tabla hash favorece búsquedas exactas. El árbol mantiene las claves **ordenadas** y facilita rangos y recorridos que una tabla hash tendría que resolver con trabajo adicional.

## Cómo encuentran una clave

- **Tabla hash**: calcula un [hash](/articulos/funciones-hash/) de la clave, que indica directamente dónde está. En promedio, **O(1)**.
- **Árbol**: compara la clave con la del nodo y baja a la izquierda o a la derecha. **O(log n)**.

Estas cotas suponen hashes y comparaciones de coste acotado, distribución adecuada y carga controlada para la tabla hash. Con claves de longitud variable hay que contar también su procesamiento; no son promesas de tiempos concretos.

## El orden cambia las operaciones disponibles

La tabla hash reparte las claves sin orden. El árbol las tiene ordenadas, así que puede:

- **Recorrerlas en orden.**
- **Buscar un rango**: todas las claves entre dos valores.
- **Encontrar la menor, la mayor o la más cercana** a un valor.

```js
const precios = new Map([
	["teclado", 40],
	["monitor", 180],
	["raton", 15],
]);

console.log(precios.get("monitor")); // 180

const ordenadas = [...precios.keys()].toSorted();
console.log(ordenadas.join(" ")); // "monitor raton teclado"
```

El ejemplo muestra la API de `Map`, cuya especificación no impone una tabla hash concreta. Mantiene orden de inserción, no orden alfabético. Para listar las claves alfabéticamente hemos ordenado una copia. Un árbol ordenado con esas mismas parejas entregaría `monitor`, `raton` y `teclado` al recorrerlo en orden. Si solo pides `monitor`, ambas estructuras localizan 180; si pides todas las claves entre `m` y `s`, el árbol localiza el inicio y recorre ese intervalo.

## Comparación

| | Tabla hash | Árbol de búsqueda equilibrado |
| --- | --- | --- |
| Buscar una clave | O(1) en promedio | O(log n) |
| Peor caso | O(n), con muchas colisiones | O(log n), garantizado |
| Orden por valor de clave | No; puede conservar otro orden, como inserción | Sí |
| Rangos, mínimo, máximo | Hay que recorrer todo | Eficiente |
| Requisito de las claves | Que se puedan resumir con un hash | Que se puedan comparar |
| Ejemplos | Diccionarios de CPython, HashMap de Java | TreeMap de Java, mapas ordenados de C++ |

## Cuál usar

- **Tabla hash** cuando solo se busca por clave exacta: cachés, recuentos, conjuntos de elementos vistos. Es la opción por defecto.
- **Árbol** cuando hacen falta el orden o los rangos: clasificaciones, búsquedas por intervalos de fechas, el siguiente evento en el tiempo.

Algunas bases de datos ofrecen ambos tipos de índice: el de [árbol B](/articulos/arboles-b/) admite rangos y orden; el de hash está orientado a igualdades. La disponibilidad y el tipo predeterminado dependen del motor.

## Confusiones frecuentes

- **Confundir orden de inserción y orden de claves.** Recorrer `Map` conserva el primero; no entrega las claves ordenadas por su valor.
- **Aplicar O(1) sin sus supuestos.** Colisiones, crecimiento y procesamiento de claves pueden cambiar el coste de una operación concreta.
- **Buscar un rango como si fuera una igualdad.** Un árbol puede localizar el inicio y recorrer las coincidencias; devolver muchos resultados también tiene coste.

## Lo esencial

- Las dos guardan pares de clave y valor.
- La tabla hash ofrece búsqueda esperada constante bajo sus supuestos, sin mantener por sí sola el orden de las claves.
- El árbol equilibrado busca en tiempo logarítmico y mantiene las claves ordenadas.
- Para rangos, recorridos en orden y mínimos, el árbol; para búsquedas exactas, la tabla hash.
