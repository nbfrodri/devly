Una **prueba A/B** compara dos versiones de algo, una página, un botón, un correo, mostrando cada una a un grupo de usuarios elegido **al azar**, y mide cuál consigue mejor resultado: más compras, más registros, menos abandonos. La versión A suele ser la actual y la B, el cambio que se quiere probar.

## Por qué al azar

Comparar "las ventas de este mes con el botón nuevo" con "las del mes pasado" no sirve: entre medias han cambiado muchas cosas, la temporada, las campañas, la competencia. Es el problema de confundir [correlación con causalidad](/articulos/correlacion-y-causalidad/).

Asignar cada usuario al azar a A o B **en el mismo periodo** equilibra sus características en expectativa, aunque una muestra concreta pueda quedar desequilibrada. Un **experimento controlado** permite estimar el efecto de la asignación si la implementación, la medición y el tratamiento de los datos respetan el diseño; el sorteo no corrige por sí solo abandonos o errores de registro.

## Cómo se hace

1. **Una hipótesis y una métrica**: "un botón más visible aumentará la tasa de compra".
2. **Calcular la muestra necesaria** según el efecto mínimo que interese detectar, la tasa de partida, la potencia y el nivel de error elegidos.
3. **Elegir la unidad y repartir al azar** de forma estable. En este ejemplo es el usuario: sus visitas repetidas no cuentan como usuarios independientes. Si varios usuarios se influyen, puede hacer falta asignar grupos completos.
4. **Fijar la duración y regla de parada** antes de empezar, cubriendo el periodo relevante y la muestra planificada. Un diseño secuencial válido permite otras reglas, pero requiere un análisis compatible.
5. **Analizar** con un [contraste de hipótesis](/articulos/contraste-de-hipotesis-y-valor-p/).

## El análisis

Suponemos dos grupos independientes de 4000 usuarios, una única observación de compra sí/no por usuario y un análisis al final del experimento. Bajo la hipótesis de igual tasa, estimamos una tasa conjunta y calculamos una aproximación normal para la diferencia. `cdfNormal(z)` aproxima la probabilidad de que una normal estándar sea menor o igual a `z`; el polinomio implementa esa aproximación numérica.

```js
function cdfNormal(z) {
	const t = 1 / (1 + 0.3275911 * Math.abs(z / Math.SQRT2));
	const y =
		1 -
		((((1.061405429 * t - 1.453152027) * t + 1.421413741) * t - 0.284496736) * t + 0.254829592) *
			t *
			Math.exp(-((z / Math.SQRT2) ** 2));
	return 0.5 * (1 + (z >= 0 ? y : -y));
}

const a = { usuarios: 4000, compras: 200 };
const b = { usuarios: 4000, compras: 260 };

const tasaA = a.compras / a.usuarios;
const tasaB = b.compras / b.usuarios;
const conjunta = (a.compras + b.compras) / (a.usuarios + b.usuarios);
const error = Math.sqrt(conjunta * (1 - conjunta) * (1 / a.usuarios + 1 / b.usuarios));
const z = (tasaB - tasaA) / error;
const valorP = 2 * (1 - cdfNormal(Math.abs(z)));

console.log(tasaA, tasaB); // 0.05 0.065
console.log(`z = ${z.toFixed(2)}, p = ${valorP.toFixed(4)}`); // "z = 2.88, p = 0.0040"
```

La versión B convierte un 6,5 % frente al 5 % de A: **1,5 puntos porcentuales** de diferencia y un **30 % relativo** respecto al 5 %. La tasa conjunta es `460 / 8000 = 0,0575`; el error bajo la nula es aproximadamente `0,00521`, de donde sale `z ≈ 2,88`. Hay suficientes compras y no compras en ambos grupos para que esta aproximación sea razonable.

Bajo la hipótesis de tasas iguales y los supuestos del análisis, una desviación al menos tan extrema en cualquiera de los dos sentidos tiene una probabilidad aproximada de 0,004. Esto es evidencia contra esa hipótesis; no significa que B tenga una probabilidad del 99,6 % de ser mejor. La decisión debe considerar también la incertidumbre del efecto, las métricas de control y el coste del cambio.

## Los errores que la estropean

- **Aplicar un contraste de muestra fija y parar en una mirada favorable.** Multiplica las oportunidades de rechazar por azar y altera el error previsto. Se respeta el plan o se usa desde el principio un método secuencial válido.
- **Muestras con poca potencia para el efecto buscado.** Pueden no detectar una mejora relevante; un resultado no significativo no demuestra que no exista.
- **Elegir después la métrica que mejor salió.** Buscar entre muchas aumenta el riesgo de una mejora accidental; se distinguen las métricas planificadas de la exploración y se tratan las comparaciones múltiples.
- **Olvidar las métricas de control.** Un cambio puede subir las compras y disparar las devoluciones o las quejas.
- **Ignorar el efecto novedad.** Lo nuevo atrae al principio y luego se normaliza.
- **Ignorar el tamaño del efecto.** Una mejora "significativa" del 0,01 % puede no compensar el coste del cambio.

## Más allá de A y B

Se pueden probar varias versiones a la vez (A/B/n) o combinaciones de cambios, teniendo en cuenta las comparaciones adicionales. Un enfoque **bayesiano** puede calcular una probabilidad posterior de que B supere a A mediante el [teorema de Bayes](/articulos/teorema-de-bayes/). Esa probabilidad depende de la previa, el modelo y los datos; no elimina los problemas del diseño experimental.

## Lo esencial

- Una prueba A/B muestra dos versiones a usuarios repartidos al azar y compara una métrica.
- El reparto al azar ayuda a identificar el efecto de la asignación; medición, pérdidas e interferencias también importan.
- Se planifica la muestra antes y se analiza con un contraste de hipótesis.
- Parar en una mirada favorable o seleccionar entre muchas métricas sin ajustar el análisis puede aumentar los falsos positivos.
