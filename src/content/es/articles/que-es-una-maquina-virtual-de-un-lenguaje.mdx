La **máquina virtual de un lenguaje** es un programa que ejecuta un **código intermedio**, llamado a menudo *bytecode*, en lugar del código máquina de un procesador concreto. El compilador del lenguaje produce ese código intermedio, y la máquina virtual lo ejecuta en cualquier sistema donde esté instalada.

Es la idea que Java resumió en su lema: escribir una vez, ejecutar en cualquier sitio.

## Cómo funciona

```
código fuente ──compilar──▶ bytecode ──máquina virtual──▶ ejecución
```

Un programa en Java se compila a bytecode. El mismo archivo funciona en Windows, Linux o macOS, sobre cualquier [arquitectura](/articulos/arquitecturas-x86-y-arm/), porque en cada uno hay una máquina virtual de Java que sabe ejecutarlo.

## Más rápida de lo que parece

Interpretar el bytecode instrucción a instrucción sería lento. Las máquinas virtuales modernas usan **compilación en el momento**, *just in time*: detectan las partes del programa que más se ejecutan y las traducen a código máquina mientras el programa funciona. A menudo el resultado se acerca a la velocidad de un programa compilado.

V8, el motor de JavaScript de Chrome y de [Node.js](/articulos/que-es-nodejs/), hace algo parecido: interpreta al principio y compila lo que se repite.

## Qué más aporta

- **Gestión automática de memoria**, con recolector de basura, como explica [la pila y el montículo](/articulos/pila-y-monticulo-de-memoria/).
- **Comprobaciones de seguridad**, como impedir accesos fuera de un array.
- **Varios lenguajes**: sobre la máquina virtual de Java funcionan también Kotlin o Scala.

## Con qué no confundirla

Una **máquina virtual de sistema**, como las que explica [contenedores y máquinas virtuales](/articulos/contenedores-y-maquinas-virtuales/), simula un ordenador completo para ejecutar otro sistema operativo. La de un lenguaje solo ejecuta programas de ese lenguaje. Comparten nombre, no propósito.
