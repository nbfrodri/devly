**JavaScript** es el lenguaje que ejecutan los navegadores y [Node.js](/articulos/que-es-nodejs/). **[TypeScript](/articulos/que-es-typescript/)** es JavaScript con **tipos estáticos** añadidos: se escribe casi igual, con anotaciones que indican qué tipo tiene cada valor, y una herramienta comprueba los errores antes de ejecutar. Después, TypeScript se convierte en JavaScript normal.

TypeScript conserva la mayor parte de la sintaxis de JavaScript y permite una adopción gradual. Eso no significa que cualquier programa JavaScript pase su verificador: puede señalar errores o requerir anotaciones según la configuración.

## La diferencia en un ejemplo

En JavaScript, este error pasa desapercibido hasta que alguien ve un resultado extraño:

```js
function sumar(a, b) {
	return a + b;
}

console.log(sumar(2, 3)); // 5
console.log(sumar(2, "3")); // "23"
```

Con un texto, `+` concatena en lugar de sumar. No hay ningún error.

En TypeScript:

```ts
function sumar(a: number, b: number): number {
	return a + b;
}

sumar(2, "3");
// Error: el argumento de tipo 'string' no se puede asignar a 'number'.
```

El error aparece en el editor, antes de ejecutar nada.

## Comparación

| | JavaScript | TypeScript |
| --- | --- | --- |
| Tipado | [Dinámico](/articulos/tipado-estatico-y-dinamico/) | Estático, opcional en parte |
| Errores de tipo | El lenguaje comprueba al ejecutar; otras herramientas pueden analizar antes | Detecta ciertas incompatibilidades antes de ejecutar si se pasa el verificador |
| Se ejecuta directamente | Sí | No: se [transpila](/articulos/compilar-y-transpilar/) a JavaScript |
| Paso de construcción | No hace falta | Sí, o un entorno que lo admita |
| Ayuda del editor | Puede inferir tipos y usar anotaciones JSDoc | Usa tipos inferidos y declarados para navegación y comprobaciones |
| Curva de aprendizaje | Menor | Algo mayor |
| Mantenimiento | Depende de contratos, pruebas y herramientas | Añade comprobaciones estáticas a esas prácticas |

## Lo que TypeScript no cambia

- **El comportamiento al ejecutar.** Los tipos se borran. El programa hace exactamente lo mismo que el JavaScript equivalente.
- **Los datos que llegan de fuera.** Si una API devuelve algo distinto de lo declarado, TypeScript no lo detecta. En las fronteras del programa hay que validar.
- **Los errores de lógica.** Un programa con tipos correctos puede hacer lo que no debe.

## Cuándo usar cada uno

- **JavaScript**: scripts pequeños, prototipos rápidos, páginas con poco código.
- **TypeScript**: cuando compensa expresar contratos y detectar usos incompatibles antes de ejecutar. Hay que mantener tipos, configuración y herramientas; no garantiza cambios sin errores.

No es una elección para siempre: un proyecto de JavaScript puede adoptar TypeScript poco a poco, archivo a archivo.

## Confusiones frecuentes

- **Confundir quitar tipos con comprobarlos.** Algunas herramientas solo transforman la sintaxis. Ejecuta el verificador, por ejemplo `tsc --noEmit`, como paso propio.
- **Creer que `any` prueba compatibilidad.** Desactiva parte de las comprobaciones y permite que pase código incorrecto.
- **Confiar en una anotación para datos de una API.** La respuesta debe validarse al ejecutar; sus bytes no obedecen a una declaración de tipos.

## Lo esencial

- TypeScript es JavaScript con tipos estáticos.
- El verificador detecta ciertas incompatibilidades antes de ejecutar, con el alcance de sus tipos y configuración.
- TypeScript se convierte en JavaScript, y los tipos desaparecen al ejecutar.
- Compensa en proyectos medianos y grandes; para scripts pequeños, JavaScript basta.
