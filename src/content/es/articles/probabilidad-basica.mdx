La **probabilidad** es un número entre 0 y 1 que un modelo asigna a un suceso para expresar su incertidumbre. En los dados y monedas de este artículo, con un número finito de resultados de probabilidad positiva, 0 significa imposible y 1, seguro. Unas pocas reglas permiten combinar sucesos y comprobar intuiciones.

Es la base de la estadística, del [aprendizaje automático](/articulos/que-es-el-aprendizaje-automatico/) y de cualquier decisión con incertidumbre.

## Los términos

| Término | Significado | Con un dado |
| --- | --- | --- |
| Experimento | Una acción de resultado incierto | Lanzarlo |
| Espacio muestral | Todos los resultados posibles | 1, 2, 3, 4, 5, 6 |
| Suceso | Un conjunto de resultados | "Sale par": 2, 4, 6 |

Cuando todos los resultados son igual de probables, la probabilidad de un suceso es una división:

**casos favorables / casos posibles**

Que salga par: 3 de 6, es decir, 0,5.

Suponemos dados equilibrados y lanzamientos independientes. Con dos dados hay 36 parejas ordenadas igual de probables: un 1 en el primero y un 2 en el segundo es distinto de obtenerlos al revés. Enumerarlas evita confundir parejas con sumas:

```js
const resultados = [];

for (let a = 1; a <= 6; a++) {
	for (let b = 1; b <= 6; b++) {
		resultados.push([a, b]);
	}
}

const probabilidad = (cumple) =>
	resultados.filter(cumple).length / resultados.length;

console.log(resultados.length); // 36
console.log(probabilidad(([a, b]) => a + b === 7).toFixed(3)); // "0.167"
console.log(probabilidad(([a, b]) => a + b === 12).toFixed(3)); // "0.028"
```

Sumar 7 es seis veces más probable que sumar 12: hay seis formas de conseguirlo y una sola de sacar dos seises.

## Qué significa

Hay dos lecturas, y las dos se usan.

- **Como frecuencia.** En repeticiones independientes con la misma probabilidad, la proporción tiende a acercarse a ella al aumentar la muestra. No tiene por qué mejorar en cada repetición. Es lo que aprovecha el [método de Monte Carlo](/articulos/metodo-de-monte-carlo/).
- **Como grado de confianza.** "Un 70 % de probabilidad de lluvia mañana" no habla de repetir mañana muchas veces. Expresa cuánto se cree en algo con la información disponible.

## Reglas básicas

### El contrario

La probabilidad de que algo **no** ocurra es 1 menos la de que ocurra. No sacar un 6: 1 − 1/6 = 5/6.

Parece poca cosa, y es de lo más útil: a menudo es más fácil calcular lo contrario de lo que se busca.

### Uno u otro

Si dos sucesos no pueden darse a la vez, son **excluyentes**, y sus probabilidades se suman. Sacar un 1 o un 2: 1/6 + 1/6.

Si pueden darse a la vez, hay que restar lo que se ha contado dos veces. Sacar par o mayor que 3: los pares son 2, 4, 6; los mayores que 3 son 4, 5, 6. El 4 y el 6 están en los dos grupos. El resultado es 3/6 + 3/6 − 2/6 = 4/6.

### Uno y otro

Dos sucesos son **independientes** si que ocurra uno no cambia la probabilidad del otro. Modelamos así los lanzamientos de una moneda cuando el procedimiento no hace depender uno del anterior.

Para sucesos independientes, la probabilidad de que ocurran ambos es el **producto**. Dos seises seguidos: 1/6 × 1/6 = 1/36.

De aquí sale una aplicación: si diez componentes son necesarios y sus estados de disponibilidad son independientes, con probabilidad 0,99 para cada uno el conjunto tiene probabilidad `0,99¹⁰ ≈ 0,904`. No se puede aplicar ese producto si comparten una causa de fallo, como la misma fuente de alimentación.

## La falacia del jugador

Tras cinco caras seguidas, ¿es más probable que salga cruz?

En el modelo de una moneda equilibrada con lanzamientos independientes, no: la probabilidad sigue siendo 0,5. Si no se sabe si la moneda está equilibrada, los resultados sí pueden aportar información sobre ella.

Creer que la cruz "ya toca" es un error tan extendido que tiene nombre. La frecuencia se acerca a la mitad a la larga, no porque la moneda compense, sino porque las rachas se diluyen entre muchos lanzamientos.

## Probabilidad condicionada

Es la probabilidad de un suceso **sabiendo que ha ocurrido otro**. Se escribe P(A | B), "probabilidad de A dado B".

En un espacio finito, condicionamos restringiendo la atención a los resultados compatibles con B y reajustando sus probabilidades. La fórmula `P(A | B) = P(A y B) / P(B)` exige `P(B) > 0`.

```js
const resultados = [];

for (let a = 1; a <= 6; a++) {
	for (let b = 1; b <= 6; b++) {
		resultados.push([a, b]);
	}
}

const sumaAlta = ([a, b]) => a + b >= 10;
const conUnSeis = resultados.filter(([a]) => a === 6);

console.log((resultados.filter(sumaAlta).length / resultados.length).toFixed(3)); // "0.167"
console.log(conUnSeis.filter(sumaAlta).length / conUnSeis.length); // 0.5
```

La probabilidad de sumar 10 o más es de un 17 %. Si ya se sabe que el primer dado es un 6, sube al 50 %: solo quedan seis casos posibles, y tres valen.

Dicho de otro modo: dos sucesos son independientes cuando saber uno **no** cambia la probabilidad del otro.

## El error de dar la vuelta

P(A | B) y P(B | A) son cosas distintas, y confundirlas es uno de los errores más graves y frecuentes.

En un ejemplo hipotético, una prueba detecta el 99 % de los casos de una enfermedad y da un falso positivo en el 5 % de las personas sin ella. La enfermedad afecta al 1 % de la población muestreada. Si una persona elegida al azar de esa población da positivo, ¿qué probabilidad de enfermedad asigna este modelo?

La respuesta intuitiva ronda el 95 %. Se cuenta con 10 000 personas:

```js
const enfermos = 100;
const sanos = 9900;

const positivosVerdaderos = (enfermos * 99) / 100;
const positivosFalsos = (sanos * 5) / 100;

const probabilidad =
	positivosVerdaderos / (positivosVerdaderos + positivosFalsos);

console.log(positivosVerdaderos); // 99
console.log(positivosFalsos); // 495
console.log(probabilidad.toFixed(2)); // "0.17"
```

Un 17 %. De cada seis positivos, cinco son de personas sanas.

La razón es que hay muchísimos más sanos que enfermos, y el 5 % de un grupo enorme supera al 99 % de uno pequeño. Ignorar cuánta gente hay en cada grupo se llama **olvido de la tasa base**.

La relación entre las dos probabilidades condicionadas la da el **[teorema de Bayes](/articulos/teorema-de-bayes/)**. Es el mismo problema que hay detrás de la [precisión de un clasificador](/articulos/como-se-evalua-un-modelo-de-clasificacion/): al buscar algo infrecuente, una tasa de falsos positivos pequeña puede bastar para que dominen las falsas alarmas.

## La intuición engaña

¿Cuántas personas hacen falta en una sala para que sea más probable que improbable que al menos dos cumplan años el mismo día? El modelo supone 365 fechas equiprobables e independientes y omite años bisiestos. La función recibe un número entero no negativo de personas:

```js
function coincidencia(personas) {
	if (personas > 365) return 1;
	let todasDistintas = 1;

	for (let i = 0; i < personas; i++) {
		todasDistintas = todasDistintas * ((365 - i) / 365);
	}

	return 1 - todasDistintas;
}

console.log(coincidencia(23).toFixed(2)); // "0.51"
console.log(coincidencia(50).toFixed(2)); // "0.97"
```

Bastan 23. Se calcula con la regla del contrario: la probabilidad de que todas las fechas sean distintas, y se resta de 1.

Sorprende porque uno piensa en coincidir con su propia fecha. Pero vale cualquier pareja, y con 23 personas hay 253 parejas.

No es una curiosidad: el mismo cálculo dice cuándo esperar una colisión en una [función hash](/articulos/funciones-hash/) o en identificadores generados al azar. Llegan mucho antes de lo que sugiere el número de valores posibles.

## En informática

- **Estructuras de datos.** Las [tablas hash](/articulos/tablas-hash/) gestionan colisiones; una distribución adecuada y una carga controlada ayudan a mantener pequeños los grupos que hay que recorrer.
- **Fiabilidad.** Cuántas copias hacen falta para que perder todas a la vez sea casi imposible.
- **Aprendizaje automático.** Algunos modelos estiman probabilidades; hay que comprobar qué significan y cómo se ajustan a los resultados observados.
- **Pruebas A/B.** Cuantificar la incertidumbre de una diferencia bajo el modelo del experimento.
- **Seguridad.** Cuánto se tarda en adivinar una clave.

## Lo esencial

- La probabilidad va de 0 a 1; con resultados igual de probables, son casos favorables entre posibles.
- La de que algo no ocurra es 1 menos la de que ocurra.
- Para sucesos excluyentes se suma; para independientes que deben darse ambos, se multiplica.
- La probabilidad condicionada cambia con lo que se sabe, y no se puede dar la vuelta sin más.
- Un resultado anterior no cambia la probabilidad del siguiente cuando las repeticiones son independientes; no todo proceso aleatorio cumple esa condición.
