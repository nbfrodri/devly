Una **clave foránea**, o ajena, relaciona una o varias columnas con una clave de referencia, normalmente una [clave primaria](/articulos/que-es-una-clave-primaria/). Puede apuntar a otra tabla o a la misma. Con la restricción activa, los valores no nulos deben corresponder a una fila referenciada; los detalles de claves compuestas y nulos dependen del motor.

## Un ejemplo

En una base SQLite vacía:

```sql
PRAGMA foreign_keys = ON;
CREATE TABLE clientes (id INTEGER PRIMARY KEY, nombre TEXT NOT NULL);
CREATE TABLE pedidos (
	id INTEGER PRIMARY KEY,
	cliente_id INTEGER NOT NULL REFERENCES clientes (id),
	fecha TEXT NOT NULL
);
INSERT INTO clientes VALUES (1, 'Ana');
INSERT INTO pedidos VALUES (10, 1, '2026-10-15');
SELECT id, cliente_id FROM pedidos;
-- 10 | 1
```

La consulta devuelve el pedido 10 asociado al cliente 1. `cliente_id` es una clave foránea: cada pedido guarda el `id` de su cliente.

## Qué garantiza

La **integridad referencial**:

- No se puede crear un pedido con un `cliente_id` que no existe.
- No se puede borrar un cliente que tiene pedidos, salvo que se indique qué hacer con ellos.

Ese "qué hacer" se configura:

| Opción | Al borrar el cliente… |
| --- | --- |
| Impedir (por defecto) | Se rechaza el borrado |
| `ON DELETE CASCADE` | Se borran también sus pedidos |
| `ON DELETE SET NULL` | Los pedidos quedan sin cliente si la columna admite NULL |

El ejemplo exige cliente con `NOT NULL`, así que `SET NULL` no serviría sin cambiar esa regla. La comprobación de claves foráneas se activa por conexión en SQLite. La clave referenciada también puede ser una combinación de columnas con unicidad que el motor admita.

## Para qué sirve

- **Relacionar** tablas, como explica el [modelo entidad-relación](/articulos/modelo-entidad-relacion/).
- **Combinar** datos con [JOIN](/articulos/tipos-de-join/).
- **Evitar datos huérfanos**, una de las fuentes de mala [calidad de datos](/articulos/calidad-de-datos/).

## Con qué no confundirla

- **Clave primaria**: identifica cada fila de su tabla y no se repite. Una clave foránea sí puede repetirse: un cliente tiene muchos pedidos.
- Una clave foránea no crea un índice automáticamente en todas las bases de datos. Si se usa mucho para buscar, conviene crearlo.
