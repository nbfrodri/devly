Una **interfaz** describe **qué forma** debe tener un objeto: qué propiedades y qué métodos ofrece, con qué tipos. No dice **cómo** se implementan. Es un contrato: cualquier cosa que cumpla la interfaz puede usarse donde se espera.

## Un ejemplo

En [TypeScript](/articulos/que-es-typescript/):

```ts
interface Almacen {
	guardar(clave: string, valor: string): void;
	leer(clave: string): string | undefined;
}

class AlmacenEnMemoria implements Almacen {
	#datos = new Map<string, string>();
	guardar(clave: string, valor: string) { this.#datos.set(clave, valor); }
	leer(clave: string) { return this.#datos.get(clave); }
}
```

Quien usa un `Almacen` no necesita saber si los datos van a memoria, a un archivo o a una base de datos. Se puede cambiar la implementación sin tocar el código que la usa.

## Para qué sirve

- **Desacoplar**: el código depende de lo que algo hace, no de cómo. Es la base de uno de los [principios SOLID](/articulos/principios-solid/), el de inversión de dependencias.
- **Sustituir en pruebas**: en una [prueba](/articulos/pruebas-de-software/), un almacén real se cambia por uno falso que cumple la misma interfaz.
- **Documentar**: deja claro qué ofrece un componente.

## Con qué no confundirla

- **[Clase](/articulos/que-es-una-clase/)**: una clase da el código; una interfaz, solo la forma.
- **Clase abstracta**: puede incluir parte del código y obliga a heredar de ella. Una interfaz no impone herencia.
- **Interfaz de usuario**: lo que ve una persona en pantalla. Mismo nombre, otro concepto.
- **[API](/articulos/que-es-una-api/)**: también es una interfaz, en sentido amplio, entre programas.
