Un **gestor de paquetes** es una herramienta que instala, actualiza y desinstala programas de forma automática. Descarga cada programa de un **repositorio**, un almacén de confianza, junto con todo lo que necesita para funcionar, y lleva la cuenta de lo instalado.

Existen para los sistemas operativos, como `apt` o `pacman` en [Linux](/articulos/distribuciones-de-linux/), y para los lenguajes de programación, como `npm` para JavaScript o `pip` para Python.

## Qué problema resuelve

Instalar un programa a mano significa buscarlo en internet, descargarlo de una web que hay que creer legítima, ejecutar un instalador y repetir el proceso con cada biblioteca que necesite. Y después, acordarse de actualizarlo todo.

El gestor lo convierte en una orden:

```bash
sudo apt install git
```

## Qué es un paquete

Un archivo que contiene el programa y unos **metadatos**: nombre, versión, descripción y, sobre todo, la lista de **dependencias**, los otros paquetes que necesita.

## Las dependencias

Es el trabajo central del gestor. Si A necesita B y C, y C necesita D, hay que instalar D, C y B antes que A. Es una [ordenación topológica](/articulos/ordenacion-topologica/) del grafo de dependencias.

Además, hay que respetar las **versiones**: si A necesita B en la versión 2 o superior, y otro programa necesita B por debajo de la 2, hay un conflicto. Encontrar un conjunto de versiones compatible para todo puede ser un problema difícil.

### Comparar versiones

Las versiones se suelen escribir con el esquema de **versionado semántico**: mayor, menor y corrección, como `2.14.3`. Compararlas no es comparar texto:

```js
function compararVersiones(a, b) {
	const partesA = a.split(".").map(Number);
	const partesB = b.split(".").map(Number);

	for (let i = 0; i < 3; i++) {
		if (partesA[i] !== partesB[i]) return partesA[i] - partesB[i];
	}

	return 0;
}

console.log("1.10.0" < "1.9.0"); // true
console.log(compararVersiones("1.10.0", "1.9.0") > 0); // true
```

Como texto, "1.10.0" va antes que "1.9.0", porque el carácter "1" es menor que "9". Como versión, la 1.10 es posterior. Un error clásico.

En el versionado semántico, cambiar el número **mayor** indica cambios incompatibles; el **menor**, funciones nuevas compatibles; el último, solo correcciones.

## Seguridad

- **Firmas.** Los paquetes de las distribuciones están firmados, y el gestor comprueba la firma antes de instalar. Un paquete alterado por el camino se rechaza.
- **Revisión.** En las distribuciones, los paquetes los preparan y revisan sus mantenedores.

Los repositorios de los lenguajes son distintos: cualquiera puede publicar. Eso los hace enormes y útiles, y también un objetivo: paquetes maliciosos con nombres parecidos a los legítimos, o paquetes legítimos cuyo autor pierde el control de su cuenta. Un proyecto pequeño puede arrastrar cientos de dependencias indirectas, como recuerda el artículo sobre [Node.js](/articulos/que-es-nodejs/). Cómo protegerse lo explica [cadena de suministro de software](/articulos/cadena-de-suministro-de-software/).

## El archivo de bloqueo

En un proyecto, el gestor de paquetes del lenguaje genera un **archivo de bloqueo** que fija la versión exacta de cada dependencia, también de las indirectas. Así todos los que trabajan en el proyecto, y el [pipeline de integración continua](/articulos/integracion-y-despliegue-continuos/), instalan exactamente lo mismo. Ese archivo se guarda en el repositorio.

## Lo esencial

- Un gestor de paquetes instala, actualiza y desinstala programas desde un repositorio de confianza.
- Resuelve las dependencias, instalándolas en el orden correcto y con versiones compatibles.
- Las versiones se comparan por números, no como texto.
- Los paquetes firmados protegen de alteraciones; los repositorios abiertos exigen más cuidado.
- El archivo de bloqueo garantiza que todos instalan las mismas versiones.
