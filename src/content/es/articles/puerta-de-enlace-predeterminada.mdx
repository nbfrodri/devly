La **puerta de enlace predeterminada** (*default gateway*) es el router que se utiliza como siguiente salto de la **ruta por defecto**. Recibe los paquetes para los que no coincide una ruta más específica. En la configuración de un equipo suele indicarse mediante la IP local de ese router.

En una casa, es el router que da acceso a internet, con direcciones típicas como `192.168.1.1`.

## Cómo decide un equipo

En el caso sencillo de una interfaz, una ruta a su [subred](/articulos/subredes-y-cidr/) y otra por defecto:

- Si el destino está **en la misma red**, lo envía directamente al otro equipo.
- Si **no**, lo envía a la puerta de enlace, que se encargará de llevarlo más allá.

```js
const ip = (t) => t.split(".").reduce((n, o) => n * 256 + Number(o), 0);
const mismaRed = (a, b, bits) => {
	const tamano = 2 ** (32 - bits);
	return Math.floor(ip(a) / tamano) === Math.floor(ip(b) / tamano);
};

const yo = "192.168.1.20";
const destino = (d) => (mismaRed(yo, d, 24) ? "directo" : "puerta de enlace");

console.log(destino("192.168.1.35")); // "directo"
console.log(destino("203.0.113.10")); // "puerta de enlace"
```

El ejemplo supone direcciones válidas y un prefijo entero entre 0 y 32. Solo representa esas dos rutas; no sustituye la selección de una tabla con más entradas.

## En la tabla de rutas

La **ruta por defecto** es una entrada de la tabla de [enrutamiento](/articulos/enrutamiento/); la puerta de enlace es el siguiente router indicado por esa entrada. Se utiliza cuando no coincide otra ruta más específica. En Linux aparece al consultar la tabla:

```bash
ip route
# default via 192.168.1.1 dev wlan0
# 192.168.1.0/24 dev wlan0 proto kernel scope link src 192.168.1.20
```

La salida comentada es un ejemplo: tu interfaz y direcciones pueden ser distintas. La primera línea usa el router `192.168.1.1` como siguiente salto predeterminado; la segunda indica que `192.168.1.0/24` se alcanza directamente.

Ahora imagina que se añade la ruta `10.0.0.0/8` por otro router local, `192.168.1.254`. Para llegar a `10.20.0.5` gana `/8` frente a `/0`: se utiliza `.254`, aunque el destino no esté en la subred local. Esa es la razón por la que «todo lo que no es local va al router predeterminado» no sirve para cualquier configuración.

## Cómo se configura

En IPv4 puede recibirse mediante [DHCP](/articulos/que-es-dhcp/) o configurarse manualmente, tanto en clientes como en servidores. En IPv6, los anuncios de router intervienen en el descubrimiento de routers predeterminados; no se debe trasladar sin cambios el mecanismo de IPv4.

## Cuando falla

- **Sin ruta predeterminada**, los destinos cubiertos por rutas específicas pueden seguir funcionando; los demás no tienen una salida elegida.
- **Con un siguiente salto inaccesible**, tener la entrada no basta: en IPv4 sobre Ethernet, puede fallar la obtención de su MAC mediante [ARP](/articulos/que-es-arp/).
- **Con salida pero sin retorno**, el envío puede llegar al destino y la respuesta no volver. La tabla local no describe por sí sola todo el recorrido.

Todo el recorrido, desde que un equipo envía un paquete hasta que llega al otro lado del mundo, lo cuenta [cómo viaja un paquete por internet](/articulos/como-viaja-un-paquete-por-internet/).

## Lo esencial

- La puerta de enlace predeterminada es el siguiente router de la ruta por defecto.
- Una ruta coincidente más específica tiene prioridad sobre ella.
- La ruta es una entrada de la tabla; la puerta de enlace es el siguiente salto que indica.
- Su ausencia no rompe las rutas específicas; su presencia no garantiza que funcione todo el camino.
