Una **simulación de eventos discretos** modela un sistema como una sucesión de **eventos** que ocurren en momentos concretos: un cliente llega, empieza a ser atendido, se va. Entre un evento y el siguiente no pasa nada relevante, así que la simulación **salta** directamente de uno a otro en lugar de avanzar segundo a segundo.

Sirve para estimar, bajo un modelo, qué proporción de clientes esperaría más de cinco minutos con distintas cantidades de cajas, o qué carga podrían atender unos servidores en hora punta. Una simulación finita no demuestra que nunca habrá una espera mayor.

## Las piezas

- **Reloj**: el tiempo actual de la simulación.
- **Lista de eventos futuros**: ordenada por tiempo. Se saca siempre el más próximo; es una [cola de prioridad](/articulos/monticulos-y-colas-de-prioridad/).
- **Estado**: lo que hay en cada momento, por ejemplo cuántos clientes esperan y si el empleado está ocupado.
- **Recursos** limitados: cajas, servidores, camas de un hospital.

## Un ejemplo: una ventanilla

Clientes que llegan a una ventanilla con un solo empleado. Cada uno tarda 1,5 minutos en ser atendido, por orden de llegada. El ejemplo recibe llegadas finitas no negativas y una duración finita positiva; en llegadas simultáneas manda el orden del array. Si varios eventos tienen el mismo tiempo, se procesa primero el que se programó antes.

```js
function simular(llegadas, duracionServicio) {
	const eventos = llegadas.map((tiempo, cliente) => ({ tiempo, tipo: "llegada", cliente, orden: cliente }));
	let siguienteOrden = eventos.length;
	const cola = [];
	const esperas = [];
	let ocupado = false;

	const empezar = (cliente, ahora) => {
		ocupado = true;
		esperas.push(ahora - llegadas[cliente]);
		eventos.push({ tiempo: ahora + duracionServicio, tipo: "salida", cliente, orden: siguienteOrden++ });
	};

	while (eventos.length > 0) {
		eventos.sort((a, b) => a.tiempo - b.tiempo || a.orden - b.orden);
		const evento = eventos.shift();

		if (evento.tipo === "llegada") {
			if (ocupado) cola.push(evento.cliente);
			else empezar(evento.cliente, evento.tiempo);
		} else {
			ocupado = false;
			if (cola.length > 0) empezar(cola.shift(), evento.tiempo);
		}
	}
	return esperas;
}

const esperas = simular([0, 1, 2, 3, 4], 1.5);
console.log(esperas.join(" ")); // "0 0.5 1 1.5 2"
```

El estado después de cada evento permite explicar esas esperas. Los clientes se numeran desde cero; «cola» excluye al que está siendo atendido:

| Tiempo | Evento | Cliente en servicio | Cola | Nueva espera registrada |
| --- | --- | --- | --- | --- |
| 0 | Llega 0 | 0 | Vacía | 0 |
| 1 | Llega 1 | 0 | 1 | — |
| 1,5 | Sale 0 | 1 | Vacía | 0,5 |
| 2 | Llega 2 | 1 | 2 | — |
| 3 | Llega 3 | 1 | 2, 3 | — |
| 3 | Sale 1 | 2 | 3 | 1 |
| 4 | Llega 4 | 2 | 3, 4 | — |
| 4,5 | Sale 2 | 3 | 4 | 1,5 |
| 6 | Sale 3 | 4 | Vacía | 2 |
| 7,5 | Sale 4 | Nadie | Vacía | — |

La llegada del cliente 3 estaba programada desde el principio, antes que la salida del 1, y por eso se procesa primero en el empate. Se atienden a razón de `1 / 1,5 ≈ 0,667` clientes por minuto, mientras llegan a razón de uno por minuto. Si esa pauta continuase indefinidamente, la cola crecería sin estabilizarse. Con estas llegadas regulares, dos empleados de igual velocidad bastarían para empezar cada atención sin espera; el código mostrado solo modela uno.

La simulación no avanza minuto a minuto: salta de evento en evento. Si entre dos clientes pasan tres horas, se resuelve en un paso.

Aquí se reordena un array en cada extracción para que el código sea corto. Eso no tiene el coste de un montículo: puede repetir trabajo sobre muchos eventos pendientes. Una implementación de mayor tamaño suele usar una cola de prioridad con inserción y extracción logarítmicas, más una cola FIFO eficiente para los clientes.

## Con azar

En la realidad, las llegadas y las duraciones varían. Se generan con [números aleatorios](/articulos/numeros-aleatorios-y-pseudoaleatorios/) que siguen distribuciones realistas, y se repite la simulación muchas veces, como en el [método de Monte Carlo](/articulos/metodo-de-monte-carlo/), para obtener no solo la espera media, sino cuánto puede variar.

En muchos modelos de colas con llegadas o servicios variables, las esperas crecen mucho al acercarse al 100 % de utilización: queda poco margen para absorber una racha de llegadas. No es una ley de cualquier sistema; llegadas perfectamente espaciadas y servicio determinista pueden comportarse de otra forma. Para dimensionar conviene representar esa variabilidad, como recuerda [escalado vertical y horizontal](/articulos/escalado-vertical-y-horizontal/).

## Herramientas

Para modelos reales hay bibliotecas especializadas. SimPy, en Python, define cada componente activo, un cliente, un vehículo, como un proceso, y ofrece recursos compartidos de capacidad limitada, como servidores o ventanillas. La propia documentación avisa de que es excesivo para simulaciones de paso fijo sin interacción entre procesos.

## Errores comunes

- **No definir desempates.** Dos eventos simultáneos se procesan en algún orden; si cambia el estado que observa cada uno, puede cambiar el resultado.
- **Tomar una ejecución como garantía de servicio.** Una muestra de llegadas no cubre todas las rachas posibles; se necesitan repeticiones y un modelo validado.
- **Medir solo la espera media.** Puede ocultar una minoría de esperas muy largas; conviene estudiar también percentiles y proporciones que superan el objetivo.

## Lo esencial

- Una simulación de eventos discretos modela un sistema como eventos en momentos concretos.
- Salta de evento en evento usando una cola de prioridad ordenada por tiempo.
- Sirve para dimensionar recursos y predecir colas y esperas.
- Con azar se repite muchas veces, como en Monte Carlo, para conocer también la variabilidad.
