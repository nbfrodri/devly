Un **demonio**, en inglés *daemon*, es un programa que se ejecuta en **segundo plano**, sin ventana ni terminal, y que normalmente arranca con el sistema y se queda esperando a hacer su trabajo. En Windows se llaman **servicios**, y en Linux se usa también esa palabra para el programa junto con su configuración.

Un servidor web, una base de datos, el programa que sincroniza la hora o el que registra los eventos del sistema son demonios.

## El nombre

No tiene nada de diabólico. Viene del "demonio de Maxwell", un ser imaginario de un experimento mental de física que trabaja sin descanso en segundo plano. Los programadores del MIT adoptaron la palabra en los años sesenta para estos procesos.

Por tradición, muchos terminan en "d": `sshd`, el servidor de acceso remoto; `systemd`, el sistema de inicio; `crond`, el de [tareas programadas](/articulos/tareas-programadas-cron/).

## Qué los distingue

- **No dependen de una sesión**: siguen funcionando aunque nadie haya iniciado sesión, y no se cierran al cerrar una terminal.
- **Arrancan solos** con el sistema.
- **Esperan**: casi todo el tiempo están parados, hasta que llega una conexión, se cumple una hora o pasa algo.
- **Escriben en registros** en lugar de en pantalla.

## Quién los gestiona

El **sistema de inicio**, el primer proceso que arranca el núcleo, como explica [el arranque de un sistema operativo](/articulos/arranque-de-un-sistema-operativo/). En la mayoría de las distribuciones de Linux es **systemd**.

Cada servicio se describe en un archivo de **unidad**:

```ini
[Unit]
Description=Mi aplicación web
After=network.target

[Service]
ExecStart=/usr/bin/node /srv/app/servidor.js
User=app
Restart=on-failure
Environment=PUERTO=3000

[Install]
WantedBy=multi-user.target
```

Dice qué programa ejecutar, con qué usuario, que arranque después de la red, y que lo reinicie si falla.

Se maneja con órdenes como estas:

```bash
sudo systemctl start mi-app       # arrancar
sudo systemctl stop mi-app        # parar
sudo systemctl enable mi-app      # que arranque con el sistema
systemctl status mi-app           # ver su estado
journalctl -u mi-app              # ver sus registros
```

## Lo que hace el gestor por ti

- **Arrancar en orden**, respetando dependencias.
- **Reiniciar** el servicio si se cae.
- **Parar de forma ordenada**, enviando primero la [señal](/articulos/senales-y-comunicacion-entre-procesos/) SIGTERM y, si no responde, SIGKILL.
- **Recoger los registros** de todos los servicios en un sitio.
- **Limitar recursos**: memoria máxima, uso de procesador.
- **Aislar**: ejecutar con un usuario sin privilegios, sin acceso a ciertas carpetas.

Antes, cada demonio tenía que hacer buena parte de esto por su cuenta, con técnicas complejas para separarse de la terminal. Hoy, el programa se ejecuta como uno normal y el gestor se ocupa del resto.

## Buenas prácticas

- **Un usuario propio y sin privilegios** por servicio, siguiendo el principio de mínimo privilegio que explica [permisos y usuarios](/articulos/permisos-y-usuarios/). Si alguien lo compromete, no obtiene el control del sistema.
- **Configuración por [variables de entorno](/articulos/variables-de-entorno-y-secretos/)**, no escrita en el código.
- **Terminar bien** al recibir SIGTERM: cerrar conexiones y terminar lo que estaba haciendo.
- **Registros útiles**, para saber qué ha pasado sin estar delante, como explica [observabilidad](/articulos/observabilidad/).

## En contenedores y Kubernetes

Dentro de un [contenedor](/articulos/que-es-docker/) no suele haber un sistema de inicio: la aplicación es el proceso principal, y es Docker o [Kubernetes](/articulos/que-es-kubernetes/) quien la arranca, la vigila y la reinicia. La idea es la misma, a otra escala.

## Lo esencial

- Un demonio es un programa en segundo plano, sin interfaz, que arranca con el sistema.
- En Linux los gestiona el sistema de inicio, normalmente systemd, mediante archivos de unidad.
- El gestor los arranca en orden, los reinicia si fallan y recoge sus registros.
- Conviene que cada servicio use un usuario sin privilegios y termine de forma ordenada.
