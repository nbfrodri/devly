Abre la consola de cualquier navegador y suma 0,1 más 0,2. El resultado no es 0,3.

```js
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
```

No es un error de JavaScript. También se observa con tipos binarios de doble precisión en otros lenguajes, aunque la forma de mostrar el resultado varía. Depende del tipo y de sus operaciones: los tipos decimales o racionales pueden representar este cálculo de forma exacta.

## El mismo problema, en decimal

Intenta escribir un tercio con decimales: 0,3333... No acaba nunca. Si solo tienes sitio para diez cifras, escribes 0,3333333333 y aceptas un pequeño error.

Y si sumas tres veces ese número, obtienes 0,9999999999, no 1.

No es que las matemáticas fallen. Es que un tercio no se puede escribir de forma exacta en base 10 con un número finito de cifras.

## En binario le pasa a 0,1

Los ordenadores trabajan en [binario](/articulos/que-es-un-bit/), y en binario las cifras tras la coma valen un medio, un cuarto, un octavo, y así sucesivamente.

Algunos números encajan a la perfección:

| Decimal | Binario |
| --- | --- |
| 0,5 | 0,1 |
| 0,25 | 0,01 |
| 0,75 | 0,11 |

Otros no. Un décimo no se puede escribir como una suma **finita** de potencias negativas de dos. En binario es periódico:

```
0,0001100110011001100110011...
```

El grupo `0011` se repite sin fin, igual que el 3 de un tercio.

Como la memoria es finita, el formato utiliza un número limitado de cifras y redondea al representable más cercano, con una regla para resolver empates. Lo que se guarda al escribir `0.1` no es exactamente un décimo, sino algo como:

```js
console.log((0.1).toFixed(20)); // "0.10000000000000000555"
```

Lo mismo le pasa a 0,2 y a 0,3. Al sumar las aproximaciones de 0,1 y 0,2, los pequeños errores no se cancelan, y el resultado es un número ligeramente distinto de la aproximación de 0,3.

En cambio, con números que sí encajan en binario no hay sorpresa:

```js
console.log(0.5 + 0.25 === 0.75); // true
```

## La coma flotante

El tipo `number` de JavaScript usa **coma flotante binaria de doble precisión**, un formato definido en IEEE 754. El estándar también incluye otros formatos: compartir su nombre no obliga a todos los tipos y lenguajes a producir o mostrar el mismo resultado.

Guarda cada número como en la notación científica: unas cifras significativas y un exponente que indica dónde va la coma. El formato más común usa 64 [bits](/articulos/que-es-un-bit/), lo que da unas quince o dieciséis cifras decimales de precisión.

Es un compromiso muy bueno: con el mismo tamaño representa desde números minúsculos hasta enormes. El precio es que muchos decimales finitos, como 0,1, necesitan aproximación en esa representación binaria.

## Cómo convivir con ello

### Elegir qué significa «igual»

La igualdad exacta es útil cuando quieres saber si dos valores representados coinciden, y funciona en operaciones exactas como `0.5 + 0.25 === 0.75`. Cuando esperas pequeñas diferencias de redondeo, puedes comprobar si están dentro de una tolerancia adecuada al problema:

```js
function casiIguales(a, b) {
	return Math.abs(a - b) < Number.EPSILON;
}

console.log(casiIguales(0.1 + 0.2, 0.3)); // true
```

`Number.EPSILON` es la distancia entre 1 y el siguiente `number` mayor. Resuelve este ejemplo, pero no es una tolerancia universal ni siquiera para todo cálculo cerca de 1. El error depende de las operaciones y de los datos. Puede hacer falta combinar tolerancia absoluta cerca de cero y relativa para magnitudes mayores.

### Importes con reglas explícitas

Si un importe exige exactitud en unidades decimales, conviene usar enteros en una unidad fijada o un tipo decimal apropiado. Una aproximación binaria puede cambiar el resultado de un redondeo; no introduce automáticamente un céntimo de error en cada operación.

Por ejemplo, estos importes usan céntimos enteros dentro del rango seguro de `number`:

```js
const precioEnCentimos = 10 + 20;

console.log(precioEnCentimos); // 30
console.log(precioEnCentimos / 100); // 0.3
```

La división final produce un `number` cuya presentación es `0.3`; no convierte su representación binaria en tres décimos exactos. Al calcular impuestos, repartir importes o convertir monedas, también hay que definir escala y redondeo. Muchos lenguajes y motores ofrecen tipos decimales, con una precisión finita que igualmente tiene límites.

### Redondear al mostrar

En este caso, el formateo oculta la diferencia al mostrar dos decimales. No cambia el valor utilizado en cálculos posteriores:

```js
console.log((0.1 + 0.2).toFixed(2)); // "0.30"
```

## También afecta a los enteros grandes

En JavaScript todos los números corrientes son de coma flotante, también los enteros. Todos los enteros del rango seguro se representan exactamente; por encima, algunos siguen siendo exactos y otros ya no se distinguen:

```js
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991
console.log(9007199254740992 + 1); // 9007199254740992
```

Por encima de ese límite, sumar 1 puede no cambiar nada. Para enteros mayores existe otro tipo, `BigInt`.

## Lo esencial

- Con `number` de JavaScript, las aproximaciones de 0,1 y 0,2 suman un valor distinto de la aproximación de 0,3.
- La causa es que 0,1 tiene infinitas cifras en binario, como un tercio en decimal, y se guarda aproximado.
- El formato de coma flotante es un estándar: no es un fallo de ningún lenguaje.
- La tolerancia depende del cálculo; igualdad exacta y proximidad responden preguntas distintas.
- Para importes con exactitud decimal, usa una representación y reglas de redondeo acordes al dominio.
