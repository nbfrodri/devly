Para un ordenador, una imagen son números. La forma más común de representarla es como una **cuadrícula de puntos**, llamados **píxeles**, donde cada uno tiene un color expresado con unos cuantos [bits](/articulos/que-es-un-bit/). A eso se le llama imagen **de mapa de bits**. La alternativa es describir la imagen con formas geométricas: una imagen **vectorial**.

## Píxeles

Un **píxel**, palabra con [su propia historia](/articulos/de-donde-viene-la-palabra-pixel/), es el elemento más pequeño de una imagen: un punto de un solo color. Vistos de lejos, muchos juntos forman la imagen, como las teselas de un mosaico.

La **resolución** es el número de píxeles, en ancho por alto.

```js
const pixeles = 1920 * 1080;

console.log(pixeles); // 2073600
console.log(((pixeles * 3) / 1e6).toFixed(1)); // "6.2"
```

Una imagen de 1920 por 1080 tiene algo más de dos millones de píxeles. Con 3 bytes por píxel, sus colores sin comprimir ocupan 6,2 megabytes decimales, sin contar cabeceras ni otros datos. Una imagen de 40 millones de píxeles ocuparía 120 MB con esa representación.

Por eso las imágenes casi nunca se guardan sin [comprimir](/articulos/compresion-de-datos/).

## El color

### Mezcla de luces

Muchas [pantallas](/articulos/como-funciona-una-pantalla/) combinan subpíxeles que emiten o dejan pasar luz roja, verde y azul. Variando su intensidad se obtiene una gama de colores, aunque no todos los que puede percibir el ojo. Es el modelo **RGB**, por las iniciales de rojo, verde y azul en inglés.

- Las tres al máximo dan blanco.
- Las tres apagadas, negro.
- Roja y verde, amarillo.

Funciona porque el ojo tiene tres tipos de células sensibles al color, y lo que se percibe depende de cuánto se estimula cada tipo.

### En números

Lo habitual es dedicar 8 bits a cada componente: un valor de 0 a 255. Son 24 bits por píxel, y más de 16 millones de colores.

Un color se escribe a menudo en [hexadecimal](/articulos/sistema-hexadecimal/), con dos cifras por componente. Esta función acepta una cadena válida con la forma `#RRGGBB`:

```js
function aRgb(hexadecimal) {
	return [1, 3, 5].map((i) => parseInt(hexadecimal.slice(i, i + 2), 16));
}

console.log(aRgb("#1f3fe0").join(" ")); // "31 63 224"
console.log(aRgb("#ffffff").join(" ")); // "255 255 255"
console.log(256 ** 3); // 16777216
```

`#1f3fe0` se separa en `1f`, `3f` y `e0`: 31, 63 y 224. Es poco rojo, algo de verde y mucho azul. Es una de las notaciones de [CSS](/articulos/que-es-css/). El significado preciso de esos números también depende del **espacio de color**, las reglas que relacionan los valores con colores concretos; esta notación de CSS utiliza sRGB.

### Profundidad de color

Es el número de bits por píxel.

| Bits por píxel | Colores | Uso |
| --- | --- | --- |
| 1 | 2 | Blanco y negro puro |
| 8 | 256 | Escala de grises, o una paleta |
| 24 | 16,7 millones | Color habitual |
| 32: RGB de 24 bits y alfa de 8 | 16,7 millones, con 256 niveles de opacidad | Imágenes con zonas transparentes |
| 30: RGB de 10 bits por canal | Más de mil millones | Degradados con más precisión |

Estas filas describen representaciones concretas: no todo archivo de 32 bits dedica 8 al alfa. Con pocos niveles, los degradados suaves pueden convertirse en franjas visibles. Tener más bits no garantiza por sí solo **alto rango dinámico (HDR)**: para representar una diferencia mayor entre luces y sombras también importan la codificación y la pantalla.

### Transparencia

Un cuarto valor, el **canal alfa**, indica cuánto deja ver cada píxel lo que hay detrás: de totalmente transparente a totalmente opaco. Permite poner un logotipo sobre cualquier fondo.

### Escala de grises

Hay distintas conversiones a grises. Una media simple trata los tres canales igual, aunque no contribuyen igual a la percepción. Esta aproximación usa los pesos de la señal de **luma** de BT.601, una combinación de componentes RGB ya codificados:

```js
const aGris = ([rojo, verde, azul]) =>
	Math.round(0.299 * rojo + 0.587 * verde + 0.114 * azul);

console.log(aGris([255, 0, 0])); // 76
console.log(aGris([0, 255, 0])); // 150
console.log(aGris([0, 0, 255])); // 29
```

Aquí el verde aporta más al gris que el azul. Es una transformación concreta, no una fórmula universal para medir la luz: otros espacios de color usan otros pesos, y calcular luminancia física exige además deshacer la transformación no lineal aplicada a los canales.

## Imágenes vectoriales

En lugar de píxeles, se guardan **instrucciones**: "un círculo de radio 40 en esta posición, relleno de azul".

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
	<circle cx="50" cy="50" r="40" fill="#1f3fe0" />
</svg>
```

El formato habitual en la web es **SVG**, que es texto. Puedes guardar el bloque como `circulo.svg` y abrirlo en un navegador. El mismo círculo en un mapa de bits sería una cuadrícula de colores: al ampliarla no aparecen nuevos detalles. En SVG, el navegador vuelve a calcular el contorno para la resolución de destino.

| | Mapa de bits | Vectorial |
| --- | --- | --- |
| Guarda | El color de cada píxel | Formas y sus propiedades |
| Al ampliar | No aparecen detalles nuevos; puede verse borrosa o pixelada | Las formas se vuelven a dibujar a la resolución de destino |
| Tamaño del archivo | Depende de la resolución, el contenido y la compresión | Depende de las formas, los recursos incluidos y la compresión |
| Sirve para | Fotografías | Logotipos, iconos, gráficos, tipografías |

Las fotografías suelen representarse mejor como mapas de bits; describir cada detalle con formas puede resultar muy complejo. Un logotipo geométrico encaja bien en SVG. Si un SVG incluye una fotografía de mapa de bits, esa parte conserva las limitaciones de su resolución.

Para mostrarse, una imagen vectorial tiene que convertirse en píxeles. De eso se encarga el programa que la dibuja.

## Formatos

Un formato define la estructura del archivo: píxeles o formas, compresión, transparencia y metadatos. Estas son sus variantes habituales en la web:

| Formato | Compresión | Transparencia | Conviene para |
| --- | --- | --- | --- |
| JPEG habitual | Con pérdida | No | Fotografías |
| PNG | Sin pérdida | Sí | Capturas, gráficos, imágenes con texto |
| GIF | Sin pérdida sobre una paleta de hasta 256 colores por tabla | Sí, sin grados | Animaciones simples |
| WebP | Las dos | Sí | Uso general en la web |
| AVIF | Las dos | Sí | Fotografías, evaluando calidad y coste de codificación |
| SVG | Es vectorial | Sí | Iconos y logotipos |

### Elegir bien

Como punto de partida:

- **Fotografías**, con muchos colores y transiciones suaves: compara JPEG, WebP y AVIF a una calidad visual aceptable. La reducción depende de la imagen y de los ajustes.
- **Gráficos**, con colores planos y bordes definidos: sin pérdida. PNG.
- **Iconos y logotipos**: SVG.

La compresión sin pérdida de PNG suele producir fotos más grandes que una versión con pérdida aceptable, pero no hay una proporción fija. En sentido contrario, un JPEG muy comprimido puede introducir manchas alrededor de letras y bordes. GIF conserva los índices de su paleta, pero convertir una foto a esa paleta puede perder colores; una animación puede usar distintas paletas en distintos fotogramas.

## Metadatos

Un archivo de imagen puede contener **metadatos**, información adicional como fecha, modelo de cámara, ajustes o coordenadas del lugar donde se tomó. No todas las fotos incluyen ubicación.

Antes de publicar una foto, revisa qué metadatos conserva. En una aplicación propia puedes eliminar la ubicación cuando no sea necesaria; no des por hecho que otra plataforma lo hará. Es una decisión de [privacidad](/articulos/rgpd-y-proteccion-de-datos/).

## En la web

Las imágenes suelen ser lo que más pesa de una página. Lo que más rinde:

- **El tamaño justo.** Reducir ancho y alto a una décima parte deja el 1 % de los píxeles. No implica reducir los bytes al 1 %: también interviene la compresión. Ajusta la resolución al tamaño mostrado y a la densidad de pantalla.
- **Varias versiones.** El HTML permite ofrecer distintos tamaños y formatos, y el navegador elige según la pantalla, como se explica en [diseño adaptable](/articulos/diseno-adaptable/).
- **Comparar formatos y calidad** con las imágenes reales.
- **Declarar las dimensiones**, para que la página no salte al cargar.
- **Carga diferida** de las que no están a la vista.
- **Texto alternativo** que transmita la información o función de la imagen. Las imágenes puramente decorativas llevan `alt=""` para que el lector de pantalla las ignore; consulta [accesibilidad](/articulos/accesibilidad-web/).

Las pantallas de alta densidad tienen varios píxeles físicos por cada unidad de medida de la página. Para que una imagen se vea nítida en ellas, debe tener más píxeles de los que indica su tamaño en pantalla.

Todo esto incide en las [Core Web Vitals](/articulos/rendimiento-web-y-core-web-vitals/).

## Errores comunes

- **Confundir resolución con tamaño del archivo.** Dos imágenes con los mismos píxeles pueden ocupar cantidades distintas por su contenido, formato y compresión.
- **Suponer que cambiar la extensión convierte la imagen.** Renombrar `.jpg` a `.png` no reescribe sus datos; hace falta decodificar y guardar en el formato de destino.
- **Ampliar para recuperar detalle.** Interpolar crea píxeles nuevos a partir de los existentes, pero no recupera lo que la captura no registró.

## Lo esencial

- Una imagen de mapa de bits es una cuadrícula de píxeles, cada uno con su color.
- El color se guarda como intensidades de rojo, verde y azul, normalmente con 8 bits cada una.
- Una imagen vectorial guarda formas, y se amplía sin perder nitidez.
- El formato y la compresión deben elegirse según el contenido y la calidad necesaria; revisa también los metadatos antes de publicar.
