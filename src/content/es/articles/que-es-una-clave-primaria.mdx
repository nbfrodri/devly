Una **clave primaria** es la columna, o el conjunto de columnas, que **identifica de forma única** cada fila de una tabla en una [base de datos relacional](/articulos/que-es-una-base-de-datos/). Dos filas no pueden tener la misma, y no puede estar vacía.

## Un ejemplo

```sql
CREATE TABLE clientes (
	id SERIAL PRIMARY KEY,
	correo TEXT UNIQUE NOT NULL,
	nombre TEXT NOT NULL
);
```

`id` es la clave primaria. La base de datos rechazará cualquier fila con un `id` repetido o nulo, y crea automáticamente un [índice](/articulos/indices-de-bases-de-datos/) sobre ella para buscar deprisa.

## Para qué sirve

- **Identificar** una fila sin ambigüedad: actualizar o borrar exactamente esa.
- **Relacionar** tablas: otras tablas guardan ese valor como **clave foránea**. Cada pedido guarda el `id` de su cliente.

## Natural o artificial

- **Natural**: un dato que ya es único en el mundo real, como un número de documento.
- **Artificial**: un número o un identificador generado sin significado, como `id`.

Se suelen preferir las artificiales. Los datos reales cambian o resultan no ser tan únicos como se creía: un correo se puede cambiar, un documento puede estar mal escrito. Un identificador sin significado nunca necesita cambiar.

## Compuesta

A veces la clave son varias columnas juntas. En una tabla que une pedidos y productos, la pareja `(pedido_id, producto_id)` identifica cada línea, como explica el [modelo entidad-relación](/articulos/modelo-entidad-relacion/).

## Otras formas de identificar

Una tabla puede tener varias [claves candidatas](/articulos/que-es-una-clave-candidata/). La primaria es la elegida como identificador principal; las demás siguen necesitando sus restricciones de unicidad y ausencia de NULL si deben identificar cada fila.

## Con qué no confundirla

- **Clave foránea**: apunta a la clave primaria de otra tabla. Puede repetirse.
- **Columna única**: también impide repetidos, como `correo` en el ejemplo, pero una tabla puede tener varias. Clave primaria solo hay una.
