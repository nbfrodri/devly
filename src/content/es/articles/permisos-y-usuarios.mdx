Los **permisos** son reglas que el sistema utiliza para autorizar operaciones. Un [proceso](/articulos/que-es-un-proceso/) actúa con unas **credenciales**, como una identidad de usuario y grupos. El sistema contrasta esas credenciales con las reglas del recurso y otras restricciones. Aquí seguimos el modelo básico de archivos de tipo Unix, concretado en Linux.

## Por qué no todos los programas tienen el mismo acceso

Un editor necesita leer y modificar tus documentos; un servicio que atiende peticiones de internet puede necesitar solo una carpeta concreta. Ejecutarlos con identidades distintas permite reducir qué recursos puede afectar cada uno. Es el **mínimo privilegio**: conceder lo necesario para su tarea.

Un **usuario** tiene un identificador numérico, **UID**. Un **grupo** reúne identidades a las que se puede conceder acceso conjunto. Los procesos conservan varias identidades con funciones diferentes; para el modelo habitual de acceso a archivos importan la identidad efectiva y los grupos aplicables. Un programa hereda credenciales al iniciarse, pero ciertos mecanismos autorizados pueden cambiarlas.

Separar cuentas limita acceso; no demuestra que un fallo solo pueda afectar a esa cuenta. También importan los permisos concedidos, servicios accesibles y posibles vulnerabilidades.

## Elegir el conjunto de permisos

Cada archivo tiene propietario, grupo y tres conjuntos básicos:

| Conjunto | Cuándo se utiliza en este modelo |
| --- | --- |
| Propietario | La identidad del proceso coincide con la del dueño |
| Grupo | No coincide con el dueño, pero uno de sus grupos coincide con el del archivo |
| Otros | No coincide ninguna de las anteriores |

**No se suman los tres conjuntos.** Sin reglas adicionales, si eres el propietario se evalúan sus permisos, aunque «otros» tenga más. Las listas de control de acceso, o **ACL**, permiten reglas más detalladas y amplían este modelo.

Cada conjunto tiene tres bits, escritos `r`, `w` y `x`:

| Permiso | En un archivo regular | En un directorio |
| --- | --- | --- |
| Lectura, `r` | Leer contenido | Enumerar nombres |
| Escritura, `w` | Modificar contenido | Modificar entradas, junto con búsqueda |
| Ejecución o búsqueda, `x` | Permitir su ejecución, si el resto de requisitos se cumple | Buscar entradas y recorrerlo |

Para abrir `/datos/informe.txt` hay que poder recorrer los directorios de la ruta y obtener el permiso correspondiente sobre el archivo. Leer los nombres de una carpeta no concede automáticamente lectura de todos sus archivos.

Eliminar `informe.txt` modifica su entrada en el directorio. Normalmente requiere escritura y búsqueda en ese directorio, no escritura en el contenido del archivo. El **sticky bit**, utilizado en directorios compartidos como `/tmp`, restringe quién puede eliminar o renombrar entradas aunque pueda escribir allí. También pueden intervenir un montaje de solo lectura u otras políticas.

## Leer letras y números

Un modo como `rw-r-----` contiene tres tríos: propietario `rw-`, grupo `r--`, otros `---`. El propietario puede leer y escribir, el grupo leer y los demás no obtienen esos permisos.

Cada posición tiene un valor: lectura 4, escritura 2 y ejecución 1. La suma de cada trío es una cifra de **octal**, base ocho. El modo anterior es `640`: seis para el propietario, cuatro para el grupo y cero para otros. Son nueve [bits](/articulos/que-es-un-bit/) de permiso.

Este ejemplo convierte solo esos nueve caracteres básicos. Rechaza letras en una posición incorrecta; los indicadores especiales como `s` y `t` quedan fuera de su alcance:

```js
function aNumero(permisos) {
	if (typeof permisos !== "string" || permisos.length !== 9 ||
		!/^(?:[r-][w-][x-]){3}$/.test(permisos)) {
		throw new TypeError("Se esperan tres grupos de r, w y x o guiones");
	}
	const valores = { r: 4, w: 2, x: 1, "-": 0 };
	let resultado = "";
	for (let i = 0; i < 9; i += 3) {
		const trio = permisos.slice(i, i + 3);
		resultado += [...trio].reduce((suma, letra) => suma + valores[letra], 0);
	}
	return resultado;
}

console.log(aNumero("rwxr-xr--")); // "754"
console.log(aNumero("rw-r--r--")); // "644"
console.log(aNumero("rw-r-----")); // "640"
```

## Cambiar el modo de un archivo propio

`chmod` cambia permisos; no cambia la identidad del proceso. Este bloque completo usa Bash y utilidades de Linux, sin privilegios de administrador. Crea su propio directorio temporal y retira únicamente los objetos que acaba de crear:

```bash
(
	carpeta_prueba=$(mktemp -d) || exit 1
	archivo_prueba="$carpeta_prueba/nota.txt"
	printf '%s\n' 'hola' > "$archivo_prueba" || exit 1
	chmod 600 "$archivo_prueba" || exit 1
	stat -c '%a' "$archivo_prueba"
	chmod g+r "$archivo_prueba" || exit 1
	stat -c '%a' "$archivo_prueba"
	rm -- "$archivo_prueba" && rmdir -- "$carpeta_prueba"
)
```

Imprime `600` y `640`. Primero solo el dueño recibe lectura y escritura; después `g+r` añade lectura al grupo. `u`, `g` y `o` designan propietario, grupo y otros. El directorio temporal tiene sus propias restricciones: conceder lectura al grupo del archivo no concede recorrido por su carpeta.

`chown` cambia propietario y grupo cuando quien lo solicita está autorizado. No hace falta cambiar de dueño para practicar con tu propio archivo. Tampoco hay un modo correcto universal: `644` permite lectura a otros; `600` la restringe en este modelo, pero no cifra el contenido ni impide accesos privilegiados.

## Privilegios y otras restricciones

**root**, normalmente UID 0, es la identidad administrativa tradicional. Linux separa facultades privilegiadas en **capacidades**. Permiten excepciones a ciertas comprobaciones, pero no significan que cualquier operación sea posible: pueden seguir aplicándose restricciones de montaje, políticas obligatorias o límites de un contenedor.

`sudo` ejecuta una orden con la identidad autorizada por su política, frecuentemente root. No implica siempre pedir contraseña ni convierte toda orden en válida. Para editar una nota propia no hace falta elevar privilegios.

## Errores comunes

- **Responder a cualquier denegación con `chmod 777`.** Amplía los nueve permisos, pero no resuelve rutas incorrectas, montajes de solo lectura ni todas las políticas. Primero identifica proceso, operación y componente que la rechaza.
- **Suponer que `x` basta para ejecutar.** También hacen falta un formato o intérprete válido, acceso a la ruta y un montaje que lo permita.
- **Confundir propietario con copia protegida.** Los permisos regulan acceso; no sustituyen cifrado, copias ni un diseño que limite qué datos puede alcanzar cada servicio.

## Lo esencial

- El sistema decide según credenciales, operación, recurso y restricciones.
- Propietario, grupo y otros son clases que se seleccionan, no permisos que se suman.
- Los bits tienen significados diferentes en archivos y directorios.
- Los privilegios permiten excepciones concretas; no eliminan todos los límites.
