**Linux** es, en sentido estricto, un **[núcleo](/articulos/que-es-el-kernel/)**: software que gestiona ejecución, memoria y acceso a recursos del ordenador. En el uso corriente, «Linux» también designa [sistemas operativos](/articulos/que-es-un-sistema-operativo/) completos que utilizan ese núcleo. Conviene distinguir ambos sentidos para entender qué se instala y quién mantiene cada parte.

## De un núcleo a un sistema utilizable

Linus Torvalds inició Linux en 1991. Su publicación permitió que otras personas lo probaran y contribuyeran a desarrollarlo; la historia de su nombre se amplía en [por qué Linux se llama Linux](/articulos/por-que-linux-se-llama-linux/).

Un núcleo necesita otros programas para ofrecer un entorno de uso. El proyecto **GNU** ya desarrollaba herramientas para un sistema libre de tipo Unix: un [compilador](/articulos/compilador-e-interprete/) para traducir código y una [shell](/articulos/terminal-y-shell/) para interpretar órdenes, entre otras piezas. Su combinación con Linux dio lugar a sistemas conocidos como **GNU/Linux**. No todo sistema que usa el núcleo Linux contiene exactamente ese conjunto.

Una **[distribución](/articulos/distribuciones-de-linux/)** selecciona, integra y mantiene componentes. Por ejemplo, dos instalaciones pueden usar distintas versiones o configuraciones de Linux, distintos escritorios y diferentes herramientas de actualización. Compartir la familia del núcleo no significa que sus archivos sean idénticos.

| Pieza | Responsabilidad | Ejemplo de componente |
| --- | --- | --- |
| Núcleo | Administrar recursos y ofrecer servicios básicos | Linux |
| Biblioteca | Ofrecer funciones reutilizables a programas | Una biblioteca de C |
| Intérprete de órdenes | Interpretar instrucciones de una shell | Bash |
| Gestor de servicios | Iniciar y supervisar trabajo del sistema | systemd, en sistemas que lo eligen |
| Gestor de paquetes | Instalar y actualizar componentes preparados | APT, DNF o pacman |
| Entorno gráfico | Organizar ventanas e interacción visual | GNOME o KDE Plasma |

Android también utiliza Linux, pero añade sus propias bibliotecas, servicios y entorno de ejecución de aplicaciones. Compartir núcleo con una distribución de escritorio no hace intercambiables automáticamente sus aplicaciones.

## Seguir la lectura de una nota

Imagina que abres `nota.txt` con un editor. El recorrido ayuda a separar responsabilidades:

1. **El editor** interpreta tu acción y decide qué archivo necesita. Su interfaz no la dibuja el núcleo.
2. **Una biblioteca** puede preparar la solicitud. El programa pide al sistema abrir y leer mediante [llamadas al sistema](/articulos/llamadas-al-sistema/).
3. **Linux** resuelve la ruta, comprueba el acceso aplicable y utiliza la implementación del [sistema de archivos](/articulos/sistema-de-archivos/). Si necesita datos del dispositivo, intervienen sus controladores.
4. **El editor** recibe bytes e interpreta el formato del documento para mostrártelo.

La lectura no exige siempre acceder físicamente al disco: los datos pueden estar ya en memoria. Tampoco equivale una petición a leer todo el archivo de una vez. Cada capa tiene un contrato; un error de ruta, permisos o formato puede aparecer en una etapa distinta.

Mientras ocurre, Linux reparte tiempo de procesador entre tareas y organiza su memoria. Un **[proceso](/articulos/que-es-un-proceso/)** es una ejecución con recursos propios; los **[permisos](/articulos/permisos-y-usuarios/)** limitan operaciones según las identidades y reglas del sistema.

## Cómo se organiza Linux por dentro

Linux se describe como **monolítico y modular**. Muchos servicios esenciales comparten el espacio privilegiado del núcleo; ciertos componentes pueden construirse como módulos cargables. La comparación de [núcleo monolítico y micronúcleo](/articulos/nucleo-monolitico-y-micronucleo/) explica esa frontera.

No todos los componentes son módulos, ni cualquier módulo puede descargarse mientras está en uso. Un **controlador** es software que permite gestionar un dispositivo; su disponibilidad depende del hardware, la versión y la configuración. La existencia de Linux para una arquitectura no garantiza soporte para cualquier equipo con ese procesador.

## Qué permite su licencia

El núcleo se distribuye bajo **GPL versión 2**, con las notas y excepciones que documenta el proyecto. Permite usar, estudiar, modificar y redistribuir el software conforme a sus condiciones. **Libre no significa obligatoriamente sin precio**: puede cobrarse por distribuirlo o prestar soporte.

La redistribución de código o binarios tiene obligaciones, entre ellas conservar los derechos de la licencia y proporcionar el código fuente correspondiente mediante las formas admitidas. Modificarlo para uso privado no obliga por sí solo a publicar esos cambios en internet. La interfaz de llamadas al sistema tampoco convierte automáticamente cualquier aplicación que la use en GPL.

Una distribución reúne componentes con licencias propias. El artículo sobre [licencias de software](/articulos/licencias-de-software/) desarrolla sus diferencias; no basta con mirar el nombre del núcleo para determinar la licencia de todo lo instalado.

El desarrollo se organiza mediante revisiones, mantenedores de subsistemas y contribuciones de personas y organizaciones. Que el código sea accesible permite inspeccionarlo y proponer cambios; no hace que cualquier propuesta se incorpore sin revisión.

## Ideas de tipo Unix que encontrarás

Linux sigue interfaces y convenciones de tipo Unix. Muchas operaciones utilizan descriptores de archivos, incluso para dispositivos o canales, pero «todo es un archivo» es una simplificación: cada recurso tiene capacidades diferentes.

El árbol de directorios parte de `/`. Otros sistemas de archivos se incorporan en puntos de ese árbol, lo que se llama **montar**. Directorios como `/etc`, para configuración, y `/var`, para datos variables, tienen convenciones que explica [la jerarquía de Linux](/articulos/jerarquia-de-directorios-de-linux/).

La [shell](/articulos/terminal-y-shell/) permite conectar herramientas. Muchas configuraciones usan texto, aunque también existen formatos binarios e interfaces de administración. El usuario `root` tiene facultades administrativas; sus excepciones y restricciones se estudian con los permisos, no como un poder sin límites.

## Dónde encaja y qué comprobar

Linux se utiliza en servidores, ordenadores personales, sistemas Android y dispositivos integrados. Los **[contenedores Linux](/articulos/contenedores-y-maquinas-virtuales/)** comparten un núcleo Linux; en un equipo anfitrión de otro sistema puede proporcionarlo una máquina virtual. También existen contenedores de Windows, por lo que «contenedor» no significa siempre Linux.

Al preparar un equipo, comprueba aplicaciones, controladores, arquitectura y mantenimiento de la distribución concreta. Estudiar Linux permite observar mecanismos reales del sistema operativo; no obliga a atribuirle ventajas universales de velocidad, seguridad o compatibilidad.

## Errores comunes

- **Descargar solo el núcleo esperando un escritorio.** Para un entorno completo necesitas componentes integrados.
- **Confundir código disponible con ausencia de condiciones.** Las licencias determinan derechos y obligaciones.
- **Atribuir cualquier problema al núcleo.** El editor, biblioteca, servicio, configuración o controlador también forman parte del recorrido.

## Lo esencial

- Linux nombra un núcleo y, coloquialmente, sistemas construidos sobre él.
- Las distribuciones integran y mantienen componentes que pueden variar.
- Las aplicaciones solicitan recursos al núcleo mediante interfaces definidas.
- Licencia, soporte de hardware y compatibilidad de aplicaciones se comprueban por separado.
