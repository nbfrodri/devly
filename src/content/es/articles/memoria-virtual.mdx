La **memoria virtual** permite que un [proceso](/articulos/que-es-un-proceso/) trabaje con direcciones que se traducen a recursos físicos. El sistema operativo configura esas traducciones y permisos; el hardware los aplica al acceder a memoria. Dos procesos pueden usar el mismo número de dirección y llegar a lugares diferentes.

Además de separar espacios de direcciones, permite compartir regiones de forma controlada y mantener fuera de la RAM ciertos datos. No promete memoria ilimitada ni convierte cada fallo de acceso en una lectura de disco.

## Direcciones del proceso y direcciones físicas

Una **dirección virtual** pertenece al espacio que ve el proceso. No todo ese espacio tiene que ser accesible: puede contener huecos y regiones con permisos diferentes. Que la numeración permita cero no significa que el programa tenga memoria asignada en esa dirección.

Una **dirección física** identifica una posición en el espacio físico del sistema. En los ejemplos siguientes apuntará a [RAM](/articulos/memoria-ram-y-almacenamiento/). Las traducciones pertenecen al contexto del proceso, por lo que la dirección virtual 100 de A no tiene por qué significar lo mismo que la 100 de B.

## Páginas, marcos y desplazamientos

En un sistema paginado, las **páginas** dividen el espacio virtual y los **marcos** dividen la memoria física. Usaremos páginas de 4096 bytes, cuatro kibibytes; existen otros tamaños.

Una dirección se separa en número de página y **desplazamiento**, la posición dentro de ella. La tabla de páginas proporciona el marco y los permisos. Para este modelo hemos asignado deliberadamente la página cero:

| Proceso | Página virtual | Marco físico | Permiso |
| --- | --- | --- | --- |
| A | 0 | 5 | Leer y escribir |
| B | 0 | 9 | Leer y escribir |
| A y B | 1 | 2 | Leer |

La dirección 100 pertenece a la página 0 con desplazamiento 100. En A llega a `5 × 4096 + 100 = 20580`; en B, a `9 × 4096 + 100 = 36964`.

En cambio, 4100 pertenece a la página 1 con desplazamiento 4. Ambos procesos llegan a 8196: el ejemplo comparte ese marco para lectura. No hay contradicción entre espacios propios y páginas compartidas.

```js
const tamano = 4096;
const tablaA = { 0: { marco: 5, escritura: true }, 1: { marco: 2, escritura: false } };
const tablaB = { 0: { marco: 9, escritura: true }, 1: { marco: 2, escritura: false } };

function traducir(tabla, direccion, escribir = false) {
	if (!Number.isSafeInteger(direccion) || direccion < 0) {
		throw new RangeError("Dirección entera no negativa requerida");
	}
	const pagina = Math.floor(direccion / tamano);
	const entrada = tabla[pagina];
	if (entrada === undefined) return "sin traducción presente";
	if (escribir && !entrada.escritura) return "escritura no permitida";
	return entrada.marco * tamano + direccion % tamano;
}

console.log(traducir(tablaA, 100)); // 20580
console.log(traducir(tablaB, 100)); // 36964
console.log(traducir(tablaA, 4100), traducir(tablaB, 4100)); // 8196 8196
console.log(traducir(tablaA, 4100, true)); // "escritura no permitida"
console.log(traducir(tablaA, 9000)); // "sin traducción presente"
```

La función explica traducción y permisos en tablas pequeñas. No simula un sistema operativo ni decide si una página ausente debe crearse, recuperarse o rechazarse.

## La MMU y la TLB

La **unidad de gestión de memoria**, MMU, participa en la traducción y comprobación de permisos. Para evitar recorrer tablas en cada acceso, una caché llamada **TLB** conserva traducciones y atributos recientes.

Un fallo de TLB significa que la traducción no estaba en esa caché. Puede resolverse consultando las tablas, sin traer datos del disco. El recorrido lo realiza hardware o software según la arquitectura. Su coste depende de la organización de tablas y del patrón de acceso; no existe una tasa de aciertos garantizada.

## Qué significa un fallo de página

Cuando el acceso no puede completarse con la traducción o los permisos disponibles, el procesador entrega el control al sistema operativo. Este examina la dirección, el tipo de acceso y las regiones válidas del proceso. Según el sistema y el caso, puede ocurrir lo siguiente:

| Causa | Respuesta posible |
| --- | --- |
| Primera escritura en memoria anónima válida | Asignar un marco inicializado, sin leer una copia del disco |
| Página válida guardada en intercambio | Recuperarla del almacenamiento |
| Escritura sobre una página compartida con copia en escritura | Crear una copia privada y ajustar permisos |
| Dirección no asignada o acceso prohibido | Rechazar el acceso y notificar o terminar el proceso |

La **copia en escritura** permite compartir inicialmente una página mientras nadie la modifique. El primer escritor obtiene su copia para que su cambio no afecte al otro proceso. Una página de solo lectura no autoriza siempre esta solución: depende de cómo esté definida la región.

Si el sistema resuelve el fallo, actualiza el estado necesario y puede reintentar la instrucción. El programa observa al menos el tiempo empleado; si no se puede resolver, no continúa como si nada.

## Capacidad, protección y coste

El **[intercambio o swap](/articulos/swap-y-memoria-ram/)** permite retirar ciertas páginas de RAM, pero puede no estar habilitado y no toda página es intercambiable. Algunas páginas respaldadas por archivos pueden descartarse y volver a leerse sin escribir una copia nueva.

Si el conjunto de páginas activas no cabe y hay que moverlas continuamente, el sistema puede sufrir **hiperpaginación** o *thrashing*. Reservar espacio virtual tampoco garantiza conseguir RAM después: influyen los límites y la política de asignación.

La protección depende de traducciones, permisos y privilegios correctamente aplicados. Las regiones compartidas son explícitas; una dirección virtual por sí sola no concede acceso a memoria ajena. Marcar datos como no ejecutables ayuda a limitar ataques, pero no sustituye las demás defensas.

La [pila y el montículo](/articulos/pila-y-monticulo-de-memoria/) organizan regiones usadas por el programa dentro de este espacio; no son dos memorias físicas independientes.

## Lo esencial

- La dirección virtual se interpreta dentro de un espacio de direcciones y sus permisos.
- La traducción cambia página por marco y conserva el desplazamiento.
- Un fallo de TLB y un fallo de página son situaciones distintas.
- Un fallo de página puede requerir asignar, copiar, recuperar datos o rechazar el acceso.
