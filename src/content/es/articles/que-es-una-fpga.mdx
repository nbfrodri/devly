Una **FPGA**, matriz de puertas programable en campo, es un circuito integrado con lógica e interconexiones que pueden configurarse después de fabricarlo. La configuración selecciona funciones y conexiones entre recursos existentes; no fabrica transistores nuevos ni permite convertir un chip pequeño en un circuito de tamaño ilimitado.

Muchos modelos pueden reconfigurarse, pero el mecanismo y sus límites dependen del dispositivo. La idea central es adaptar hardware a una tarea: decidir qué calcula cada bloque y cómo pasan los datos entre ellos.

## Una función como tabla

Una pieza habitual es la **tabla de consulta**, LUT. Una LUT de cuatro entradas guarda dieciséis bits: una salida para cada combinación posible. Las entradas seleccionan qué casilla leer, como una tabla de verdad de [lógica digital](/articulos/puertas-logicas/).

Tomemos `F = (x AND y AND z) OR w`. La salida debe activarse cuando x, y y z estén activos juntos, o cuando w esté activo por sí solo. Este JavaScript construye una LUT de ejemplo; no configura una FPGA real:

```js
const lut = Array.from({ length: 16 }, (_, i) => {
	const [x, y, z, w] = [(i >> 3) & 1, (i >> 2) & 1, (i >> 1) & 1, i & 1];
	return (x & y & z) | w;
});

console.log(lut.join("")); // "0101010101010111"
console.log(lut[0b1110], lut[0b1100]); // 1 0
```

Declaramos el orden `xyzw`: x es el bit más significativo. `1110` selecciona la casilla 14: las tres primeras entradas valen 1 y sale 1. `1100` selecciona la casilla 12: falta z y w tampoco activa la salida, por lo que sale 0. Si w pasa a 1, `1101` selecciona la casilla 13 y sale 1.

Cambiar los bits almacenados cambia la función. Esto no significa que haya dieciséis procesos ejecutándose: la combinación de entradas selecciona un valor mediante el circuito de la LUT.

## Guardar estado y conectar bloques

Los bloques lógicos suelen combinar LUT, [biestables](/articulos/circuitos-secuenciales-y-biestables/) y selección de conexiones. Una salida puede pasar directamente al siguiente bloque o guardarse en un registro, según el diseño.

Por ejemplo, podríamos capturar F en cada flanco de reloj para que otro bloque use un valor estable. Debemos respetar tiempos de propagación y captura: configurar lógica no elimina esas restricciones.

Una FPGA también puede incorporar bloques dedicados de memoria, multiplicadores o interfaces. La cantidad, organización y funciones disponibles varían entre familias. Las conexiones tienen límites de capacidad y retardo; un diseño puede caber en número de LUT y aun así no cumplir su frecuencia objetivo.

## La misma función en CPU y FPGA

Un [procesador](/articulos/como-funciona-un-procesador/) puede leer cuatro entradas, calcular F mediante instrucciones y escribir una salida. Su software decide cuándo repetir el cálculo, y puede compartir recursos con otras tareas.

En la FPGA podemos dedicar una LUT y conexiones a F. Sus entradas producen una salida tras el retardo del circuito; si añadimos registro, se captura según el reloj. Otra LUT puede calcular otra función a la vez. También podemos compartir recursos entre ciclos si conviene ahorrar espacio.

La comparación útil exige las mismas entradas, frecuencia de actualización y condiciones de salida. Leer sensores, transferir datos y sincronizar señales puede dominar el tiempo en ambos casos. Una FPGA no es automáticamente más rápida ni más eficiente para cualquier programa.

Además, puede implementar un **procesador configurable**, como LatticeMico32, que sí ejecuta instrucciones. Algunos dispositivos combinan lógica programable con procesadores físicos ya integrados. Configurar hardware y ejecutar software pueden coexistir.

## Del diseño a la configuración

1. Describir funciones, registros e interfaces con un lenguaje de hardware, como Verilog o VHDL, y comprobar su comportamiento.
2. **Sintetizar**: transformar la descripción en recursos lógicos compatibles con el dispositivo.
3. **Colocar y enrutar**: asignar bloques físicos y conexiones, y comprobar restricciones temporales.
4. Generar y cargar el archivo de configuración, llamado **bitstream**.

Una descripción contiene comportamientos concurrentes y también construcciones secuenciales; no debe leerse automáticamente como una lista de instrucciones de CPU. Tampoco todo código válido para simulación puede sintetizarse en hardware.

## Cuándo tiene sentido

Una FPGA permite ensayar un circuito antes de fabricar un **ASIC**, un chip diseñado para una aplicación concreta, o adaptar interfaces y procesamiento de señales después de fabricar el equipo.

Un ASIC puede optimizar área, energía y rendimiento para una tarea y un volumen suficientes, con un coste inicial de diseño y fabricación. Sus circuitos físicos quedan fijados, aunque puede incluir registros configurables o procesadores. Una CPU facilita cambiar programas; una FPGA ofrece lógica configurable dentro de sus recursos. Elegir exige comparar desarrollo, unidades producidas, consumo y requisitos, sin asignar a cada categoría una velocidad universal.

## Lo esencial

- Una FPGA configura funciones y conexiones entre recursos físicos ya fabricados.
- Una LUT almacena una tabla de verdad; los registros permiten conservar estado.
- El paralelismo posible depende del diseño, los recursos y la llegada de datos.
- Una FPGA puede alojar un procesador; configurar lógica no excluye ejecutar instrucciones.
