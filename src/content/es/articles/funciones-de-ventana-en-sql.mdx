Una **función de ventana** en [SQL](/articulos/que-es-sql/) calcula un valor para cada fila a partir de un **conjunto de filas relacionadas**, su ventana, sin agruparlas en una sola. Permite obtener totales acumulados, posiciones en una clasificación o comparaciones con la fila anterior, conservando el detalle de cada fila.

## El problema

`GROUP BY` resume: si se agrupan las ventas por mes, se obtiene una fila por mes y se pierde el detalle. A veces se quieren las dos cosas a la vez: cada venta **y** el total de su mes, o cada mes **y** el acumulado hasta él.

## La sintaxis

Ejecuta los bloques SQL en orden en una base SQLite vacía. Cada fila representa las ventas de una tienda en un mes del mismo año:

```sql
CREATE TABLE ventas (
	tienda TEXT NOT NULL,
	mes INTEGER NOT NULL,
	total INTEGER NOT NULL,
	PRIMARY KEY (tienda, mes)
);
INSERT INTO ventas VALUES
	('Norte', 1, 100), ('Norte', 2, 150), ('Norte', 3, 120),
	('Sur', 1, 80), ('Sur', 3, 40);
```

Una función de ventana lleva la cláusula `OVER`, que define su cálculo. Para la tienda Norte:

```sql
SELECT mes, total,
	SUM(total) OVER (ORDER BY mes) AS acumulado,
	RANK() OVER (ORDER BY total DESC) AS posicion
FROM ventas
WHERE tienda = 'Norte'
ORDER BY mes;
```

- `SUM(total) OVER (ORDER BY mes)` suma el total desde el primer mes hasta el actual.
- `RANK() OVER (ORDER BY total DESC)` da la posición de cada mes según sus ventas.

El resultado contiene `(1, 100, 100, 3)`, `(2, 150, 250, 1)` y `(3, 120, 370, 2)`. El `ORDER BY` exterior ordena las filas devueltas; el de cada `OVER` organiza su cálculo. Pueden ser diferentes.

Lo mismo, imitado en JavaScript:

```js
const ventas = [
	{ mes: 1, total: 100 },
	{ mes: 2, total: 150 },
	{ mes: 3, total: 120 },
];

let suma = 0;
const acumulado = ventas.map((v) => (suma = suma + v.total));

const posiciones = ventas.map(
	(v) => 1 + ventas.filter((otro) => otro.total > v.total).length,
);

console.log(acumulado.join(" ")); // "100 250 370"
console.log(posiciones.join(" ")); // "3 1 2"
```

Cada mes conserva su fila, con dos datos calculados sobre la ventana.

## Particiones

`PARTITION BY` reinicia la ventana para cada grupo:

```sql
SELECT tienda, mes, total,
	SUM(total) OVER (PARTITION BY tienda ORDER BY mes) AS acumulado_tienda
FROM ventas
ORDER BY tienda, mes;
```

El acumulado empieza de cero para cada tienda: Norte conserva `100, 250, 370`; Sur obtiene `80, 120`. La partición no junta esas filas como haría `GROUP BY`.

## Las más usadas

| Función | Qué devuelve |
| --- | --- |
| `ROW_NUMBER()` | Un número correlativo |
| `RANK()` | La posición, con empates y saltos: 1, 1, 3 |
| `DENSE_RANK()` | La posición, con empates sin saltos: 1, 1, 2 |
| `LAG(columna)` | El valor de la fila anterior |
| `LEAD(columna)` | El valor de la fila siguiente |
| `SUM`, `AVG`, `COUNT` | La agregación sobre la ventana |

`LAG` permite comparar con el periodo anterior sin [JOIN](/articulos/tipos-de-join/): el crecimiento respecto al mes pasado.

## Marcos

El **marco** limita qué filas de la partición usa una agregación para cada fila. Esta media toma la fila actual y hasta dos anteriores:

```sql
SELECT tienda, mes,
	AVG(total) OVER (
		PARTITION BY tienda ORDER BY mes
		ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
	) AS media
FROM ventas
ORDER BY tienda, mes;
```

Para Norte, las medias son `100`, `125` y aproximadamente `123,33`: la tercera usa `(100 + 150 + 120) / 3`. Para Sur son `80` y `60`, calculadas con las filas de enero y marzo. **Tres filas no garantizan tres meses consecutivos**: falta febrero. Si un mes sin fila debe contar como cero, hay que generar ese calendario y expresar esa decisión antes del cálculo.

Sin marco explícito, una agregación con `ORDER BY` usa por defecto un marco de tipo `RANGE` hasta la fila actual y sus empates, en SQLite y PostgreSQL. Con dos filas del mismo mes, ambas podrían recibir el mismo acumulado. `ROWS` cuenta posiciones de filas; necesita un orden que resuelva los empates si quieres resultados reproducibles por fila. Aquí `(tienda, mes)` es único.

Estos detalles importan al analizar [series temporales](/articulos/series-temporales/): la consulta debe corresponder al periodo que quieres medir.

## Errores comunes

- **Confundir orden del cálculo y orden de salida.** El `ORDER BY` de `OVER` no garantiza cómo se presentan las filas; añade el exterior cuando importe.
- **Filtrar antes y esperar que la ventana vea lo eliminado.** `WHERE` se aplica antes del cálculo. Si filtras a marzo antes de sumar, enero y febrero ya no forman parte de la entrada.
- **Usar `ROW_NUMBER()` sin resolver empates.** Si importa cuál recibe cada número, añade una columna que determine un orden único. `RANK()` expresa otra intención: conservar empates.

## Lo esencial

- Una función de ventana calcula sobre un grupo de filas sin juntarlas en una.
- `OVER` define la ventana; `PARTITION BY` la reinicia por grupo; `ORDER BY` la ordena.
- Sirven para acumulados, posiciones, comparaciones con la fila anterior y medias móviles.
