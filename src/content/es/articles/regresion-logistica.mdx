La **regresión logística** es un modelo que estima la probabilidad de una clase, habitualmente en un problema binario. Combina características mediante pesos y transforma esa puntuación con una función que produce valores entre cero y uno.

## Por qué no basta una recta

Quieres clasificar mensajes como correo no deseado o legítimo. Una regresión lineal corriente puede producir valores negativos o mayores que uno; no son probabilidades válidas.

La regresión logística conserva una puntuación lineal, pero aplica la **función sigmoide**: `1 / (1 + exp(-z))`, donde `z` es la puntuación. A medida que `z` aumenta, la probabilidad se acerca a uno; si disminuye mucho, se acerca a cero.

Se llama regresión por su formulación estadística, aunque se utiliza para [clasificación](/articulos/clasificacion-y-regresion/). El nombre no convierte su salida en una predicción de cualquier magnitud numérica.

## Cómo funciona

### De puntuación a probabilidad

En una situación simplificada, una característica indica cuántas señales sospechosas tiene un mensaje. Hemos fijado unos pesos didácticos; este código no entrena un detector real:

```js
const sigmoide = (z) => 1 / (1 + Math.exp(-z));
const probabilidad = (senales) => sigmoide(-2 + 2 * senales);

console.log(probabilidad(0).toFixed(3)); // "0.119"
console.log(probabilidad(1).toFixed(3)); // "0.500"
console.log(probabilidad(2).toFixed(3)); // "0.881"
```

Los pesos determinan cómo influyen las entradas antes de la transformación. En un modelo entrenado, se aprenden a partir de ejemplos etiquetados, no se eligen solo porque una salida parezca convincente.

## Cómo aprende el modelo

El entrenamiento suele minimizar una **pérdida logarítmica**, que penaliza asignar poca probabilidad a la respuesta correcta. Una predicción muy segura y equivocada recibe una penalización grande. El [descenso del gradiente](/articulos/descenso-del-gradiente/) puede ajustar los pesos para reducir esa pérdida.

### Una actualización paso a paso

Partimos de dos mensajes y unos parámetros iniciales:

| Mensaje | Señales sospechosas | Etiqueta real | Probabilidad inicial |
| --- | --- | --- | --- |
| Legítimo | 0 | 0 | 0,5 |
| Spam | 2 | 1 | 0,5 |

El peso y el intercepto empiezan en cero. Por eso la puntuación de ambos mensajes es cero y la sigmoide devuelve 0,5.

Para esta pérdida, el **gradiente** del peso es el promedio de `(probabilidad - etiqueta) × entrada`. El del intercepto es el promedio de `probabilidad - etiqueta`. El gradiente indica hacia dónde aumenta la pérdida; restarlo mueve los parámetros en la dirección contraria.

El cálculo sigue cuatro pasos:

1. Calcular las probabilidades con los parámetros actuales.
2. Restar a cada probabilidad su etiqueta real.
3. Promediar las contribuciones al gradiente.
4. Restar el gradiente multiplicado por la **tasa de aprendizaje**, aquí 0,4.

```js
const datos = [{ x: 0, y: 0 }, { x: 2, y: 1 }];
let peso = 0;
let intercepto = 0;
const sigmoid = (z) => 1 / (1 + Math.exp(-z));
const errores = datos.map(({ x, y }) => sigmoid(intercepto + peso * x) - y);
const gradientePeso = errores.reduce((s, e, i) => s + e * datos[i].x, 0) / datos.length;
const gradienteIntercepto = errores.reduce((s, e) => s + e, 0) / datos.length;
peso -= 0.4 * gradientePeso;
intercepto -= 0.4 * gradienteIntercepto;

console.log(peso.toFixed(1)); // "0.2"
console.log(sigmoid(intercepto + peso * 2).toFixed(3)); // "0.599"
```

El mensaje de spam pasa de 0,5 a aproximadamente 0,599. El legítimo continúa en 0,5 porque el intercepto aún no cambió. Antes de otro paso se recalculan ambas probabilidades: no se reutilizan los errores iniciales.

Dos ejemplos no bastan para obtener un detector fiable, pero permiten ver cómo las etiquetas modifican la predicción.

### Entender la penalización

La pérdida de un positivo es `-log(p)`: con `p = 0,5` vale aproximadamente 0,693; con `p = 0,599`, 0,513. Para un negativo se usa `-log(1 - p)`. Por eso una respuesta segura pero equivocada resulta tan costosa. En entrenamiento real también puede añadirse **regularización**, una penalización que limita pesos excesivos.

## De probabilidad a etiqueta

Para producir una etiqueta, eliges un **umbral**. Con umbral 0,5 clasificas como positiva una probabilidad igual o superior a ese valor. Pero 0,5 no es una obligación del modelo.

- **Evitar falsos positivos:** puedes exigir una probabilidad mayor antes de mandar automáticamente un correo a spam.
- **Detectar más casos sospechosos:** puedes reducir el umbral para enviarlos a revisión, aceptando revisar también más mensajes legítimos.

El umbral depende del coste de ambos errores. Se elige y evalúa con datos adecuados, separado del ajuste de pesos.

## Sus límites

### Una probabilidad no es certeza

Que el modelo produzca 0,9 no demuestra que tenga razón en el 90 % de cualquier grupo o entorno. La **calibración** estudia si los valores predichos corresponden a frecuencias observadas en datos representativos.

El cambio de distribución o una selección poco representativa puede empeorar esa relación. También puede haber clases desequilibradas: una exactitud alta no basta para saber si detecta los positivos relevantes. Utiliza métricas y umbrales ajustados al problema.

### La frontera básica es lineal

En las características elegidas, la frontera de decisión del caso binario básico es lineal. Si las clases requieren relaciones más complejas, necesitas transformar características o elegir otro modelo. Más complejidad no elimina la necesidad de validación.

El preprocesamiento forma parte del sistema. Si escalas las entradas al entrenar, debes aplicar la misma transformación al predecir. Y no debes aprender ese escalado utilizando el conjunto reservado para la prueba final.

## Errores comunes

- **Confundir probabilidad con etiqueta.** El umbral decide la clase; no cambia por sí solo los pesos.
- **Interpretar 0,9 como una garantía universal de acierto.** La calibración depende de datos representativos.
- **Preparar las entradas de otra forma al predecir.** El modelo necesita las mismas transformaciones usadas al entrenar.

## Lo esencial

- La sigmoide convierte una puntuación lineal en un valor entre cero y uno.
- El entrenamiento aprende pesos; el umbral determina etiquetas.
- Evalúa errores, calibración y costes de las decisiones.
- El nombre «regresión» no impide que se utilice para clasificación.
