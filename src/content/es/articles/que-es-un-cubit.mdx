Un **cúbit**, o bit cuántico, es una unidad de información descrita por las reglas de la mecánica cuántica. Al medirlo de la forma que usaremos aquí, se obtiene un [bit](/articulos/que-es-un-bit/): 0 o 1. Antes de medir, su estado puede contener una **superposición**, una combinación de los estados asociados a esos resultados.

La utilidad no consiste en leer muchos valores a la vez. Consiste en transformar esas combinaciones para obtener distribuciones de resultados útiles para ciertos cálculos.

## Qué describe el estado

Trabajaremos con un modelo ideal de un cúbit aislado, sin ruido, en un **estado puro**: descrito mediante un vector de amplitudes. Para un cúbit son dos números, `a` y `b`, asociados a los estados que escribimos `|0⟩` y `|1⟩`. Los símbolos entre barras y ángulos nombran estados; no son instrucciones de programación.

La expresión `a |0⟩ + b |1⟩` indica una superposición. Las **amplitudes** no son directamente probabilidades: pueden tener signo o ser números complejos. Estos últimos tienen una parte real y otra imaginaria; no hace falta operarlos para seguir los primeros ejemplos.

Para pasar de amplitud a probabilidad se calcula su **módulo al cuadrado**. Si la amplitud es real, basta elevarla al cuadrado. Si es `x + yi`, el resultado es `x² + y²`. Las probabilidades de 0 y 1 deben sumar uno.

## Un resultado de cada medición

Una **base de medición** especifica qué estados se distinguen. Usaremos la base computacional, formada por `|0⟩` y `|1⟩`. Medir entrega uno de esos resultados, con probabilidad `|a|²` o `|b|²`.

La [probabilidad](/articulos/probabilidad-basica/) va de 0 a 1: 0,36 equivale al 36 %. Considera las amplitudes reales 0,6 y 0,8:

```js
const amplitudes = [0.6, 0.8];
const probabilidades = amplitudes.map((a) => a * a);

console.log(probabilidades.map((p) => p.toFixed(2)).join(" ")); // "0.36 0.64"
console.log(probabilidades.reduce((suma, p) => suma + p, 0).toFixed(2)); // "1.00"
```

El código calcula las probabilidades del modelo; no mide un cúbit físico. Si preparas muchas veces ese mismo estado y mides cada preparación, esperas aproximarte a esas proporciones, sin exigir exactamente 36 ceros en cien intentos.

En una medición ideal, obtener 0 deja el estado en `|0⟩`. Medir inmediatamente otra vez en la misma base, sin operaciones ni ruido intermedios, vuelve a dar 0. Para repetir el experimento original hay que preparar de nuevo la superposición.

## Por qué no basta con lanzar una moneda

Las amplitudes `[0.6, 0.8]` y `[0.6, -0.8]` dan las mismas probabilidades en esa base. Sin embargo, otras operaciones pueden distinguir sus efectos: las amplitudes se combinan antes de convertirlas en probabilidades.

Esa combinación puede reforzar o cancelar contribuciones. Se llama **interferencia**. El siguiente artículo, [puertas cuánticas e interferencia](/articulos/puertas-cuanticas-e-interferencia/), sigue dos operaciones para mostrar una cancelación con números. Un listado de probabilidades, por sí solo, pierde la información de fase necesaria para predecir ese recorrido.

## Varios cúbits y el coste de representarlos

Dos cúbits pueden dar `00`, `01`, `10` o `11` al medir en la base computacional. Un vector general de estado puro asigna una amplitud a cada combinación. Para `n` cúbits, esa representación tiene `2^n` entradas.

Si guardamos explícitamente cada amplitud compleja con dos números de ocho bytes:

```js
const bytesPorAmplitud = 16;
const cubits = 50;
const petabytes = (2 ** cubits * bytesPorAmplitud) / 1e15;

console.log(petabytes.toFixed(0)); // "18"
```

Son unos 18 petabytes decimales solo para ese vector denso. **No es un mínimo para toda simulación de cincuenta cúbits.** Algunos estados y familias de operaciones admiten representaciones mucho más compactas, como muestra el formalismo de estabilizadores estudiado por Gottesman. Tampoco puedes extraer las `2^n` amplitudes mediante una sola medición: obtienes una cadena de `n` bits.

El **[entrelazamiento](/articulos/entrelazamiento-cuantico/)** añade relaciones entre cúbits que no se describen asignando un estado puro independiente a cada uno. Sus consecuencias dependen del estado conjunto y de cómo se mida.

## Del modelo al dispositivo

Las operaciones físicas tienen errores. La **decoherencia** degrada las relaciones de fase al interactuar el sistema con su entorno; no significa que cualquier interacción destruya instantáneamente todo el estado. Hay diferentes tecnologías y condiciones de funcionamiento, no una única temperatura exigida por la definición de cúbit.

La corrección de errores busca proteger información lógica utilizando varios cúbits físicos y operaciones adicionales. Contar cúbits físicos no basta para conocer qué cálculo fiable puede ejecutar una máquina.

Tampoco hay aceleración universal. El algoritmo de Shor, por ejemplo, proporciona un procedimiento eficiente de factorización en el modelo cuántico ideal; ejecutarlo a una escala útil requiere recursos y control de errores. Ese resultado no demuestra que cualquier programa cotidiano vaya a funcionar más rápido.

## Lo esencial

- Las amplitudes describen el estado; sus módulos al cuadrado dan probabilidades en la base elegida.
- Medir devuelve un resultado clásico y puede cambiar el estado.
- Interferencia y entrelazamiento permiten operaciones distintas de las de un bit clásico.
- El coste de simulación y las ventajas prácticas dependen del estado, del algoritmo y del dispositivo.
