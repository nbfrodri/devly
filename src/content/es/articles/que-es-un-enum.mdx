Un **enum**, o **tipo enumerado**, es un [tipo de dato](/articulos/tipos-de-datos/) cuyo conjunto de valores posibles es **cerrado** y está escrito en el código, cada uno con un nombre: los palos de la baraja, los días de la semana, los estados de un pedido. Una variable de ese tipo solo puede tomar uno de esos valores. El nombre viene de **enumerar**: se escriben todos los valores posibles.

## El problema que resuelve

Sin enums, los estados se suelen representar con textos o números sueltos:

```js
const pedido = { estado: "enviado" };

if (pedido.estado === "enviddo") {
	console.log("en camino");
} else {
	console.log("no entra"); // "no entra"
}
```

Una errata en `"enviddo"` no da ningún error: la condición, simplemente, nunca se cumple. Y nada impide asignar un estado que no existe, como `"perdido"`. Con números es peor: `estado = 3` no dice nada a quien lee el código.

Un enum da un nombre a cada valor y deja que el lenguaje compruebe que solo se usan los que existen.

## En JavaScript: un objeto congelado

JavaScript no tiene enums, pero se imitan con un objeto que no se puede modificar:

```js
const Estado = Object.freeze({
	PENDIENTE: "pendiente",
	ENVIADO: "enviado",
	ENTREGADO: "entregado",
});

const pedido = { estado: Estado.ENVIADO };

console.log(pedido.estado === Estado.ENVIADO); // true
console.log(Estado.ENVIDO); // undefined
console.log(Object.values(Estado).length); // 3
```

Escribir mal el nombre da `undefined`: no lanza un error automáticamente. El editor puede ayudar con autocompletado, pero el lenguaje no impide guardar cualquier otro texto en `pedido.estado`. `Object.freeze` protege las propiedades del objeto `Estado`, no los valores que aceptan otras variables.

## En TypeScript

[TypeScript](/articulos/que-es-typescript/) sí comprueba los valores al compilar. Tiene dos formas habituales:

```ts
enum Direccion {
	Arriba,
	Abajo,
}

type Estado = "pendiente" | "enviado" | "entregado";

let estado: Estado = "enviado";
estado = "enviddo"; // Error de compilación: ese valor no está en el tipo
```

- Un `enum` numérico asigna números automáticamente: `Arriba` vale 0 y `Abajo`, 1. Los enums de texto, con un valor escrito para cada miembro, se leen mejor al depurar.
- Una **unión de literales** consigue lo mismo sin generar código extra, y es la opción que prefieren muchos equipos.

## En otros lenguajes

```python
from enum import Enum

class Estado(Enum):
    PENDIENTE = 1
    ENVIADO = 2
    ENTREGADO = 3
```

- **Java** y **Python** tienen enums que son clases: cada valor es un [objeto](/articulos/que-es-un-objeto/), y pueden tener métodos.
- **Rust** va más allá: cada variante puede llevar **datos propios**. Una dirección IP puede ser la variante `V4` con cuatro números o la `V6` con un texto. Rust no tiene un valor nulo: usa un enum, `Option`, con las variantes "hay un valor" y "no hay nada", y obliga a tratar los dos casos.

## Recorrer todos los casos

La gran ventaja de un conjunto cerrado es que se puede comprobar que se han tratado **todos** los casos:

```js
const ETIQUETAS = {
	pendiente: "Preparando",
	enviado: "En camino",
	entregado: "Entregado",
};

function etiqueta(estado) {
	if (Object.hasOwn(ETIQUETAS, estado)) {
		return ETIQUETAS[estado];
	}
	return "Estado desconocido";
}

console.log(etiqueta("enviado")); // "En camino"
console.log(etiqueta("perdido")); // "Estado desconocido"
```

`Object.hasOwn` comprueba si la tabla tiene una propiedad propia con ese nombre. Si existe, `ETIQUETAS[estado]` obtiene su texto; si no, la función devuelve el mensaje alternativo. Este código maneja un valor inesperado, pero no comprueba que la tabla incluya todos los estados posibles.

En Rust, una expresión `match` exige cubrir todas las variantes. En TypeScript puedes comprobar exhaustividad mediante una rama que deba recibir el tipo `never`, que representa un caso imposible. Una cadena cualquiera de `if` no obtiene esa garantía automáticamente. Solo los lugares preparados para esa comprobación avisarán al añadir un estado nuevo.

## Cuándo usarlos

- Cuando el conjunto de valores es **fijo y conocido**: estados, tipos, direcciones, niveles.
- No cuando los valores cambian con frecuencia o los define el usuario, como las categorías de una tienda: eso va en una [base de datos](/articulos/que-es-una-base-de-datos/).

Los estados de un enum son a menudo los de una máquina de estados, como los que dibuja un diagrama de estados de [UML](/articulos/uml/).

## Errores comunes

- **Creer que nombres compartidos validan entradas externas.** Un texto recibido de una API debe comprobarse antes de tratarlo como un estado válido; los tipos de TypeScript no se ejecutan en producción.
- **Confundir casos posibles con transiciones permitidas.** Que existan `PENDIENTE` y `ENTREGADO` no decide si se puede pasar directamente de uno al otro. Esa regla requiere lógica adicional.
- **Suponer exhaustividad automática.** Un valor por defecto puede ocultar que falta tratar una nueva variante. Hay que elegir una comprobación que detecte ese caso.

## Lo esencial

- Un enum es un tipo con un conjunto cerrado de valores con nombre.
- Evita las erratas y los valores imposibles de los textos y números sueltos.
- JavaScript los imita con objetos congelados; TypeScript, Java, Python y Rust los tienen en el lenguaje.
- Permiten comprobar que se tratan todos los casos posibles.
