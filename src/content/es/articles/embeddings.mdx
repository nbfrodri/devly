Un **embedding** es una representación de algo, normalmente un texto, como una lista de números. En una representación semántica se entrena un modelo para que la proximidad entre vectores refleje relaciones útiles entre sus entradas. Esa proximidad permite ordenar candidatos por parecido; no demuestra que dos textos signifiquen lo mismo.

A esa lista de números se la llama **vector**.

## Qué problema resuelve

Para un programa, "coche" y "automóvil" son dos textos sin relación: no comparten casi ninguna letra. Y "banco" y "banca" se parecen mucho, signifiquen lo que signifiquen.

Una búsqueda puramente literal puede perder un documento que diga "reparación de neumáticos" cuando consultas "cómo arreglar una rueda pinchada". Los buscadores también pueden ampliar consultas con sinónimos; los embeddings ofrecen otra manera de relacionar expresiones distintas.

Hace falta una forma de representar el **significado**, no las letras.

## Significados como posiciones

Imagina un mapa en el que cada palabra es un punto. Las palabras de animales están en una zona, las de comida en otra, las de tecnología en otra. Dentro de la zona de animales, "perro" y "lobo" están cerca; "perro" y "sardina", algo más lejos.

Un embedding es la posición de un texto en un mapa así. Las coordenadas son los números del vector.

Un mapa de verdad tiene dos dimensiones. Los embeddings suelen tener decenas, cientos o miles de dimensiones. Su tamaño y entrenamiento determinan qué relaciones pueden representar; cada coordenada no corresponde necesariamente a un matiz interpretable.

Nadie define qué significa cada dimensión. Las aprende un modelo de [aprendizaje automático](/articulos/que-es-el-aprendizaje-automatico/) a partir de enormes cantidades de texto, con una idea de fondo: las palabras que aparecen en contextos parecidos suelen significar cosas parecidas.

## Medir el parecido

Una medida habitual es la **similitud del coseno**, que compara la dirección de dos vectores no nulos del mismo espacio:

- 1: misma dirección.
- 0: direcciones perpendiculares.
- −1: direcciones opuestas.

Estos valores describen geometría. Su interpretación semántica depende del modelo y de la tarea: un coseno cercano a cero no demuestra por sí solo que dos textos carezcan de relación.

Este ejemplo usa vectores inventados de tres dimensiones para ilustrarlo. La función presupone arrays de igual longitud, con números finitos y norma distinta de cero; los vectores reales los calcula un modelo:

```js
function similitud(a, b) {
	let producto = 0;
	let normaA = 0;
	let normaB = 0;

	for (let i = 0; i < a.length; i++) {
		producto = producto + a[i] * b[i];
		normaA = normaA + a[i] * a[i];
		normaB = normaB + b[i] * b[i];
	}

	return producto / (Math.sqrt(normaA) * Math.sqrt(normaB));
}

const perro = [0.9, 0.8, 0.1];
const lobo = [0.8, 0.9, 0.2];
const ordenador = [0.1, 0.2, 0.9];

console.log(similitud(perro, lobo) > 0.95); // true
console.log(similitud(perro, ordenador) < 0.4); // true
```

En este ejemplo, "perro" y "lobo" dan un coseno de aproximadamente 0,990; "perro" y "ordenador", 0,303. Los límites 0,95 y 0,4 solo comprueban estos números inventados: no son umbrales generales de significado.

## No solo palabras

Se pueden calcular embeddings de frases, párrafos y documentos enteros. También de imágenes, sonidos o productos de una tienda. Incluso existen modelos que colocan texto e imágenes en el mismo espacio, de modo que la frase "un gato durmiendo" queda cerca de una foto de un gato durmiendo.

## Para qué se usan

### Búsqueda semántica

En lugar de buscar palabras, se busca significado:

1. Se calcula el embedding de cada documento y se guarda.
2. Cuando llega una consulta, se calcula su embedding.
3. Se devuelven los documentos cuyos vectores están más cerca.

Un modelo adecuado puede situar "rueda pinchada" cerca de "reparación de neumáticos". Hay que comprobarlo con consultas y documentos representativos; el entrenamiento no garantiza cada coincidencia.

### Dar contexto a un modelo de lenguaje

Los parámetros de un [modelo de lenguaje](/articulos/modelos-de-lenguaje/) reflejan su entrenamiento, pero al responder también utiliza el contexto que recibe. Para que responda sobre tus documentos, se usa la [**generación aumentada por recuperación**](/articulos/generacion-aumentada-por-recuperacion/) (RAG):

1. Con embeddings, se buscan los fragmentos de tus documentos más relacionados con la pregunta.
2. Esos fragmentos se añaden a la instrucción que recibe el modelo.
3. El modelo responde apoyándose en ellos.

El modelo dispone así de información concreta adicional. Esto puede reducir errores, aunque recuperar un fragmento incorrecto o ignorarlo al responder sigue siendo posible.

### Otros usos

- **Recomendaciones**: sugerir productos o artículos parecidos a los que has visto.
- **Agrupación**: reunir automáticamente textos que tratan de lo mismo.
- **Detección de duplicados**: encontrar preguntas que dicen lo mismo con otras palabras.
- **Clasificación**: decidir a qué categoría pertenece un texto por su cercanía a ejemplos.

## Bases de datos vectoriales

Comparar una consulta con millones de vectores, uno a uno, sería lento. Las [**bases de datos vectoriales**](/articulos/bases-de-datos-vectoriales/) están diseñadas para encontrar con rapidez los vectores más cercanos a uno dado.

Muchas usan índices **aproximados**, que reducen el trabajo a cambio de poder omitir vecinos cercanos. También existen búsquedas exactas. La latencia y la calidad dependen del índice, sus parámetros, los datos y el hardware; deben medirse.

## Lo que hay que saber antes de usarlos

- **Se necesita un espacio compatible.** Tener el mismo número de dimensiones no basta. Lo habitual es usar el mismo modelo, aunque algunos sistemas entrenan codificadores distintos para consultas y documentos dentro de un espacio común. Al cambiar de espacio, hay que recalcular o convertir los vectores con un procedimiento validado.
- **Cercanía no es verdad.** "El café es bueno" y "el café es malo" pueden quedar próximos: hablan de lo mismo. Un embedding capta el tema mejor que el matiz.
- **Heredan [sesgos](/articulos/sesgos-en-los-algoritmos/).** Reflejan las asociaciones presentes en los textos de entrenamiento, incluidos los estereotipos.
- **El tamaño de los fragmentos importa.** Un documento puede superar el límite de entrada del modelo o mezclar varios temas. Dividirlo ayuda a localizar pasajes, pero fragmentos demasiado pequeños pueden perder contexto.
- **No sustituyen a la búsqueda por palabras.** Para un código de producto o un nombre propio, la coincidencia literal sigue siendo mejor. Muchos sistemas combinan las dos.

## Lo esencial

- Un embedding representa un texto como un vector de números.
- Un modelo semántico busca representar relaciones útiles mediante proximidad; puede equivocarse.
- La similitud del coseno mide lo próximos que están dos vectores.
- Permiten la búsqueda por significado y dar contexto relevante a un modelo de lenguaje.
- La comparación exige vectores de un espacio compatible, no solo de igual longitud.
