Un **callback**, o función de **retrollamada**, es una [función](/articulos/funciones/) que se entrega como argumento a otra función, para que esta la ejecute cuando le corresponda.

La idea se parece a dejar tu teléfono en una tienda: "llámame cuando llegue el pedido". Ilustra un callback asíncrono. Otros se llaman inmediatamente, dentro de la función que los recibe.

## Dos usos

### Personalizar un comportamiento

La función que recibe el callback hace un trabajo general, y el callback decide un detalle:

```js
const ordenados = [3, 1, 2].toSorted((a, b) => a - b);
const dobles = [1, 2, 3].map((n) => n * 2);

console.log(ordenados.join(" ")); // "1 2 3"
console.log(dobles.join(" ")); // "2 4 6"
```

`toSorted` sabe ordenar, pero necesita que le digas cómo comparar. `map` sabe recorrer, pero necesita que le digas qué hacer con cada elemento. A las funciones que reciben otras se las llama [de orden superior](/articulos/funciones-de-orden-superior-y-clausuras/).

### Reaccionar a algo que pasará después

```javascript
setTimeout(() => {
	console.log("Se ejecuta el callback"); // "Se ejecuta el callback"
}, 0);
console.log("Primero continúa el programa"); // "Primero continúa el programa"
```

La última línea imprime primero; el callback del temporizador se ejecuta después. Cero no significa ejecución inmediata. Los manejadores de eventos de un botón siguen otra condición: se llaman si llega el evento, que podría no ocurrir.

## El problema de anidar

Cuando cada operación asíncrona necesitaba un callback, y cada callback lanzaba otra operación, el código se iba anidando hacia la derecha sin fin. Se le llamó el "infierno de los callbacks". Las [promesas y async/await](/articulos/promesas-y-async-await/) nacieron para resolverlo.

## Con qué no confundirlo

Un callback no es un tipo especial de función: es cualquier función, usada de una manera concreta. Lo que la convierte en callback es que se pasa a otra para que la llame.
