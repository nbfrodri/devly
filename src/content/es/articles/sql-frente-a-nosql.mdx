Una base de datos **SQL**, o relacional, guarda la información en tablas con una estructura fija y relaciones entre ellas. Una base de datos **NoSQL** la guarda con otras formas, más flexibles, pensadas para casos en los que las tablas encajan mal.

A las primeras también se las llama **estructuradas** y a las segundas **no estructuradas**, aunque los datos de una base NoSQL sí tienen estructura: lo que cambia es que no está fijada de antemano.

Este artículo las compara. Cada una tiene su explicación completa en [qué es una base de datos](/articulos/que-es-una-base-de-datos/) y [qué es una base de datos NoSQL](/articulos/bases-de-datos-nosql/).

## La diferencia de fondo

En una base relacional **defines la estructura antes de guardar nada**: qué tablas hay, qué columnas tiene cada una y de qué tipo. La base de datos rechaza lo que no encaje.

En una base NoSQL **guardas los datos con la forma que tengan**. Cada elemento puede ser distinto del anterior, y de que tengan sentido se ocupa tu programa.

## El mismo dato en los dos modelos

Un cliente con dos pedidos, en una base relacional, se reparte en dos tablas unidas por una clave:

| id | nombre |
| --- | --- |
| 1 | Ana |

| id | cliente_id | total |
| --- | --- | --- |
| 10 | 1 | 25 |
| 11 | 1 | 40 |

En una base de documentos, el cliente y sus pedidos van juntos:

```js
const cliente = {
	nombre: "Ana",
	pedidos: [
		{ id: 10, total: 25 },
		{ id: 11, total: 40 },
	],
};

console.log(cliente.pedidos.length); // 2
```

En el primer caso, para ver a Ana con sus pedidos hay que combinar las dos tablas. En el segundo se lee un solo documento. A cambio, en el primero cada dato está escrito una única vez, y en el segundo, si los pedidos se consultan también por otros caminos, es fácil acabar con copias que hay que mantener iguales.

## Comparación

| | SQL (relacional) | NoSQL |
| --- | --- | --- |
| Forma de los datos | Tablas de filas y columnas | Documentos, clave-valor, columnas anchas o grafos |
| Estructura | Fija, definida antes | Flexible, puede variar por elemento |
| Relaciones | Claves foráneas y combinación de tablas | Limitadas; se guarda junto lo que se lee junto |
| Lenguaje de consulta | [SQL](/articulos/que-es-sql/), común a todas | Propio de cada sistema |
| Transacciones | Garantías fuertes | Depende del sistema; a menudo más limitadas |
| Crecimiento | Sobre todo con una máquina más potente | Pensadas para repartirse entre muchas máquinas |
| Quién valida los datos | La base de datos | El programa |

Son tendencias generales. Hay bases relacionales que se reparten entre máquinas y bases NoSQL con transacciones completas.

## Qué se gana y qué se pierde

### Con una base relacional

- **Los datos son coherentes.** La base de datos impide un pedido sin cliente o una fecha con letras.
- **Cualquier pregunta es posible.** Como los datos están separados y relacionados, puedes combinarlos de formas que no habías previsto al diseñar.
- **Cambiar la estructura cuesta.** Añadir una columna a una tabla con millones de filas hay que planificarlo.

### Con una base NoSQL

- **Empezar y cambiar es rápido.** No hay que definir ni migrar una estructura.
- **Las lecturas previstas son muy eficientes**, porque los datos se guardan con la forma en que se van a pedir.
- **Las preguntas imprevistas son difíciles.** Si necesitas los datos de una forma que no anticipaste, puede hacer falta reorganizarlos.
- **La coherencia depende de ti.** Nada impide guardar dos documentos del mismo tipo con campos distintos.

## Cómo elegir

Elige **relacional** cuando:

- los datos tienen una estructura clara y relaciones entre sí;
- la corrección es prioritaria: dinero, inventario, reservas;
- no sabes aún qué consultas vas a necesitar.

Elige **NoSQL** cuando:

- la forma de los datos varía mucho de un elemento a otro;
- lees casi siempre bloques completos por un identificador;
- el volumen exige repartir los datos entre muchas máquinas;
- lo importante son las conexiones entre elementos, caso en el que encaja una base de grafos.

Si dudas, una base relacional es el punto de partida más seguro: cubre bien la mayoría de las aplicaciones y es más fácil pasar de un modelo estricto a uno flexible que al revés.

## No hay que elegir solo una

Muchas aplicaciones combinan las dos: una base relacional para los datos principales y una clave-valor como caché o para las sesiones. Cada dato va a donde mejor se maneja.

## Confusiones frecuentes

- **"NoSQL es más moderno, luego es mejor."** Resuelve problemas distintos. Las bases relacionales siguen siendo las más usadas.
- **"NoSQL no tiene estructura."** La tiene, pero no la impone la base de datos.
- **"SQL no escala."** Escala hasta volúmenes muy grandes; lo que resulta más difícil es repartirla entre muchas máquinas.

## Lo esencial

- Una base relacional fija la estructura y garantiza la coherencia; una NoSQL da flexibilidad y la coherencia queda en manos del programa.
- La relacional responde bien a preguntas imprevistas; la NoSQL, a las lecturas para las que se diseñó.
- La elección depende de la forma de los datos y de cómo se van a consultar.
- Es habitual usar las dos en la misma aplicación.
