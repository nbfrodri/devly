La **ALU**, unidad aritmético-lógica, es la parte del [procesador](/articulos/como-funciona-un-procesador/) que hace las operaciones: sumas, restas, comparaciones y operaciones lógicas sobre bits. Está construida con [puertas lógicas](/articulos/puertas-logicas/), y casi toda su aritmética se apoya en una sola operación: **sumar**.

## Qué hace

Recibe dos números, en binario, y un código que indica qué operación hacer. Devuelve el resultado y unas cuantas señales sobre él.

| Tipo | Operaciones |
| --- | --- |
| Aritméticas | Sumar, restar, a veces multiplicar |
| Lógicas | AND, OR, XOR, NOT, bit a bit |
| Desplazamientos | Mover los bits a la izquierda o a la derecha |
| Comparaciones | Igual, menor, mayor |

Es un circuito **combinacional**: su salida depende solo de las entradas de ese instante, no guarda nada. Lo que hay que recordar va en los registros, que son [circuitos secuenciales](/articulos/circuitos-secuenciales-y-biestables/).

## Sumar bit a bit

Se suma en binario igual que a mano en decimal: columna a columna, de derecha a izquierda, llevándose una cuando no cabe.

Para una columna hacen falta tres entradas, los dos bits y el acarreo que llega de la anterior, y dos salidas, el bit del resultado y el acarreo que se pasa a la siguiente. Ese circuito es un **sumador completo**: unas pocas puertas XOR, AND y OR.

Encadenando uno por bit, el acarreo de cada uno entra en el siguiente:

```js
function sumadorCompleto(a, b, acarreoEntrada) {
	const suma = a ^ b ^ acarreoEntrada;
	const acarreo = (a & b) | (acarreoEntrada & (a ^ b));

	return { suma, acarreo };
}

function sumar(x, y, bits = 8) {
	let acarreo = 0;
	let resultado = 0;

	for (let i = 0; i < bits; i++) {
		const columna = sumadorCompleto((x >> i) & 1, (y >> i) & 1, acarreo);
		resultado = resultado | (columna.suma << i);
		acarreo = columna.acarreo;
	}

	return { resultado, desbordamiento: acarreo };
}

console.log(sumar(100, 27).resultado); // 127
console.log(sumar(200, 100).resultado); // 44
console.log(sumar(200, 100).desbordamiento); // 1
```

200 + 100 son 300, que no cabe en 8 bits, cuyo máximo es 255. El resultado da la vuelta y queda 44, con un acarreo que sobra por la izquierda. Ese acarreo final avisa del **desbordamiento**.

### El acarreo, un cuello de botella

En este diseño, llamado **sumador de acarreo propagado**, cada columna espera a la anterior. Con 64 bits, el acarreo puede tener que atravesar 64 sumadores uno tras otro.

Los procesadores reales usan **sumadores con anticipación de acarreo**: circuitos adicionales que calculan de antemano, a partir de las entradas, dónde se generará un acarreo. Gastan más puertas y suman mucho más deprisa. Es un ejemplo constante en el diseño de hardware: se cambia espacio por tiempo.

## Restar es sumar

No hace falta un circuito de restar. Con el [complemento a dos](/articulos/complemento-a-dos/), un número negativo se obtiene invirtiendo todos los bits y sumando 1. Restar es sumar el opuesto.

```js
function sumar(x, y) {
	return (x + y) & 255;
}

const opuesto = (x) => sumar(~x & 255, 1);

console.log(opuesto(5)); // 251
console.log(sumar(20, opuesto(5))); // 15
```

En 8 bits, el −5 se escribe como 251. Sumar 20 y 251 da 271, que no cabe; descartando lo que sobra quedan 15, que es 20 − 5.

La misma ALU sirve para las dos operaciones: una señal decide si se invierte el segundo número antes de sumarlo.

## Multiplicar

Multiplicar en binario es más fácil que en decimal, porque cada cifra del multiplicador es 0 o 1: o se suma el multiplicando, o no.

```js
function multiplicar(a, b) {
	let resultado = 0;
	let multiplicando = a;
	let multiplicador = b;

	while (multiplicador > 0) {
		if (multiplicador & 1) {
			resultado = resultado + multiplicando;
		}

		multiplicando = multiplicando << 1;
		multiplicador = multiplicador >> 1;
	}

	return resultado;
}

console.log(multiplicar(13, 11)); // 143
```

Desplazar a la izquierda multiplica por 2, igual que añadir un cero multiplica por 10 en decimal. El algoritmo suma copias desplazadas del multiplicando: **desplazar y sumar**.

Los procesadores actuales tienen circuitos de multiplicación que hacen todas esas sumas en paralelo. Dividir es más costoso, y sigue siendo de las operaciones más lentas.

## Los indicadores

Además del resultado, la ALU anota unas señales sobre él, llamadas **indicadores**:

| Indicador | Se activa cuando |
| --- | --- |
| Cero | El resultado es 0 |
| Negativo | El bit más alto es 1 |
| Acarreo | Sobra un acarreo, en una operación sin signo |
| Desbordamiento | El resultado con signo no cabe |

Son la base de las decisiones. Para comparar dos números, la ALU los **resta** y mira los indicadores: si el resultado es cero, son iguales; si es negativo, el primero es menor. Después, una instrucción de salto condicional consulta esos indicadores. Así se implementa un [condicional](/articulos/condicionales/).

## Operaciones lógicas y desplazamientos

Las operaciones lógicas se aplican a cada pareja de bits por separado, sin acarreos: son las más rápidas.

Se usan para manejar bits sueltos dentro de un número:

- **AND con una máscara** extrae unos bits concretos.
- **OR** activa bits.
- **XOR** los invierte.

Los [permisos de archivos](/articulos/permisos-y-usuarios/) de Unix se guardan como bits y se comprueban así.

## Lo que esto explica en el software

- **Los enteros tienen límite.** Un entero de 32 bits que supera su máximo da la vuelta y se vuelve negativo, sin error en muchos lenguajes. Ha causado fallos en programas y en cohetes.
- **Multiplicar y dividir por potencias de 2 es barato**, y los compiladores lo convierten en desplazamientos.
- **Los decimales van aparte.** Las operaciones con [coma flotante](/articulos/coma-flotante/) usan otra unidad, con circuitos específicos.

## Lo esencial

- La ALU es el circuito del procesador que hace las operaciones aritméticas y lógicas.
- Suma columna a columna con sumadores completos encadenados.
- Resta sumando el complemento a dos, y multiplica desplazando y sumando.
- Anota indicadores sobre el resultado, que se usan para comparar y decidir.
- Los números tienen un tamaño fijo, y desbordarlo da resultados incorrectos.
