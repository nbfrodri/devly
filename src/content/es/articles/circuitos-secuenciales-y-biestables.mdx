Un circuito **secuencial** conserva un estado: su comportamiento depende de las entradas y de lo que haya guardado. Un **biestable** tiene dos estados estables que permiten representar un bit. En los circuitos volátiles que veremos, mantenerlo exige alimentación.

Esto permite guardar el resultado de una suma, contar acontecimientos o recordar qué paso debe ejecutar una máquina. Una combinación de [puertas lógicas](/articulos/puertas-logicas/) sin memoria solo calcula a partir de sus entradas, después de su tiempo de propagación.

## Un lazo que mantiene el estado

Dos puertas NOR cruzadas pueden formar un biestable **SR**, también llamado *latch SR*. Tiene entradas S, de *set*, y R, de *reset*, y salidas Q y su complementaria durante el funcionamiento válido.

| S | R | Q después de estabilizarse |
| --- | --- | --- |
| 0 | 0 | Conserva el valor anterior |
| 1 | 0 | 1 |
| 0 | 1 | 0 |
| 1 | 1 | Combinación que debe evitarse |

Si S fuerza Q a 1, la realimentación mantiene ese valor cuando S vuelve a 0. Para borrarlo, activamos R. Este modelo funcional reproduce las tres combinaciones válidas; no calcula tensiones ni tiempos:

```js
function biestable(s, r, anterior) {
	if (![s, r, anterior].every((b) => b === 0 || b === 1)) {
		throw new RangeError("Se requieren bits");
	}
	if (s && r) throw new Error("Combinación SR no permitida");
	if (s) return 1;
	if (r) return 0;
	return anterior;
}

const historia = [];
let q = 0;
for (const [s, r] of [[1, 0], [0, 0], [0, 1], [0, 0]]) {
	q = biestable(s, r, q);
	historia.push(q);
}
console.log(historia.join(" ")); // "1 1 0 0"
```

En el circuito NOR, mantener S = R = 1 fuerza ambas salidas a 0: dejan de ser complementarias. El problema aparece al liberar ambas entradas a la vez, cuando no se garantiza qué estado quedará. El código rechaza esa entrada en vez de inventar una simulación de su comportamiento analógico.

## Latch y flip-flop

No todos los biestables se controlan de la misma manera:

- Un **latch D** permite que la salida siga al dato D mientras su habilitación esté activa; al desactivarla, conserva el dato.
- Un **flip-flop D** captura D en un flanco concreto del reloj y lo conserva entre capturas. Puede diseñarse para flanco de subida o de bajada.

Considera un flip-flop de subida con Q = 0. D cambia a 1 mientras el reloj está bajo: Q continúa en 0. Llega el flanco de subida: captura 1. Si D vuelve a 0 después, Q conserva 1 hasta el siguiente flanco activo. Un latch habilitado habría seguido ese cambio de D.

El dato debe permanecer estable durante ciertos intervalos antes y después del flanco, llamados **setup** y **hold**. La salida también tarda en responder. Violar estas condiciones puede dejar el circuito temporalmente en un estado no válido, denominado **metaestabilidad**; el reloj no elimina por sí solo los problemas físicos.

## Para qué sirve el reloj

En un diseño síncrono, el reloj coordina la captura del estado. Después de un flanco, la lógica calcula los valores siguientes; deben llegar a tiempo para el próximo. El periodo debe cubrir el retardo del registro, el camino combinacional más lento y el tiempo de preparación, además de los márgenes del diseño.

Esto no significa que todo circuito secuencial necesite un reloj común: el SR anterior ya recuerda sin él. Tampoco excluye entradas especiales de borrado que puedan actuar fuera del flanco.

## Registros y contadores

Agrupando ocho flip-flops con el mismo reloj obtenemos un **registro** de ocho bits. En el [procesador](/articulos/como-funciona-un-procesador/), los registros conservan datos para la [ALU](/articulos/la-alu-y-la-aritmetica-binaria/) y direcciones como la del contador de programa.

Si conectamos la entrada de un registro a su valor actual más uno, tenemos un contador. En este ejemplo ideal de tres bits, cada iteración representa una captura válida:

```js
let cuenta = 6;
const valores = [];
for (let flanco = 0; flanco < 4; flanco++) {
	cuenta = (cuenta + 1) % 8;
	valores.push(cuenta);
}
console.log(valores.join(" ")); // "7 0 1 2"
```

El contador pasa de `110` a `111`, después a `000`: al conservar tres bits, ocho vuelve a cero. No es una simulación de la frecuencia ni de las demoras de las puertas.

## Máquinas de estados

Una **[máquina de estados finitos](/articulos/automatas-finitos/)** combina estado almacenado y reglas para elegir el siguiente estado. Sus salidas pueden depender solo del estado, modelo de Moore, o también de las entradas actuales, modelo de Mealy.

Un semáforo de tráfico simplificado recorre tres estados. Supondremos que cada iteración representa una señal externa que indica «ha terminado el tiempo de este color»:

```js
const siguiente = { verde: "amarillo", amarillo: "rojo", rojo: "verde" };
let estado = "verde";
const recorrido = [estado];
for (let i = 0; i < 3; i++) {
	estado = siguiente[estado];
	recorrido.push(estado);
}
console.log(recorrido.join(" ")); // "verde amarillo rojo verde"
```

La salida es el color del estado, por lo que este caso sigue el modelo de Moore. Un controlador real necesita temporización y condiciones adicionales, como cruces y peticiones de peatones. No cambia de color en cada ciclo del reloj rápido del chip.

## Memoria y alimentación

Las celdas de **SRAM**, habituales en cachés, mantienen un estado mediante realimentación mientras reciben alimentación, sin refresco periódico. Son distintas de los flip-flops empleados en nuestro registro.

La memoria principal suele ser **DRAM**: almacena carga que se pierde gradualmente y necesita refresco. Ambas son [RAM](/articulos/memoria-ram-y-almacenamiento/) volátiles; RAM no significa exclusivamente DRAM. La [flash](/articulos/discos-duros-y-ssd/) conserva información sin alimentación mediante otro mecanismo. Ni todas las memorias usan biestables ni todas dependen de un reloj de la misma forma.

## Lo esencial

- Un circuito secuencial conserva estado; un biestable puede guardar un bit.
- La realimentación mantiene el SR cuando sus entradas vuelven al reposo válido.
- Un latch sigue el dato mientras está habilitado; un flip-flop lo captura en un flanco.
- Registros y lógica de transición permiten construir contadores y máquinas de estados.
