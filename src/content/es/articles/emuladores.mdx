Un **emulador** reproduce por software el comportamiento de una máquina o de parte de ella. Permite ejecutar programas preparados para ese modelo, incluso cuando el ordenador anfitrión entiende otras instrucciones. La compatibilidad depende de qué comportamientos implemente y con qué fidelidad.

Sirve para ejecutar software antiguo, probar un dispositivo sin tenerlo físicamente o estudiar un programa de otra arquitectura. No basta con cambiar el nombre o el formato de un [binario](/articulos/que-es-un-binario/): alguien debe realizar las operaciones que ese programa espera.

## Qué se reproduce

Hay dos alcances frecuentes:

- **Una máquina completa:** CPU, memoria y dispositivos suficientes para arrancar un sistema invitado. QEMU ofrece este modo; MAME documenta y reproduce máquinas históricas.
- **Un proceso de usuario:** sus instrucciones y su interacción con el sistema. QEMU puede ejecutar un programa Linux de otra arquitectura traduciendo sus llamadas al sistema al anfitrión, sin arrancar otro núcleo completo.

Emular no exige una arquitectura diferente. También puede interesar reproducir un dispositivo antiguo o una característica ausente en el equipo actual.

## Un procesador pequeño, definido por completo

Nuestro modelo tiene un **acumulador** `a` de ocho bits, que empieza en cero, y un **contador de programa** `pc`, que indica la posición de la siguiente instrucción. El programa es un array de bytes, enteros del 0 al 255. Sus instrucciones son:

| Código | Nombre | Longitud | Efecto |
| --- | --- | --- | --- |
| `01` | CARGAR | 2 bytes | Copiar el byte siguiente en `a` |
| `02` | SUMAR | 2 bytes | Sumar el byte siguiente y conservar ocho bits |
| `ff` | PARAR | 1 byte | Terminar y devolver `a` |

Los códigos están en hexadecimal. La suma vuelve a cero tras 255: `250 + 10` deja `4`, porque 260 módulo 256 es 4. Este modelo no tiene saltos, dispositivos ni otras instrucciones; exige encontrar PARAR antes del final. Los bytes posteriores a PARAR no se ejecutan.

```js
function ejecutar(programa) {
	if (!Array.isArray(programa) || !Array.from(programa).every(
		(b) => Number.isInteger(b) && b >= 0 && b <= 255,
	)) throw new TypeError("El programa debe contener bytes");

	let a = 0;
	let pc = 0;
	while (pc < programa.length) {
		const codigo = programa[pc];
		if (codigo === 0xff) return a;
		if (codigo !== 0x01 && codigo !== 0x02) {
			throw new Error(`Instrucción desconocida en ${pc}`);
		}
		if (pc + 1 >= programa.length) {
			throw new Error(`Falta el operando en ${pc}`);
		}
		const valor = programa[pc + 1];
		a = codigo === 0x01 ? valor : (a + valor) % 256;
		pc += 2;
	}
	throw new Error("El programa terminó sin PARAR");
}

console.log(ejecutar([0x01, 5, 0x02, 7, 0x02, 30, 0xff])); // 42
console.log(ejecutar([0x01, 250, 0x02, 10, 0xff])); // 4
```

El primer programa recorre estos estados:

| `pc` antes | Instrucción | `a` antes | `a` después | Continuación |
| --- | --- | --- | --- | --- |
| 0 | CARGAR 5 | 0 | 5 | `pc = 2` |
| 2 | SUMAR 7 | 5 | 12 | `pc = 4` |
| 4 | SUMAR 30 | 12 | 42 | `pc = 6` |
| 6 | PARAR | 42 | 42 | Devolver 42 |

El emulador **lee**, **decodifica** y **ejecuta** cada instrucción actualizando el estado simulado. CARGAR ocupa dos bytes: su operando no es otra instrucción. `[0x01]` falla por falta de operando; `[0x01, 5]` carga el cinco, pero falla después porque falta PARAR. Detectar ambos casos evita producir un resultado que nuestra máquina no define.

## Traducir bloques para reutilizar el trabajo

El bucle anterior interpreta cada operación. Un **traductor binario dinámico** convierte bloques de instrucciones invitadas en instrucciones del anfitrión y conserva el resultado para reutilizarlo. QEMU utiliza TCG para esa tarea.

La traducción debe respetar el estado visible: tamaños de registros, efectos en memoria y excepciones. Si el programa modifica su código o cambia un estado relevante, puede ser necesario invalidar una traducción. El coste depende de la carga y de cuánto trabajo pueda reutilizarse; no existe un número fijo de instrucciones anfitrionas por instrucción invitada.

## Relación con la virtualización

La [virtualización](/articulos/virtualizacion/) presenta recursos virtuales y controla su uso. Cuando las instrucciones son compatibles, puede ejecutar gran parte del código directamente en la CPU con asistencia del hardware. La emulación reproduce operaciones mediante software. Una misma herramienta puede combinar ambas.

| Caso | Qué hace falta |
| --- | --- |
| Programa AArch64 en CPU x86-64 | Traducir o interpretar instrucciones y proporcionar interfaces compatibles |
| Sistema invitado compatible con la CPU | Puede usar virtualización asistida; sus dispositivos aún pueden ser emulados |
| Aplicación Android sin teléfono físico | Un entorno que modele los componentes necesarios; la aceleración depende del equipo y de la imagen |

El nombre «emulador» de un producto no dice qué parte utiliza ejecución directa. Tampoco permite comparar velocidades sin fijar equipo, programa y grado de fidelidad.

## Los límites de reproducir una máquina

Un programa puede depender de instrucciones documentadas, peculiaridades de un dispositivo o de cuándo ocurre cada evento. Un emulador funcional puede producir el resultado aritmético correcto y fallar si un juego espera una interrupción en un momento preciso. Reproducir esos tiempos requiere un modelo adicional; no todos los emuladores lo ofrecen.

También hacen falta datos y componentes compatibles, como firmware o imágenes del sistema cuando el modelo los necesita. Conocer el hardware mediante [ingeniería inversa](/articulos/ingenieria-inversa/) ayuda a implementar sus comportamientos, pero disponer del emulador no concede derechos sobre cualquier programa que pueda ejecutar.

## Errores comunes

- **Confundir traducir instrucciones con disponer del entorno.** Un programa también puede necesitar bibliotecas, llamadas al sistema y dispositivos concretos.
- **Llamar fiel a cualquier resultado parecido.** Compatibilidad funcional y temporización exacta son objetivos diferentes.
- **Usar el tipo numérico del anfitrión sin definir el invitado.** La suma del modelo debe limitarse a ocho bits aunque JavaScript pueda representar 260.

## Lo esencial

- Emular es reproducir comportamientos; el alcance puede ser una máquina o un proceso.
- El modelo debe definir instrucciones, estado, tamaños y situaciones inválidas.
- Interpretar y traducir bloques son técnicas distintas para realizar esas operaciones.
- Compatibilidad, fidelidad y rendimiento dependen de la implementación y de la carga.
