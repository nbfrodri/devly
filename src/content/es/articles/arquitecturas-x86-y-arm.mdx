**x86** y **Arm** son familias de arquitecturas con instrucciones y codificaciones diferentes. Un [programa compilado](/articulos/compilador-e-interprete/) para una no se ejecuta directamente como código nativo de la otra. Puede haber una versión recompilada o una capa que traduzca sus instrucciones.

Aquí comparamos **x86-64**, también llamada AMD64, con **AArch64**, el estado de ejecución de 64 bits de Arm que utiliza las instrucciones **A64**. Precisar las variantes evita atribuir sus propiedades a toda la historia de ambas familias.

## El contrato y su implementación

La **arquitectura del conjunto de instrucciones**, o **ISA**, define las operaciones que entiende un [procesador](/articulos/como-funciona-un-procesador/), sus registros y la forma de codificarlas. Los registros son pequeños espacios de trabajo dentro de la CPU.

La **microarquitectura** es cómo un diseño concreto cumple ese contrato: sus unidades de ejecución, [cachés](/articulos/memoria-cache-del-procesador/) o [segmentación](/articulos/segmentacion-del-procesador/). Dos chips pueden entender las mismas instrucciones y tardar tiempos distintos en ejecutarlas.

La compatibilidad de un programa exige más que compartir ISA. También cuentan las extensiones utilizadas, el sistema operativo, las bibliotecas y la **[ABI](/articulos/que-es-una-abi/)**: reglas como dónde se pasan los argumentos de una función y dónde se devuelve el resultado.

## La misma suma en las dos arquitecturas

Queremos que una función reciba `7` y `5` y devuelva `12`. Este programa C permite comprobar el resultado:

```c
#include <stdio.h>

int sumar(int a, int b) {
	return a + b;
}

int main(void) {
	printf("%d\n", sumar(7, 5));
	return 0;
}
```

Guardado como `suma.c`, se compila con `gcc -O2 suma.c -o suma` en un entorno Linux con GCC. Al ejecutar `./suma`, imprime `12`. Aquí los operandos caben en `int`; el ejemplo no define qué hacer si una suma con signo desborda.

La tabla muestra una posible traducción de la función `sumar`, no del programa entero. Usa la ABI System V para x86-64 y AAPCS64 para AArch64. Los nombres de instrucciones son **ensamblador**, una escritura legible del código máquina.

| Paso | x86-64, sintaxis Intel | AArch64 |
| --- | --- | --- |
| Argumentos al entrar | `edi = 7`, `esi = 5` | `w0 = 7`, `w1 = 5` |
| Calcular | `lea eax, [rdi + rsi]` | `add w0, w0, w1` |
| Resultado | `eax = 12` | `w0 = 12` |
| Volver a quien llamó | `ret` | `ret` |

### En x86-64

`lea` calcula la suma indicada entre corchetes y deja sus 32 bits inferiores en `eax`. Aunque su escritura recuerda a una dirección de memoria, **no lee esa memoria**. Para esta operación el compilador puede aprovecharla como suma. Otra traducción válida podría usar `mov` y `add`.

### En AArch64

`add` suma los registros `w0` y `w1` y escribe en `w0`. Los nombres que empiezan por `w` acceden a 32 bits de los registros generales. Al volver, quien llamó encuentra ahí el resultado según la convención acordada.

Las dos versiones producen `12`, pero cambian registros, codificación y convención de llamada. Incluso `ret`, escrito igual, tiene una codificación y un mecanismo de retorno propios de cada ISA. El compilador también puede calcular una llamada con constantes de antemano; la tabla estudia la función cuando recibe argumentos durante la ejecución.

## CISC y RISC: qué explican y qué no

**CISC** alude a conjuntos de instrucciones complejos; **RISC**, a un enfoque de instrucciones regulares y operaciones aritméticas sobre registros. Son familias de decisiones de diseño, no medidas de velocidad.

| Criterio | x86-64 | A64 |
| --- | --- | --- |
| Longitud de instrucción | Variable, hasta 15 bytes | 4 bytes |
| Suma del ejemplo | Puede aprovechar `lea` | Usa `add` entre registros |
| Datos en memoria | Diversas instrucciones admiten un operando en memoria | La aritmética ordinaria trabaja con registros; cargas y almacenes trasladan datos |
| Compatibilidad | Depende del modo y las extensiones disponibles | Depende de la versión y las extensiones disponibles |
| Rendimiento y consumo | Dependen del chip y del trabajo | Dependen del chip y del trabajo |

La longitud fija facilita localizar los límites de las instrucciones A64. No implica que todas tarden lo mismo ni que existan pocas: ambas familias incluyen operaciones vectoriales y otras extensiones. La regla de cuatro bytes es de A64, no de cualquier instrucción Arm; otras variantes usan otras codificaciones.

Muchos procesadores x86 traducen instrucciones a **microoperaciones** internas. Eso describe su implementación; no convierte su ISA en otra ni permite ejecutar directamente un binario Arm. Tampoco es cierto que cada instrucción se convierta siempre en varias microoperaciones.

## Cuál conviene y cómo distribuir un programa

Si necesitas una aplicación o un controlador concreto, comprueba sus destinos admitidos. Para elegir hardware por rendimiento o autonomía, mide una carga representativa y considera memoria, refrigeración y consumo del sistema completo. La etiqueta x86 o Arm no decide el resultado.

Para distribuir software hay varias opciones:

- **Compilar por destino.** Generar versiones compatibles con cada arquitectura y sistema. Si el destino difiere del equipo donde compilas, se habla de **compilación cruzada**.
- **Distribuir fuente o bytecode.** Necesita un intérprete o entorno compatible. Las extensiones nativas y dependencias del sistema siguen importando.
- **Usar emulación o traducción.** Una capa reproduce instrucciones de otro destino. Windows en Arm, por ejemplo, permite ejecutar muchas aplicaciones x86 y x64. La cobertura y el coste dependen de la capa y de la aplicación; no cubre automáticamente cualquier controlador.

Una imagen de [Docker](/articulos/que-es-docker/) con binarios nativos tiene un destino concreto. Una publicación **multiplataforma** puede agrupar variantes para que se seleccione la adecuada. También puede utilizarse emulación cuando el entorno la proporciona; un contenedor por sí solo no traduce instrucciones.

## Dónde encaja RISC-V

**RISC-V** es otra ISA, con una base y extensiones. Su especificación abierta permite implementarla sin pagar regalías por esa ISA. Eso no hace gratuitos todos los diseños de núcleos, herramientas ni servicios de fabricación. Puede haber implementaciones abiertas o propietarias.

También difiere técnicamente de x86 y Arm: tiene sus instrucciones, registros y codificaciones. Compartir el enfoque RISC no permite intercambiar sus ejecutables sin traducción o recompilación.

## Confusiones frecuentes

- **«64 bits significa compatible».** Describe aspectos de la arquitectura, no una ISA, ABI o sistema operativo comunes.
- **«Un programa antiguo funcionará siempre».** Puede necesitar modos, bibliotecas o interfaces que el entorno ya no ofrece.
- **«Menos instrucciones significa menos tiempo».** Importan el coste de cada operación, las dependencias, la memoria y la ejecución interna.

## Lo esencial

- La ISA define instrucciones; la microarquitectura decide cómo se ejecutan.
- El mismo cálculo puede compilarse para x86-64 y AArch64 con instrucciones distintas.
- Un ejecutable necesita instrucciones, ABI y entorno compatibles, o una traducción adecuada.
- Rendimiento y consumo se comparan con programas y equipos concretos.
