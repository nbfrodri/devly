El **teorema de Bayes** es la regla para **actualizar una probabilidad cuando se recibe información nueva**. Parte de lo que se creía antes, la probabilidad **previa**, y la corrige con lo que dicen los datos para obtener la probabilidad **posterior**.

```
P(A | B) = P(B | A) × P(A) / P(B)
```

Se lee: la probabilidad de A sabiendo que ha ocurrido B es igual a la probabilidad de B si A es cierto, por la probabilidad previa de A, dividido por la probabilidad total de B. Se requiere `P(B) > 0`. Lo explica la notación de [probabilidad básica](/articulos/probabilidad-basica/).

## El ejemplo clásico: un test médico

En este modelo hipotético, se elige al azar a una persona de una población donde el 1 % tiene una enfermedad. Se conocen estas propiedades de la prueba en esa población:

- Si tienes la enfermedad, da positivo el 99 % de las veces (**sensibilidad**).
- Si no la tienes, da negativo el 95 % de las veces (**especificidad**). Es decir, un 5 % de **falsos positivos**.

La persona da positivo. El 99 % describe `P(positivo | enfermedad)`, pero buscamos `P(enfermedad | positivo)`. Bayes permite pasar de una a otra:

```js
const prevalencia = 0.01;
const sensibilidad = 0.99;
const especificidad = 0.95;

const verdaderosPositivos = sensibilidad * prevalencia;
const falsosPositivos = (1 - especificidad) * (1 - prevalencia);

const probabilidad = verdaderosPositivos / (verdaderosPositivos + falsosPositivos);
console.log((probabilidad * 100).toFixed(1)); // "16.7"
```

Solo un **16,7 %**. La explicación se ve mejor con personas que con fórmulas. De cada 10 000 personas:

| | Enfermas (100) | Sanas (9900) |
| --- | --- | --- |
| Dan positivo | 99 | 495 |
| Dan negativo | 1 | 9405 |

Hay 594 positivos, y solo 99 son de personas enfermas. Como la enfermedad es rara, los falsos positivos de la enorme mayoría sana superan a los verdaderos positivos. Es el **error de la tasa base**: olvidar lo rara que era la situación de partida.

## Previa, verosimilitud y posterior

| Pieza | En el ejemplo |
| --- | --- |
| Probabilidad previa | 1 %: lo que se sabía antes de la prueba |
| Verosimilitud | 99 %: lo probable que es el resultado si la hipótesis es cierta |
| Probabilidad posterior | 16,7 %: lo que se sabe después |

### Qué pasa con una segunda prueba

Se puede **encadenar** la actualización, pero la evidencia nueva debe modelarse condicionada a lo que ya se sabe. Solo podemos reutilizar sensibilidad y especificidad sin cambiarlas si las dos pruebas son independientes **dado que hay enfermedad**, y también **dado que no la hay**. No es lo mismo que suponer independencia sin condiciones.

Con esos supuestos adicionales, este programa independiente calcula ambas actualizaciones:

```js
function actualizar(previa, sensibilidad, especificidad) {
	const positivosConEnfermedad = previa * sensibilidad;
	const positivosSinEnfermedad = (1 - previa) * (1 - especificidad);
	return positivosConEnfermedad / (positivosConEnfermedad + positivosSinEnfermedad);
}

const primera = actualizar(0.01, 0.99, 0.95);
const segunda = actualizar(primera, 0.99, 0.95);
console.log((primera * 100).toFixed(1)); // "16.7"
console.log((segunda * 100).toFixed(1)); // "79.8"
```

Copiar dos veces el mismo resultado no aporta evidencia nueva. Tampoco basta que haya dos aparatos si comparten una causa de falsos positivos: en ese caso hace falta modelar su dependencia.

## Dónde aparece en informática

- **Filtros de spam**: estiman la probabilidad de que un correo sea spam a partir de las palabras que contiene. Es el clasificador **bayesiano ingenuo**, un modelo clásico de [aprendizaje automático](/articulos/que-es-el-aprendizaje-automatico/).
- **Evaluación de modelos**: la [precisión](/articulos/como-se-evalua-un-modelo-de-clasificacion/) de un clasificador depende de lo frecuente que sea la clase que busca, por la misma razón que el test médico.
- **Pruebas A/B** con enfoque bayesiano, como explica [pruebas A/B](/articulos/pruebas-a-b/).
- **Seguridad**: un sistema de detección de intrusos con pocos falsos positivos puede seguir generando casi solo falsas alarmas si los ataques son raros.

## Errores comunes

- **Confundir sensibilidad con probabilidad posterior.** Sus denominadores son distintos: casos con enfermedad frente a todos los positivos.
- **Usar una tasa base de otra población sin justificarla.** La probabilidad previa del grupo estudiado cambia el resultado.
- **Contar dos veces evidencia dependiente.** Puede inflar la confianza sin añadir información equivalente a una observación independiente.

## Lo esencial

- El teorema de Bayes actualiza una probabilidad previa con la evidencia para obtener la posterior.
- Con una situación rara, los falsos positivos pueden superar a los verdaderos; depende también de sensibilidad y especificidad.
- Ese error de olvidar la frecuencia de partida se llama error de la tasa base.
- Es la base de los filtros de spam bayesianos y explica el comportamiento de muchos clasificadores.
