**Cifrar** transforma un mensaje legible en datos protegidos mediante una clave. El **cifrado simétrico** usa un secreto compartido para cifrar y descifrar; el **asimétrico** permite cifrar con una clave pública y descifrar con la privada correspondiente, mediante un esquema diseñado para ello.

La criptografía asimétrica también incluye firmas y acuerdos de claves. No son una misma operación ejecutada en sentidos intercambiables.

## El mismo mensaje, dos formas de protegerlo

Luis quiere enviar a Ana «llego a las ocho». Ese es el **texto en claro**. El resultado de cifrarlo es el **texto cifrado**. Una **clave** es un dato que controla la operación: algunas deben ser secretas y otras son públicas.

El **algoritmo** es el procedimiento. Su publicación permite examinarlo, pero no demuestra por sí sola que sea seguro. También importan su análisis, la implementación y el uso correcto de claves y parámetros.

## Simétrico: compartir un secreto

Luis y Ana poseen una clave secreta `K`. Luis cifra el mensaje con `K`; Ana utiliza `K` para descifrarlo. Quien obtenga ese secreto puede comprometer la protección de los datos que dependan de él.

El cifrado César permite ver la transformación con un ejemplo de juguete: desplaza letras del alfabeto. Este código acepta solo letras minúsculas de `a` a `z` y desplazamientos enteros; no maneja espacios, tildes ni otros símbolos.

```js
function desplazar(texto, clave) {
	const desplazamiento = ((clave % 26) + 26) % 26;
	let resultado = "";

	for (const letra of texto) {
		const codigo = letra.charCodeAt(0) - 97;
		const nuevo = (codigo + desplazamiento) % 26;
		resultado += String.fromCharCode(nuevo + 97);
	}

	return resultado;
}

const cifrado = desplazar("hola", 3);
console.log(cifrado); // "krod"
console.log(desplazar(cifrado, -3)); // "hola"
```

Ambos participantes conocen el desplazamiento; para volver se aplica su inverso. Solo hay 26 desplazamientos posibles: se pueden probar todos. **El ejemplo no protege información** y no representa la seguridad de los cifrados modernos.

**AES** es un estándar de cifrado simétrico. Permite procesar grandes cantidades de datos con un coste generalmente menor que usar operaciones asimétricas sobre esos datos. Se emplea dentro de modos y protocolos: elegir «AES» no resuelve por sí solo la integridad, la generación de claves ni su almacenamiento.

La dificultad inicial del caso es compartir `K`. Enviarla en claro por el canal que un atacante puede observar permitiría a ese atacante descifrar el mensaje.

## Asimétrico: publicar una clave, conservar otra

Ana genera un par de claves relacionadas. Comparte la **pública** y protege la **privada**. En un esquema de cifrado como **RSA-OAEP**, Luis utiliza la pública de Ana para cifrar; Ana usa su privada para recuperar el mensaje.

Luis no necesita conocer la privada. La seguridad busca que deducirla a partir de la pública resulte computacionalmente inviable con parámetros adecuados, no que ambos datos carezcan de relación.

Pero Luis sí necesita comprobar que la pública pertenece a Ana. Si un atacante la sustituye por la suya, Luis cifrará para él. La clave pública no requiere secreto, pero su autenticidad importa. Un canal previamente verificado o un [certificado](/articulos/que-es-un-certificado-digital/) puede ayudar a establecer esa relación.

## Comparar las dos opciones

| Criterio | Simétrico | Asimétrico para cifrar |
| --- | --- | --- |
| Secreto necesario en nuestro caso | Luis y Ana comparten `K` | Ana conserva su privada |
| Información distribuible | La clave debe protegerse | La pública puede distribuirse, comprobando su identidad |
| Grandes volúmenes | Uso habitual para proteger los datos | Mayor coste y límites de tamaño según el esquema |
| Problema previo | Establecer un secreto común | Autenticar la pública y proteger la privada |

No son niveles de calidad. Se eligen para resolver necesidades diferentes y suelen combinarse.

## Firmar no es cifrar al revés

Una **firma digital** se genera con una clave privada y se verifica con la pública correspondiente. El verificador comprueba el mensaje y la firma; no «descifra con la pública» un texto secreto. Esquemas como RSA-PSS y ECDSA especifican sus propias operaciones.

Si Luis firma «llego a las ocho», Ana puede verificar la firma usando la pública autenticada de Luis. Cambiar «ocho» por «nueve» hará fallar la comprobación. Pero la firma no oculta la hora: confidencialidad e integridad son propiedades diferentes. Asociar la clave con Luis sigue siendo necesario para atribuirle la firma.

## Cómo se combinan en una conexión

Un **acuerdo de claves** permite obtener secretos compartidos a partir de aportaciones de ambos participantes. ECDH es un ejemplo basado en curvas elípticas; no es un algoritmo que cifre directamente cualquier mensaje.

En una conexión [TLS 1.3](/articulos/https-y-tls/) con certificados y acuerdo efímero, las partes establecen secretos, autentican el intercambio y derivan claves simétricas para proteger el tráfico. TLS también contempla modalidades con secretos previamente compartidos: no toda conexión repite el mismo intercambio.

El [recorrido de un mensaje de WhatsApp](/articulos/como-funciona-whatsapp/) muestra otra combinación de estas herramientas. En sistemas reales se usan protocolos y bibliotecas revisados; sustituirlos por una transformación casera como César perdería sus garantías.

## Lo esencial

- El cifrado simétrico protege datos mediante un secreto compartido.
- El asimétrico para cifrar distingue pública y privada; autenticar la pública es imprescindible.
- Cifrar, firmar y acordar claves son operaciones distintas.
- Los protocolos combinan mecanismos y deben proteger también integridad, claves e implementación.
