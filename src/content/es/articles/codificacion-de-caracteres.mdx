Una **codificación de caracteres** es un acuerdo sobre cómo convertir letras, cifras y símbolos en los números que un ordenador puede guardar, y cómo hacer el camino de vuelta.

## Qué problema resuelve

Un ordenador solo guarda [bits](/articulos/que-es-un-bit/), es decir, números. Para guardar un texto hay que decidir qué número corresponde a cada carácter.

Esa decisión tiene que ser compartida. Si quien escribe el texto usa una tabla y quien lo lee usa otra, los números son los mismos pero el resultado es otro. Es el origen de textos como "aÃ±o" donde debería poner "año".

## ASCII

Una de las primeras tablas que se extendieron fue **ASCII**. Asigna un número del 0 al 127 a cada carácter, lo que cabe en 7 bits.

```js
console.log("A".charCodeAt(0)); // 65
console.log("a".charCodeAt(0)); // 97
console.log(String.fromCharCode(66)); // "B"
```

ASCII cubre las letras del inglés, las cifras y algunos signos. No tiene la `ñ`, ni vocales con tilde, ni ningún alfabeto que no sea el latino básico.

## Demasiadas tablas

Para cubrir otros idiomas aparecieron decenas de tablas distintas, cada una pensada para una región. El mismo número significaba una letra en una tabla y otra en la de al lado.

Un archivo solo se leía bien si se sabía con qué tabla se había escrito, y mezclar texto de varias tablas exigía indicar cómo interpretar cada parte o utilizar otra codificación.

## Unicode

**Unicode** proporciona un repertorio común de caracteres y reglas para procesar texto. Sus posiciones se llaman **puntos de código** y se escriben con `U+` seguido de un número hexadecimal. Un carácter percibido por una persona puede corresponder a uno o a varios puntos de código.

| Carácter | Punto de código | En decimal |
| --- | --- | --- |
| A | U+0041 | 65 |
| ñ | U+00F1 | 241 |
| € | U+20AC | 8364 |

Los primeros 128 puntos de código coinciden con ASCII. El espacio de códigos de Unicode tiene más de un millón de posiciones, no todas asignadas a caracteres: alfabetos, ideogramas, símbolos matemáticos y [emojis](/articulos/de-donde-salen-los-emojis/).

```js
console.log("ñ".codePointAt(0)); // 241
console.log("€".codePointAt(0)); // 8364
```

## Del punto de código a los bytes

El punto de código identifica una posición del repertorio; una **codificación** define cómo representarla. El propio estándar Unicode define formas como UTF-8, UTF-16 y UTF-32. No son alfabetos distintos: codifican el mismo repertorio con unidades diferentes. UTF-32 usa cuatro bytes por valor escalar; UTF-8 necesita solo uno para las letras ASCII.

### UTF-8

**UTF-8** es la codificación más usada en la web. Emplea entre uno y cuatro bytes por **valor escalar Unicode**: un punto de código válido para texto, excluyendo las posiciones reservadas para sustitutos de UTF-16. Estos son ejemplos, no una clasificación completa por idioma:

| Caracteres | Bytes |
| --- | --- |
| Los de ASCII | 1 |
| `ñ` (U+00F1), `é` (U+00E9) | 2 |
| `€` (U+20AC), `中` (U+4E2D) | 3 |
| `😀` (U+1F600) | 4 |

```js
const codificador = new TextEncoder();

console.log(codificador.encode("a").length); // 1
console.log(codificador.encode("ñ").length); // 2
console.log(codificador.encode("€").length); // 3
console.log(codificador.encode("😀").length); // 4
```

UTF-8 tiene una propiedad decisiva: un texto que solo usa caracteres ASCII se escribe exactamente igual en ASCII que en UTF-8. Esa compatibilidad facilita reutilizar datos ASCII; no garantiza que cualquier programa antiguo pueda procesar correctamente texto no ASCII.

## Cuando la codificación no coincide

La `ñ` se guarda en UTF-8 como dos bytes, 195 y 177. Si un programa interpreta esos bytes como Windows-1252 o ISO-8859-1, muestra dos símbolos: `Ã±`. El recorrido se puede comprobar:

```js
const bytes = new TextEncoder().encode("ñ");
console.log([...bytes].map((b) => b.toString(16)).join(" ")); // "c3 b1"
console.log(new TextDecoder("utf-8").decode(bytes)); // "ñ"
console.log(new TextDecoder("windows-1252").decode(bytes)); // "Ã±"
```

En este ejemplo los bytes originales siguen intactos; lo equivocado es la decodificación. Si después se guarda el texto mal interpretado, también puede cambiar el archivo. Por eso una página web declara su codificación en el [HTML](/articulos/que-es-html/) con `<meta charset="utf-8">`.

## Carácter no es lo mismo que byte

De todo lo anterior sale una consecuencia práctica: la longitud de un texto depende de qué se cuente.

```js
console.log("año".length); // 3
console.log(new TextEncoder().encode("año").length); // 4
console.log("😀".length); // 2
```

El último resultado sorprende. JavaScript define sus cadenas como secuencias de unidades UTF-16: ese emoji ocupa dos, y `length` cuenta unidades, no caracteres percibidos. Es la representación observable del lenguaje; el motor puede optimizar su almacenamiento interno. Hay que tenerlo presente al limitar la longitud de un texto o al cortarlo.

## Un carácter visible puede ser una secuencia

La `ñ` puede escribirse como U+00F1 o como `n` (U+006E) seguida de una tilde combinante (U+0303). La apariencia puede ser la misma aunque sus secuencias difieran:

```js
const compuesta = "ñ";
const descompuesta = "n\u0303";
console.log(compuesta === descompuesta); // false
console.log(descompuesta.length); // 2
console.log(new TextEncoder().encode(descompuesta).length); // 3
console.log(compuesta === descompuesta.normalize("NFC")); // true
```

NFC es una forma de normalización Unicode que unifica ciertas representaciones equivalentes. No traduce texto ni convierte cualquier símbolo visualmente parecido en el mismo carácter. Para contar unidades percibidas se utilizan reglas de segmentación en **grupos de grafemas**, no solo el número de bytes o puntos de código.

## Errores comunes

- **Suponer un byte por letra.** Falla con UTF-8 fuera de ASCII y con secuencias combinadas.
- **Cortar una cadena por cualquier unidad UTF-16.** Puede separar un par sustituto o un grupo de grafemas.
- **Confundir decodificación y normalización.** La primera interpreta bytes; la segunda transforma secuencias Unicode según reglas de equivalencia.

## Lo esencial

- Una codificación convierte caracteres en números y al revés.
- Unicode define un repertorio y reglas; un carácter percibido puede ocupar varios puntos de código.
- UTF-8 usa entre uno y cuatro bytes por valor escalar y conserva los bytes de ASCII.
- Los símbolos extraños aparecen cuando un texto se lee con una codificación distinta de aquella con la que se escribió.
