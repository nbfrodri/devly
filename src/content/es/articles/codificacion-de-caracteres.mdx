Una **codificación de caracteres** es un acuerdo sobre cómo convertir letras, cifras y símbolos en los números que un ordenador puede guardar, y cómo hacer el camino de vuelta.

## Qué problema resuelve

Un ordenador solo guarda [bits](/articulos/que-es-un-bit/), es decir, números. Para guardar un texto hay que decidir qué número corresponde a cada carácter.

Esa decisión tiene que ser compartida. Si quien escribe el texto usa una tabla y quien lo lee usa otra, los números son los mismos pero el resultado es otro. Es el origen de textos como "aÃ±o" donde debería poner "año".

## ASCII

Una de las primeras tablas que se extendieron fue **ASCII**. Asigna un número del 0 al 127 a cada carácter, lo que cabe en 7 bits.

```js
console.log("A".charCodeAt(0)); // 65
console.log("a".charCodeAt(0)); // 97
console.log(String.fromCharCode(66)); // "B"
```

ASCII cubre las letras del inglés, las cifras y algunos signos. No tiene la `ñ`, ni vocales con tilde, ni ningún alfabeto que no sea el latino básico.

## Demasiadas tablas

Para cubrir otros idiomas aparecieron decenas de tablas distintas, cada una pensada para una región. El mismo número significaba una letra en una tabla y otra en la de al lado.

Un archivo solo se leía bien si se sabía con qué tabla se había escrito, y un documento no podía mezclar idiomas de tablas diferentes.

## Unicode

**Unicode** resuelve el problema con una sola tabla para todos los sistemas de escritura. Asigna a cada carácter un número único, su **punto de código**, que se escribe con `U+` seguido del número en hexadecimal.

| Carácter | Punto de código | En decimal |
| --- | --- | --- |
| A | U+0041 | 65 |
| ñ | U+00F1 | 241 |
| € | U+20AC | 8364 |

Los primeros 128 puntos de código coinciden con ASCII. Unicode tiene sitio para más de un millón de caracteres: alfabetos, ideogramas, símbolos matemáticos y emojis.

```js
console.log("ñ".codePointAt(0)); // 241
console.log("€".codePointAt(0)); // 8364
```

## Unicode no dice cómo guardar los números

Unicode asigna números, pero no fija cómo escribirlos en bytes. Eso lo decide una **codificación**. Usar siempre cuatro bytes por carácter sería sencillo, pero un texto en inglés ocuparía el cuádruple de lo necesario.

### UTF-8

**UTF-8** es la codificación más usada en la web. Emplea entre uno y cuatro bytes por carácter, según el punto de código:

| Caracteres | Bytes |
| --- | --- |
| Los de ASCII | 1 |
| Letras con tilde, `ñ`, griego, cirílico | 2 |
| La mayoría de los demás, como `€` o los ideogramas chinos | 3 |
| Emojis y caracteres poco frecuentes | 4 |

```js
const codificador = new TextEncoder();

console.log(codificador.encode("a").length); // 1
console.log(codificador.encode("ñ").length); // 2
console.log(codificador.encode("€").length); // 3
console.log(codificador.encode("😀").length); // 4
```

UTF-8 tiene una propiedad decisiva: un texto que solo usa caracteres ASCII se escribe exactamente igual en ASCII que en UTF-8. Los programas y archivos antiguos siguieron funcionando sin cambios, y eso facilitó que se adoptara en todas partes.

## Cuando la codificación no coincide

La `ñ` se guarda en UTF-8 como dos bytes, 195 y 177. Si un programa lee esos bytes creyendo que cada uno es un carácter de una tabla antigua, muestra dos símbolos: `Ã±`.

Nada se ha estropeado en el archivo. Los bytes son correctos; lo equivocado es la tabla con la que se interpretan. Por eso una página web declara su codificación en el [HTML](/articulos/que-es-html/) con `<meta charset="utf-8">`.

## Carácter no es lo mismo que byte

De todo lo anterior sale una consecuencia práctica: la longitud de un texto depende de qué se cuente.

```js
console.log("año".length); // 3
console.log(new TextEncoder().encode("año").length); // 4
console.log("😀".length); // 2
```

El último resultado sorprende. JavaScript guarda los textos por dentro con otra codificación, UTF-16, en la que ese emoji ocupa dos unidades, y `length` cuenta unidades, no caracteres. Hay que tenerlo presente al limitar la longitud de un texto o al cortarlo.

## Lo esencial

- Una codificación convierte caracteres en números y al revés.
- Unicode asigna un número único a cada carácter de todos los sistemas de escritura.
- UTF-8 guarda esos números con entre uno y cuatro bytes y es compatible con ASCII.
- Los símbolos extraños aparecen cuando un texto se lee con una codificación distinta de aquella con la que se escribió.
