Un **microprocesador** integra una o varias unidades de [procesamiento](/articulos/como-funciona-un-procesador/) y suele trabajar con memoria y otros componentes externos. Un **microcontrolador** reúne procesamiento, memoria y periféricos para controlar un dispositivo. La diferencia está en la integración y el uso previsto: no en que uno contenga literalmente solo CPU ni en una frontera fija de potencia.

Un ordenador personal suele usar un microprocesador; el control de un electrodoméstico puede resolverse con un microcontrolador. Ambos ejecutan instrucciones.

## Microprocesador

En un ordenador de propósito general, el microprocesador ejecuta aplicaciones con necesidades muy distintas.

- **Puede ofrecer mucha capacidad de cálculo.** Los modelos de ordenadores personales suelen tener varios núcleos y frecuencias de gigahercios; no todos los microprocesadores son así.
- **No funciona solo.** Necesita [memoria RAM](/articulos/memoria-ram-y-almacenamiento/), almacenamiento, y circuitos para comunicarse con pantalla, teclado y red.
- **Suele ejecutar un sistema operativo**, que organiza aplicaciones y recursos. No es un requisito para que el chip sea un microprocesador.
- **Su consumo depende del diseño y de la carga.** Una máquina de altas prestaciones también necesita alimentación y refrigeración acordes.

Está pensado para la flexibilidad: la misma máquina sirve para escribir, jugar o programar.

## Microcontrolador

Está pensado para controlar funciones dentro de un aparato. Normalmente integra:

- Un procesador modesto.
- Una pequeña memoria RAM.
- Memoria no volátil para guardar el programa en muchos modelos. Hay excepciones: el RP2040 usa flash externa.
- **Periféricos**: patillas de entrada y salida, temporizadores, conversores para leer señales analógicas, interfaces de comunicación.

Los recursos varían mucho: algunos tienen kilobytes de RAM; otros, mucha más memoria y varios núcleos. Comparar solo la frecuencia no mide cuántas veces más rápido será un programa.

A cambio:

- **Puede reducir el coste** al integrar componentes que de otro modo ocuparían la placa.
- **Puede gastar poca energía**, especialmente si duerme entre tareas. La autonomía depende también de sensores, radio y batería.
- **Es pequeño** y necesita pocos componentes alrededor.
- **Puede arrancar con un programa pequeño**, sin un sistema operativo general. El arranque sigue teniendo una duración y puede incluir comprobaciones.

Están en casi todo: electrodomésticos, mandos a distancia, coches (que llevan decenas), juguetes, termostatos, relojes.

### El programa de un microcontrolador

Lo habitual es que ejecute un único programa, grabado en su memoria flash, que empieza al recibir corriente y se repite sin fin. Ese programa se llama [**firmware**](/articulos/que-es-el-firmware/). Puede ser un bucle sencillo o incluir un pequeño sistema operativo que organice varias tareas.

Su estructura típica es un bucle: leer los sensores, decidir y actuar.

```js
function decidir(temperatura, objetivo) {
	if (temperatura < objetivo - 1) {
		return "encender calefacción";
	}
	if (temperatura > objetivo + 1) {
		return "apagar calefacción";
	}
	return "no hacer nada";
}

console.log(decidir(18, 21)); // "encender calefacción"
console.log(decidir(23, 21)); // "apagar calefacción"
console.log(decidir(21, 21)); // "no hacer nada"
```

La función es una simulación en JavaScript de la decisión de un termostato: no lee un sensor ni controla una salida real. Con objetivo 21, enciende por debajo de 20, apaga por encima de 22 y mantiene el estado anterior entre ambos límites, incluidos 20 y 22. Esa banda evita conmutar por pequeñas oscilaciones. El aparato debe conservar el estado y establecer uno inicial; la frecuencia de lectura se elige según el sistema, no tiene por qué ser de miles de veces por segundo.

Se relaciona con el mundo físico a través de sus patillas: en unas lee una señal, como la de un sensor de temperatura; en otras escribe una, como la que activa un relé.

## El mismo termostato con las dos opciones

Con un microcontrolador, el programa lee el sensor, compara con el objetivo y ordena una salida. La decisión anterior necesita muy poca memoria. Los periodos de espera permiten dormir y ahorrar energía.

Con un microprocesador y memoria externa se puede ejecutar esa misma decisión, además de una pantalla compleja, historial y otras aplicaciones. Se gana capacidad para esas funciones, a costa de una placa y un software normalmente más complejos. Si solo queremos medir y conmutar con pilas, esos recursos extra pueden no compensar. Si queremos una interfaz rica y muchas aplicaciones, pueden ser necesarios.

En ambos casos hacen falta sensor, alimentación y un circuito adecuado para accionar la carga: la patilla del chip no alimenta por sí sola una calefacción.

## Comparación

| | Microprocesador | Microcontrolador |
| --- | --- | --- |
| Contiene | CPU y otros bloques según el diseño | CPU, memoria y periféricos de control |
| Necesita alrededor | Memoria y circuitos externos según el sistema | Menos componentes para tareas sencillas |
| Recursos | Orientados a cargas más amplias en muchos modelos | Ajustados al dispositivo; varían mucho |
| Memoria | A menudo RAM externa | RAM integrada; programa interno o externo |
| Consumo | Depende del chip y del sistema | Puede aprovechar modos de bajo consumo |
| Software | Con o sin sistema operativo | Bucle de control o tareas con un sistema pequeño |
| Uso | Propósito general | Una tarea concreta |
| Ejemplos | Ordenadores, servidores | Electrodomésticos, sensores, juguetes |

## Tiempo real

Muchos microcontroladores trabajan con plazos estrictos. El sistema que despliega el airbag de un coche debe reaccionar en un tiempo máximo garantizado, siempre.

A eso se le llama **tiempo real**: importa cumplir un plazo, no solo ser rápido de media. En tiempo real estricto, incumplirlo es un fallo; otros usos toleran algún retraso con pérdida de calidad. Usar un microcontrolador no garantiza esos plazos: un bucle que espere indefinidamente a la red también llega tarde. Hay que acotar cálculos, esperas e interrupciones, y comprobar el peor caso. Los [sistemas operativos de tiempo real](/articulos/sistemas-operativos-de-tiempo-real/) ayudan a planificar tareas, pero tampoco hacen viable una carga que excede los recursos. El requisito pertenece al sistema completo, con o sin sistema operativo.

## La frontera se difumina

La distinción es clara en los extremos y borrosa en el medio.

Un **sistema en un chip** (SoC) integra varios bloques de un sistema: CPU, controladores de memoria, gráficos o comunicaciones, según el modelo. Los teléfonos usan SoC y suelen necesitar RAM externa al chip. El término describe integración; no es una categoría situada necesariamente a medio camino entre microprocesador y microcontrolador.

También hay microcontroladores modernos con capacidad suficiente para ejecutar sistemas operativos pequeños y conectarse por wifi.

## Para aprender

Las placas de desarrollo como Arduino montan un microcontrolador con todo lo necesario para programarlo desde un ordenador por USB. Son la forma habitual de empezar con la electrónica programable y con el [**internet de las cosas**](/articulos/internet-de-las-cosas/): objetos que intercambian datos mediante una red.

## Confusiones frecuentes

- **Clasificar el chip solo por su frecuencia.** La memoria, los periféricos y el trabajo requerido también deciden qué encaja.
- **Confundir placa y chip.** Una placa de desarrollo añade alimentación, conectores y otros circuitos al microcontrolador.
- **Suponer que integrar significa no necesitar nada externo.** Sensores, cargas, alimentación y a veces memoria siguen fuera del chip.

## Lo esencial

- Un microcontrolador integra recursos para controlar dispositivos; un microprocesador suele apoyarse más en componentes externos.
- La elección depende de memoria, interfaces, energía y trabajo necesario, no solo de la frecuencia.
- El firmware puede organizarse en un bucle o en varias tareas.
- Un plazo garantizado exige analizar el sistema completo; no lo da el nombre del chip.
