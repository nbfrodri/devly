**FAT** es una familia de [sistemas de archivos](/articulos/sistema-de-archivos/) basada en una tabla de asignación. **NTFS** utiliza otras estructuras y ofrece funciones como control de acceso y recuperación mediante un diario. Compararemos principalmente **FAT32** con NTFS, sin atribuir las mismas capacidades a FAT12, FAT16 o exFAT.

## FAT32: seguir una cadena

El espacio se asigna en **clústeres**, grupos de sectores contiguos. Un archivo puede ocupar varios clústeres separados. El directorio registra su inicio y tamaño; la **tabla de asignación de archivos**, *File Allocation Table*, permite seguir el siguiente clúster de su cadena. Se parece a una [lista enlazada](/articulos/listas-enlazadas/).

Este modelo usa números y la palabra `fin`, no los bytes reales del formato. Rechaza una referencia inexistente o un ciclo, en vez de seguir indefinidamente una tabla dañada:

```js
const tabla = new Map([[2, 3], [3, 7], [7, "fin"]]);

function clusteres(primero, asignacion = tabla) {
	const cadena = [];
	const vistos = new Set();
	let actual = primero;
	while (actual !== "fin") {
		if (!Number.isSafeInteger(actual) || actual < 2 ||
			!asignacion.has(actual) || vistos.has(actual)) {
			throw new Error("Cadena incompleta o repetida");
		}
		vistos.add(actual);
		cadena.push(actual);
		actual = asignacion.get(actual);
	}
	return cadena;
}

console.log(clusteres(2).join(" ")); // "2 3 7"
```

El recorrido visita 2, 3 y 7 y encuentra el final. Si 7 volviera a 3, se detectaría la repetición. Esto valida solo la cadena del modelo: un lector real debe comprobar tamaños, rangos, marcas reservadas y más estructuras. El archivo vacío también tiene reglas propias en el formato real.

FAT32 conserva nombres, fechas, tamaños y atributos. No almacena listas de control de acceso como NTFS; no significa que carezca de cualquier metadato. Un sistema operativo puede imponer restricciones al montar el volumen, pero no está guardando por ello permisos NTFS dentro de FAT32.

## El mismo vídeo en dos formatos

Queremos copiar un vídeo de **5 000 000 000 bytes** a una unidad con 10 000 000 000 bytes libres. Hay espacio total, pero importa también cuánto puede medir un archivo.

FAT32 guarda el tamaño en un campo de 32 bits sin signo. Su máximo es **4 294 967 295 bytes**, exactamente **4 GiB menos un byte**. Un GiB son 2 elevado a 30 bytes; no equivale al GB decimal.

```js
const maximoFat32 = 2 ** 32 - 1;
const pelicula = 5_000_000_000;

console.log(maximoFat32); // 4294967295
console.log(maximoFat32 + 1 === 4 * 2 ** 30); // true
console.log(pelicula <= maximoFat32); // false
```

En FAT32 no cabe ese archivo único, aunque sobre espacio. NTFS admite ese tamaño; la copia puede realizarse si también hay capacidad, soporte de escritura y permisos. Cambiar el formato no elimina esas otras condiciones.

## NTFS: registros y recuperación

NTFS mantiene una **tabla maestra de archivos**, o MFT, con registros y atributos de archivos y directorios. Para datos que no caben en el registro, conserva información que permite localizar sus zonas asignadas. No necesita representar cada archivo como la cadena FAT del ejemplo.

Sus **listas de control de acceso** describen qué identidades pueden realizar operaciones. Eso permite separar el acceso de distintos usuarios de un mismo sistema, como desarrolla [usuarios y permisos](/articulos/permisos-y-usuarios/). El resultado depende también de cómo el sistema que monta el volumen interprete esas identidades y reglas.

NTFS utiliza un **diario de metadatos** para recuperar la coherencia de sus estructuras tras operaciones interrumpidas. No garantiza conservar el último contenido escrito por una aplicación ni sustituye una [copia de seguridad](/articulos/copias-de-seguridad/). La expulsión segura sigue siendo relevante para terminar escrituras pendientes.

Ofrece además compresión y cifrado EFS por archivo. Su disponibilidad y sus combinaciones dependen de la implementación y configuración; no se activan automáticamente por copiar un archivo a NTFS.

## Dónde entra exFAT

**exFAT** es otro formato, orientado al almacenamiento extraíble. Supera el límite por archivo de FAT32, pero conserva límites propios. Su especificación incluye una tabla de asignación y un mapa de clústeres ocupados; no es simplemente FAT32 sin un tope.

El vídeo de 5 000 000 000 bytes también puede caber en exFAT. Para llevarlo a un televisor o una cámara hay que comprobar que ese aparato admite ese formato y el archivo multimedia: son compatibilidades diferentes.

| Criterio | FAT32 | exFAT | NTFS |
| --- | --- | --- | --- |
| El vídeo del ejemplo | Supera el máximo por archivo | Tamaño admisible | Tamaño admisible |
| Diario de metadatos del formato habitual | No | No | Sí |
| Listas de acceso por usuario como las de Windows | No | No | Sí |
| Intercambio entre dispositivos | Amplio, pero no universal | Comprobar soporte de cada destino | Comprobar lectura y escritura de cada destino |
| Caso habitual | Equipos que requieren FAT32 y archivos pequeños | Unidad extraíble con archivos grandes | Volumen de Windows que necesita sus funciones |

## Elegir y evitar confusiones

Para nuestro vídeo, FAT32 queda descartado como archivo único. Entre exFAT y NTFS decide el conjunto de dispositivos y las funciones requeridas. En una unidad de sistema de Windows se deben respetar los requisitos del instalador; una partición de arranque y el volumen de datos no tienen por qué usar el mismo formato.

- **Confundir tamaño del volumen con tamaño de archivo.** Más espacio libre no amplía el campo de tamaño de FAT32.
- **Suponer que leer implica poder escribir.** El soporte puede diferir según controlador, sistema y configuración.
- **Formatear como si fuera convertir sin pérdida.** Crear otro sistema de archivos puede eliminar el acceso al contenido anterior. Preparar una copia y verificarla es una operación distinta; formatear tampoco garantiza borrado seguro.

## Lo esencial

- FAT32 y NTFS organizan datos y metadatos de manera distinta.
- FAT32 admite como máximo 4 GiB menos un byte por archivo.
- NTFS añade funciones cuya aplicación depende del sistema que las utiliza.
- Tamaño, compatibilidad y recuperación se comprueban por separado.
