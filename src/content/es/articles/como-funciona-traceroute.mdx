**Traceroute** envía sondas para observar saltos de una ruta y el tiempo de ida y vuelta de sus respuestas. Utiliza el [TTL](/articulos/ttl-en-ip/) para provocar que los paquetes expiren progresivamente más lejos. En Windows existe `tracert`; en Linux, `tracepath` también explora el recorrido y puede informar de su MTU. Sus sondas y opciones no son idénticas.

```bash
traceroute example.com
```

El comando es para un sistema que tenga `traceroute` instalado. Las direcciones y tiempos de los ejemplos siguientes son inventados; una ejecución real puede mostrar otros saltos o no recibir respuestas.

## El truco: paquetes que caducan

En IPv4, cada router reduce el **TTL** al reenviar, normalmente en uno; IPv6 utiliza **Hop Limit**. Si se agota, el paquete se descarta y puede regresar un mensaje de control **ICMP de tiempo excedido**. Es un límite contra bucles, como explica [enrutamiento](/articulos/enrutamiento/).

Traceroute aprovecha esa regla:

1. Envía una sonda con **TTL 1**. Si el primer router responde al descartarla, conocemos una dirección desde la que ha respondido y cuánto tardó el intercambio completo.
2. Envía otro con **TTL 2**. Lo descarta el segundo router.
3. Continúa aumentando el límite hasta recibir la respuesta esperada del destino o alcanzar un límite de intentos o saltos. La señal de llegada depende del tipo de sonda: UDP, ICMP o TCP, por ejemplo.

```js
const camino = ["192.168.1.1", "198.51.100.1", "192.0.2.1", "203.0.113.10"];

function enviar(ttl) {
	for (let salto = 0; salto < camino.length; salto++) {
		if (salto === camino.length - 1) return `${camino[salto]} (destino)`;
		ttl--;
		if (ttl === 0) return `${camino[salto]} (tiempo excedido)`;
	}
}

for (let ttl = 1; ttl <= 4; ttl++) console.log(ttl, enviar(ttl));
// 1 192.168.1.1 (tiempo excedido)
// 2 198.51.100.1 (tiempo excedido)
// 3 192.0.2.1 (tiempo excedido)
// 4 203.0.113.10 (destino)
```

Esta simulación acepta TTL enteros positivos y supone un camino fijo, sin pérdidas ni filtros: todos los routers responden. Una red real no cumple necesariamente esas condiciones. No necesita que cada router ejecute traceroute: aprovecha respuestas del protocolo, aunque un equipo sí puede reconocer o filtrar esas sondas.

## Cómo leer el resultado

- **Cada línea es un salto**, con el tiempo de ida y vuelta hasta ese router. Normalmente se envían tres paquetes por salto.
- **Asteriscos** (`* * *`): no llegó la respuesta esperada dentro del plazo. Puede haber filtrado, limitación, pérdida o un problema real; el símbolo no permite decidir cuál.
- **Un tiempo alto**: incluye ida, procesamiento de la respuesta y vuelta. No mide solo el cable inmediatamente anterior.
- **El camino de vuelta puede ser otro**: el enrutamiento no tiene por qué ser simétrico. Además, distintas sondas pueden seguir rutas diferentes.

Por ejemplo, imagina respuestas de 2 ms, 85 ms y 12 ms en tres saltos sucesivos. No puedes concluir que el segundo enlace añade 83 ms a todo el tráfico: el router puede tardar en generar su propia respuesta mientras reenvía otros paquetes con normalidad. Tampoco restar tiempos de líneas distintas aísla con precisión la latencia de cada enlace.

## Para qué sirve

- Buscar indicios de dónde dejan de recibirse respuestas.
- Comparar recorridos y tiempos observados desde distintos puntos o momentos.
- Entender por qué un servidor responde lento desde un sitio y no desde otro.

`tracepath` puede explorar la [MTU del camino](/articulos/que-es-una-mtu/). En cualquier caso, conviene contrastar las sondas con el servicio real: un filtro puede permitir HTTPS y bloquear la clase de sonda utilizada.

## Lo esencial

- Traceroute observa respuestas de saltos mediante sondas con TTL creciente.
- Los tiempos son de ida y vuelta, no medidas aisladas de cada enlace.
- Un asterisco significa ausencia de respuesta dentro del plazo, no una causa demostrada.
- Ayuda a diagnosticar junto con otras pruebas; no garantiza un mapa fijo y completo.
