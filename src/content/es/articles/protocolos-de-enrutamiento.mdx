Un router decide por dónde enviar cada paquete consultando su tabla de [enrutamiento](/articulos/enrutamiento/). En una red pequeña, esa tabla se escribe a mano. En una grande, los routers la construyen solos, intercambiando información con sus vecinos mediante **protocolos de enrutamiento**. Si un enlace cae, la recalculan.

Hay dos ámbitos distintos:

- **Dentro de un sistema autónomo**, la red de una sola organización: protocolos de **pasarela interior**, como RIP u OSPF.
- **Entre sistemas autónomos**, es decir, entre las redes que forman internet: **BGP**.

## RIP: vector de distancias

RIP es un protocolo de **vector de distancias**, basado en el algoritmo de Bellman-Ford. Cada router conoce solo a sus vecinos y les cuenta periódicamente a qué distancia está de cada destino. Cada uno se queda con el mejor camino que le ofrezcan:

```js
const coste = { A: { B: 1, C: 4 }, B: { A: 1, C: 2, D: 5 }, C: { A: 4, B: 2, D: 1 }, D: { B: 5, C: 1 } };

let distancias = { A: 0 };
for (let ronda = 1; ronda <= 3; ronda++) {
	const nuevas = { ...distancias };
	for (const [nodo, d] of Object.entries(distancias)) {
		for (const [vecino, c] of Object.entries(coste[nodo])) {
			if (nuevas[vecino] === undefined || d + c < nuevas[vecino]) nuevas[vecino] = d + c;
		}
	}
	distancias = nuevas;
	console.log(ronda, JSON.stringify(distancias));
}
// 1 {"A":0,"B":1,"C":4}
// 2 {"A":0,"B":1,"C":3,"D":5}
// 3 {"A":0,"B":1,"C":3,"D":4}
```

Las distancias desde A mejoran ronda a ronda, a medida que llega información de más lejos: C pasa de 4 a 3 al descubrir el camino por B, y D de 5 a 4 por C.

Es sencillo, pero lento al reaccionar a cambios y limitado: la propia especificación de RIP fija un máximo de 15 saltos, y su forma de resolver ciertos bucles, "contar hasta infinito", es lenta en redes grandes. Hoy se usa poco.

## OSPF: estado de enlaces

OSPF es un protocolo de **estado de enlaces**, pensado para funcionar dentro de un único sistema autónomo. Cada router anuncia a todos los demás el estado de sus propios enlaces, de modo que todos mantienen una **base de datos idéntica** con el mapa completo de la red. Con ese mapa, cada uno calcula los caminos más cortos con el [algoritmo de Dijkstra](/articulos/algoritmo-de-dijkstra/).

| | Vector de distancias (RIP) | Estado de enlaces (OSPF) |
| --- | --- | --- |
| Qué conoce cada router | Lo que le cuentan sus vecinos | El mapa completo de la red |
| Algoritmo | Bellman-Ford | Dijkstra |
| Reacción a cambios | Lenta | Rápida |
| Coste | Bajo | Más memoria y cálculo |

## BGP: el protocolo de internet

Internet es una red de miles de **sistemas autónomos**: operadores, grandes empresas, universidades, proveedores de nube. Entre ellos se usa **BGP**, el protocolo de pasarela de frontera.

- Cada sistema anuncia a sus vecinos qué redes puede alcanzar, junto con la **lista de sistemas autónomos** que atraviesa ese camino. Esa lista permite detectar bucles.
- Las sesiones BGP van sobre [TCP](/articulos/tcp-y-udp/), en el puerto 179, lo que le da entrega fiable y ordenada sin reinventarla.
- No busca solo el camino más corto: cada organización aplica **políticas** según sus acuerdos comerciales, por ejemplo preferir un enlace por el que no paga.

BGP se basa en la confianza. Un sistema autónomo que anuncie, por error o con mala intención, redes que no son suyas puede desviar o dejar sin servicio una parte de internet. Por eso se están extendiendo mecanismos para firmar qué redes pertenece anunciar a cada uno.

## Lo esencial

- Los protocolos de enrutamiento permiten a los routers construir sus tablas solos y adaptarse a fallos.
- RIP es de vector de distancias: cada router se fía de lo que le cuentan sus vecinos.
- OSPF es de estado de enlaces: todos tienen el mapa completo y calculan con Dijkstra.
- BGP une los sistemas autónomos de internet, con rutas guiadas por políticas, sobre TCP.
