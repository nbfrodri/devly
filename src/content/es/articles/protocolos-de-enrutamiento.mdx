Los **protocolos de enrutamiento** permiten intercambiar información para seleccionar rutas. Un router utiliza las rutas instaladas para reenviar paquetes; no consulta a todos sus vecinos por cada paquete nuevo. Las rutas pueden ser configuradas manualmente o aprendidas por distintos protocolos.

Hay dos ámbitos distintos:

- **Dentro de un sistema autónomo**, la red de una sola organización: protocolos de **pasarela interior**, como RIP u OSPF.
- **Entre sistemas autónomos**, es decir, entre las redes que forman internet: **BGP**.

## RIP: vector de distancias

RIP es un protocolo de **vector de distancias**, basado en Bellman-Ford. Cada router anuncia distancias hacia destinos; otro combina lo anunciado con el coste de llegar a ese vecino. Con coste uno por enlace, la métrica cuenta saltos. RIP limita las métricas alcanzables a 15 y usa 16 para indicar inalcanzable.

El siguiente ejemplo ilustra la relajación de distancias de Bellman-Ford con costes inventados. Tiene el grafo completo en memoria para observar las rondas; **no implementa los mensajes, temporizadores ni reglas de RIP**, y sus costes no representan simplemente saltos:

```js
const coste = { A: { B: 1, C: 4 }, B: { A: 1, C: 2, D: 5 }, C: { A: 4, B: 2, D: 1 }, D: { B: 5, C: 1 } };

let distancias = { A: 0 };
for (let ronda = 1; ronda <= 3; ronda++) {
	const nuevas = { ...distancias };
	for (const [nodo, d] of Object.entries(distancias)) {
		for (const [vecino, c] of Object.entries(coste[nodo])) {
			if (nuevas[vecino] === undefined || d + c < nuevas[vecino]) nuevas[vecino] = d + c;
		}
	}
	distancias = nuevas;
	console.log(ronda, JSON.stringify(distancias));
}
// 1 {"A":0,"B":1,"C":4}
// 2 {"A":0,"B":1,"C":3,"D":5}
// 3 {"A":0,"B":1,"C":3,"D":4}
```

Las distancias desde A mejoran ronda a ronda, a medida que llega información de más lejos: C pasa de 4 a 3 al descubrir el camino por B, y D de 5 a 4 por C.

RIP debe afrontar además información que queda desactualizada. Tras un corte, dos vecinos pueden creer que el otro aún conoce una ruta y anunciar distancias crecientes: el problema de **contar hasta infinito**. El límite y las reglas para evitar anunciar ciertas rutas de vuelta ayudan, pero no convierten la recuperación en instantánea.

## OSPF: estado de enlaces

OSPF es un protocolo de **estado de enlaces**, usado dentro de un sistema autónomo. Distribuye anuncios que describen enlaces y costes. Los routers de una misma **área** buscan mantener una base de datos coherente de su topología y calculan rutas de menor coste con [Dijkstra](/articulos/algoritmo-de-dijkstra/).

Una red OSPF puede dividirse en áreas; no todos sus routers conservan cada detalle de toda la organización. Durante un cambio, los anuncios tardan en propagarse, así que las bases de datos y las decisiones pueden diferir temporalmente.

| | Vector de distancias (RIP) | Estado de enlaces (OSPF) |
| --- | --- | --- |
| Información central | Distancias anunciadas por vecinos | Estado de enlaces de su área |
| Algoritmo | Bellman-Ford | Dijkstra |
| Cambios | Actualizaciones de distancias y reglas de convergencia | Distribución de anuncios y recálculo |
| Coste | Mantener rutas y actualizar vecinos | Mantener estado de enlaces y calcular caminos |

En el mismo grafo del ejemplo, A tiene un enlace directo a C de coste 4 y otro camino A → B → C de coste total 3. OSPF con esos costes elegiría el segundo. Un RIP configurado con coste uno por enlace preferiría el enlace directo: un salto frente a dos. «Más corto» depende de qué se mide.

## BGP: el protocolo de internet

Internet es una red de miles de **sistemas autónomos**: operadores, grandes empresas, universidades, proveedores de nube. Entre ellos se usa **BGP**, el protocolo de pasarela de frontera.

- Cada sistema anuncia a sus vecinos qué redes puede alcanzar, junto con la **lista de sistemas autónomos** que atraviesa ese camino. Esa lista permite detectar bucles.
- Las sesiones BGP van sobre [TCP](/articulos/tcp-y-udp/), en el puerto 179, lo que le da entrega fiable y ordenada sin reinventarla.
- No busca solo el camino más corto: cada organización aplica **políticas** según sus acuerdos comerciales, por ejemplo preferir un enlace por el que no paga.

BGP no demuestra por sí solo que un anuncio esté autorizado. Un origen o camino incorrecto puede desviar tráfico o interrumpir un servicio. La validación de origen basada en RPKI permite contrastar qué sistema autónomo está autorizado a originar un prefijo, pero no valida por sí sola cada tramo de la ruta anunciada.

## Convergencia y fallos

Si desaparece un enlace, primero debe detectarse el cambio, después propagarse la información necesaria y finalmente actualizarse las rutas. Durante ese intervalo pueden perderse paquetes o aparecer decisiones incompatibles. Tener un protocolo dinámico no crea una ruta alternativa donde físicamente no la hay.

RIP, OSPF y BGP tampoco son tres sustitutos intercambiables para cualquier red: difieren en ámbito, información y objetivos. Dentro de una organización puede interesar el coste de sus enlaces; entre organizaciones también importan las políticas de tránsito.

## Lo esencial

- Los protocolos de enrutamiento permiten a los routers construir sus tablas solos y adaptarse a fallos.
- RIP es de vector de distancias: cada router se fía de lo que le cuentan sus vecinos.
- OSPF distribuye estado de enlaces por áreas y calcula rutas con Dijkstra.
- BGP une los sistemas autónomos de internet, con rutas guiadas por políticas, sobre TCP.
