Una **llamada al sistema**, o *syscall*, es una petición de un programa al **[núcleo](/articulos/que-es-el-kernel/)** del sistema operativo. Permite solicitar servicios como abrir un archivo, crear un proceso o enviar datos sin conceder al programa el control general de esos recursos.

## Una petición, no un permiso ilimitado

Imagina que un editor quiere leer un documento. No debe poder saltarse los permisos y leer directamente cualquier bloque del disco. Solicita una apertura; el núcleo resuelve el nombre y comprueba las condiciones de acceso. Si la permite, devuelve un **[descriptor](/articulos/descriptores-de-archivo/)**: un número con el que ese proceso identifica el recurso abierto.

Después pide leer mediante ese descriptor. El permiso para ese archivo no le da acceso a toda la memoria ni a los documentos de otras personas. La frontera protege operaciones concretas, con reglas y posibles errores.

## Cómo se cruza la frontera

El hardware distingue niveles de privilegio. En el modelo habitual, los programas ejecutan en **modo usuario** y el núcleo dispone de operaciones restringidas. Es una separación de capacidades: el núcleo de una máquina virtual, por ejemplo, sigue sujeto al hipervisor.

Una llamada sigue este recorrido:

1. El código prepara el identificador del servicio y sus argumentos según la convención del sistema y la arquitectura. Pueden ir en registros o en otras ubicaciones acordadas.
2. Una instrucción especial transfiere el control a una entrada preparada por el núcleo. No permite elegir cualquier dirección dentro de él.
3. El núcleo valida la petición: qué recurso identifica, si el acceso está permitido y si las direcciones de memoria aportadas son utilizables.
4. Realiza el trabajo o devuelve un error. Algunas operaciones pueden dejar al proceso esperando.
5. Cuando corresponde, vuelve al código de usuario con el resultado. Hay excepciones: terminar el proceso no devuelve el control al programa terminado.

Linux en [x86-64](/articulos/arquitecturas-x86-y-arm/) puede usar la instrucción `syscall`; AArch64 utiliza `svc`. La idea es común, pero números, registros y resultados forman una interfaz concreta. Una llamada al sistema tampoco es una interrupción externa de un dispositivo: es una entrada solicitada por el programa, como distingue [interrupciones y entrada/salida](/articulos/interrupciones-y-entrada-salida/).

## Seguir una lectura

Supongamos que el editor ha abierto un archivo de cinco bytes y solicita hasta tres bytes cada vez:

| Petición | Resultado posible en este ejemplo | Qué hace el editor |
| --- | --- | --- |
| Primera lectura, hasta 3 bytes | 3 | Procesa esos tres bytes |
| Segunda lectura, hasta 3 bytes | 2 | Procesa los dos restantes |
| Tercera lectura | 0 | Reconoce el final del archivo |

Pedir tres no garantiza recibir tres. `read` puede devolver menos por otras razones; un error tampoco equivale a final de archivo. Si los datos no están disponibles, una lectura bloqueante puede dejar la tarea esperando y permitir ejecutar otra. Si ya están disponibles, puede regresar sin cambiar de tarea.

**Cambiar de modo no obliga a cambiar de contexto.** El [cambio de contexto](/articulos/cambio-de-contexto/) selecciona otra ejecución; atender una syscall puede continuar la misma.

## La biblioteca prepara el trabajo

Normalmente no escribes esas instrucciones de procesador. Las bibliotecas ofrecen funciones y hacen las llamadas necesarias. No existe una equivalencia universal de una función del lenguaje con una syscall: pueden agrupar, repetir o evitar operaciones usando datos ya disponibles.

Este ejemplo se ejecuta con Node.js en Linux, con `/proc` montado:

```js
import { readFileSync } from "node:fs";

const contenido = readFileSync("/proc/self/stat", "utf8");

console.log(typeof process.pid); // "number"
console.log(contenido.split(" ")[0] === String(process.pid)); // true
```

`/proc/self/stat` presenta información del proceso que lo lee; su primer campo es su identificador. El núcleo genera este contenido: leer un archivo no implica siempre acceder a un disco. La función síncrona devuelve el texto o lanza un error, por ejemplo si esa ruta no existe en el entorno.

En Linux, `strace` permite observar las llamadas de una ejecución. Puedes encontrar `openat` aunque la biblioteca hable de «abrir», además de lecturas y cierres. Los nombres y cantidades deben comprobarse en la traza, no deducirse solo del nombre de una función JavaScript.

## Otros servicios y límites

`fork` crea un proceso; `execve` sustituye su programa. `mmap` establece regiones de memoria, que pueden ser anónimas o estar respaldadas por archivos. `socket` y `connect` preparan comunicaciones. Cada operación tiene argumentos y condiciones: compartir una forma de entrada no las vuelve intercambiables.

El cruce, la validación y el servicio consumen tiempo. Agrupar lecturas puede reducir llamadas, pero también cambia memoria usada y latencia. Hay que medir la carga concreta.

## Errores comunes

- **Suponer que todo acceso necesita una nueva syscall.** El sistema puede haber autorizado memoria compartida o una región de dispositivo; después hay accesos directos dentro de ese permiso.
- **Ignorar el resultado.** Una lectura parcial, un error y un final de archivo requieren decisiones distintas.
- **Confundir biblioteca y núcleo.** Una interfaz cómoda no revela por sí sola sus operaciones internas.

## Lo esencial

- La syscall pide un servicio mediante una entrada controlada al núcleo.
- Se validan argumentos y acceso; la petición puede fallar o esperar.
- Una biblioteca puede realizar varias llamadas o ninguna para una operación.
- Entrar en modo núcleo no implica cambiar a otra tarea.
