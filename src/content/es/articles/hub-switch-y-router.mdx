Un **hub**, o concentrador, repite señales hacia sus otras conexiones. Un **switch**, o conmutador, aprende por dónde alcanzar direcciones de la red local y decide qué conexiones utilizar. Un **router**, o encaminador, consulta direcciones IP para reenviar paquetes entre redes. Un aparato puede combinar varias de estas funciones.

## Hub

Es el más simple. Cada señal que entra por un puerto sale **por todos los demás**. No entiende nada de lo que transporta: trabaja en la capa física del [modelo OSI](/articulos/modelos-osi-y-tcp-ip/).

- La señal se propaga por los otros puertos, aunque los equipos destinatarios descarten datos que no les corresponden.
- Solo puede transmitir uno a la vez; si dos lo hacen, chocan.
- No permite el mismo aislamiento entre enlaces que un switch; no es la opción habitual para construir una LAN Ethernet moderna.

## Switch

Trabaja en la [capa de enlace](/articulos/capa-de-enlace/). Examina **tramas**, los bloques de datos de Ethernet, y sus [**direcciones MAC**](/articulos/que-es-una-direccion-mac/), usadas para entregar datos en ese ámbito local. Aprende asociando la MAC de origen con el puerto por el que entró la trama.

Si conoce la MAC de destino, utiliza el puerto aprendido. Si no la conoce, normalmente **inunda**: envía la trama por los demás puertos habilitados de esa misma red lógica. Una difusión también requiere alcanzar varios puertos; un switch no envía siempre a un único destino.

Esta simulación usa tres puertos de una misma red, sin filtros, bucles ni caducidad de entradas. `A` y `B` representan direcciones MAC:

```js
const tabla = new Map();
const puertos = [1, 2, 3];

function recibir(trama, puerto) {
	tabla.set(trama.origen, puerto);
	const salida = tabla.get(trama.destino);
	if (salida === puerto) return [];
	return salida === undefined ? puertos.filter((p) => p !== puerto) : [salida];
}

console.log(recibir({ origen: "A", destino: "B" }, 1).join(" ")); // "2 3"
console.log(recibir({ origen: "B", destino: "A" }, 2).join(" ")); // "1"
console.log(recibir({ origen: "A", destino: "B" }, 1).join(" ")); // "2"
console.log(recibir({ origen: "C", destino: "A" }, 1).length); // 0
```

Primero aprende `A → 1`, pero desconoce B: salen copias por 2 y 3. Al responder B aprende `B → 2` y entrega a A por 1. El siguiente envío a B ya sale solo por 2. La última llamada representa otro equipo detrás del mismo puerto que A; no hay que devolver la trama por donde entró.

En enlaces Ethernet con **dúplex completo**, ambos extremos pueden transmitir y recibir simultáneamente sin las colisiones de un medio compartido con hub. La capacidad de puertos y del propio switch sigue siendo limitada.

## Router

Trabaja en la capa de red y entiende las [direcciones IP](/articulos/que-es-una-direccion-ip/). Su trabajo es decidir por dónde enviar cada paquete para que llegue a **otra red**, como explica [enrutamiento](/articulos/enrutamiento/).

Consulta una tabla de rutas para elegir el siguiente salto. No necesita que la red siguiente esté en otro país: también puede conectar dos subredes del mismo edificio.

## El mismo caso, con dos destinos

Ana y Bruno están en una misma red Ethernet; Carla está en otra red. Ana quiere enviar datos:

| Envío | Con hub o switch en la red de Ana | Papel del router |
| --- | --- | --- |
| Ana → Bruno | El hub repite la señal; el switch usa la MAC aprendida o inunda si aún la desconoce | No hace falta enrutar entre subredes para ese envío local |
| Ana → Carla | Ana entrega una trama a la MAC del router; hub o switch permiten llegar hasta él | El router examina la IP de Carla y reenvía hacia la otra red |

Cambiar el hub por un switch no sustituye la ruta hacia Carla. Cambia cómo se distribuyen las tramas en el primer tramo. La forma en que se conectan esos equipos se estudia en [topologías de red](/articulos/topologias-de-red/).

## Comparación

| | Hub | Switch | Router |
| --- | --- | --- | --- |
| Capa | Física | Enlace | Red |
| Entiende | Nada, solo señales | Direcciones MAC | Direcciones IP |
| Reenvía según | Señal recibida: a los otros puertos | MAC aprendida, o difusión/inundación según el caso | Ruta hacia la IP de destino |
| Conecta | Equipos de una red | Equipos de una red | Redes distintas |
| Uso | Redes Ethernet compartidas antiguas | Conectar enlaces de una LAN | Conectar redes IP |

## El "router" de casa

El aparato que da el proveedor de internet reúne varias piezas en una caja: un router, un switch con varios puertos, un punto de acceso [wifi](/articulos/como-funciona-el-wifi/), un [cortafuegos](/articulos/cortafuegos/) y a menudo un módem. Por eso se le llama router aunque haga mucho más.

## Límites de la comparación

No confundas un switch con una garantía de privacidad: que normalmente seleccione un puerto no cifra los datos ni sustituye permisos. Tampoco todos los equipos comercializados como switches se limitan a la capa de enlace; algunos incorporan enrutamiento.

## Lo esencial

- El hub repite señales por los otros puertos.
- El switch aprende MAC y puertos; un destino desconocido puede requerir inundación.
- El router conecta redes distintas y decide por dónde enviar cada paquete.
- El router doméstico combina router, switch, wifi y cortafuegos en un aparato.
